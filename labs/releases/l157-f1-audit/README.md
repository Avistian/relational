# RelBench F1 temporal-audit reproducibility release

Reproduce one complete selected experiment: five ten-epoch basic-GNN fits and five fixed-2005 preprocessing fits on every rel-f1/driver-position query. This is a research contribution prepared for public review. Public URL: PENDING_PUBLICATION.

## What the package answers

Can another reader reproduce and inspect the distinction between released preprocessing and a declared training-time fit horizon? Released source fits dated processors through2010; the course intervention fits them through2005. Both retain owner-cutoff graph sampling. This is a policy sensitivity experiment, not a claim that every transductive feature processor violates RelBench rules. The modern upstream implementation has not been diagnosed here.

## Quick evidence replay (CPU, no network)

Use Python3.11 and an isolated environment. From this directory:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install numpy==1.26.4
.venv/bin/python cli.py check
.venv/bin/python labs/_check_l157.py
.venv/bin/python cli.py replay
```

Replay verifies frozen bytes, reconstructs labels, aligns all entity/cutoff predictions, independently computes MAE, checks every epoch and selection, and applies claim gates. It does not train models. A hash is an integrity check, not an independent reviewer signature. See `labs/evidence/l157/report.md` and `report.json` for measured results and `input-manifest.json` for the primary evidence inputs.

## Full reproduction from original inputs

The pinned environment is Python3.11, Torch2.5.1/CUDA12.4, pyg-lib0.4.0+pt25cu124 and `labs/requirements-l117-runtime.txt`. The exact managed image is readable in `run_modal.py`. To run manually in a new working copy with a CUDA GPU:

```sh
python -m pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cu124
python -m pip install -r labs/requirements-l117-runtime.txt jinja2==3.1.6
python -m pip install pyg_lib==0.4.0+pt25cu124 -f https://data.pyg.org/whl/torch-2.5.1+cu124.html
python cli.py check
# Move bundled author evidence aside, preserving it for comparison:
mv labs/evidence/l157 labs/evidence/author-l157
python cli.py prepare
for lane in paper fit_horizon; do
  for seed in 0 1 2 3 4; do
    python cli.py train --lane "$lane" --seed "$seed"
  done
done
python cli.py freeze-evidence
python cli.py replay
```

No source file is imported from the teaching repository. No raw archive or text checkpoint is bundled: full runs require the original hosts. Missing or changed archives fail the hash check. No subsampling, reduced epochs or missing-seed averages are accepted. Existing seed output directories are refused. For managed author execution, `run_modal.py` reserves all allocated runtime in `budget.json` and disables retries. Its volume name identifies this author run; readers must choose a fresh volume and preserve their resulting source-manifest change as a new experiment identity. Manual training has no billing enforcement; use your own scheduler/runtime limits.

## Exact protocol and evidence boundaries

See `protocol.json`, `correction-protocol.json`, `experiment-manifest.json` and `THIRD_PARTY_NOTICES.md`. The reference paper target is Table7 basic GNN val3.193/test4.022 MAE; descriptive tolerance±.20. Corrections are not compared as paper reproductions. All prior test exposure is disclosed. Both lanes keep original numeric-encoder nonfinite first-backward gradients. No tuning or selection by test was added.

Frozen computation hashes identify what ran. Final `release-manifest.json` identifies everything shipped except itself; neither is a cryptographic signature. Raw artifacts, model weights and cached dependencies are not in the archive. Weights are regenerated by full training; selected weight hashes are retained in result files. Source/model output checks during each run and independent rescoring support the selected computational reproduction, not historical archive identity, all-paper reproduction or learner mastery.

The SQL audit was independently rerun during package preparation. Offline replay verifies its frozen report; only `prepare` rebuilds all SQL values. The feature-engineering model is not trained in this experiment.
