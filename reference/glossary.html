Q1 · Leakage & evaluation spine (L001–L010)

TermDefinitionLesson
Single-table assumptionTabular learners consume a design matrix + label vector, not raw tables, so relational data must be flattened first. The thing the RDL thesis argues throws away signal.001
Design matrix (X)The feature matrix: one row per training example, one column per feature.002
Label vector (y)The target aligned row-for-row with X — what the model predicts.002
Temporal leakageAny feature that encodes information unavailable at the prediction cutoff time; makes offline scores fantasy.001
Point-in-time (PIT)Building each row's features using only events strictly before its cutoff timestamp — the structural defence against temporal leakage.002
Stratified splitA train/test split that preserves the class prevalence in each part.003
Cross-validation (CV)Repeatedly hold out a fold, train on the rest; average the held-out scores. Fit only on the training portion of each fold.003
Grouped CVCV where all rows of an entity (customer, patient) stay together in one fold, so the model can't memorise an entity seen in training.004
Nested CVAn inner CV selects hyperparameters; an outer CV scores the whole selection procedure. The honest estimate of tuned performance.004
best_score_A grid search's best validation score — optimistic, because it was chosen using that same validation data (selection bias). Not a training score.004
Pipeline (fit scope)A container that fits every data-learning step (scaler, encoder, selector) on the training portion of each fold — never on all data before splitting.005
MCAR / MAR / MNARMissingness mechanisms: Completely At Random; At Random given observed X; Not At Random (depends on the unobserved value itself).006
Missingness indicatorA binary "was-missing" feature; preserves the pattern that imputation alone erases (essential under MNAR).006
Class imbalanceA skewed positive rate; makes accuracy misleading (the accuracy paradox) and shifts the decision threshold.007
SMOTESynthetic minority oversampling; must run inside the CV fold or it leaks.007
ROC-AUCRanking quality via TPR vs FPR; no-skill baseline 0.5; optimistic under imbalance.008
PR-AUCPrecision vs recall; no-skill baseline = prevalence; the honest lens on rare positives.008
Calibration / BrierWhether predicted probabilities match observed frequencies (reliability curve); Brier = MSE of probability vs outcome. Calibrator fit on held-out data.008
Target encodingReplacing a category by its mean target; must be out-of-fold or it leaks the label.009
Leakage spineThe Q1 checklist of leakage sources (PIT, split, pipeline scope, resampling, encoding) a reproducible baseline must clear.010

Q2 · Trees, boosting, ensembling (L011–L020)

TermDefinitionLesson
Decision treeA learner that recursively partitions feature space with axis-aligned splits into piecewise-constant regions.011
Gini impurity1 − p² − (1−p)²: the chance two random draws from a node differ in label.011
Split gainImpurity drop from a split = parent impurity − weighted children impurity (regularized form subtracts a γ toll).011
BaggingBootstrap-aggregating: average many trees on resampled data; variance falls ~1/B.012
Random ForestBagging + random feature subsets per split; OOB score estimates test error for free.012
OOB (out-of-bag)Rows not in a tree's bootstrap sample; used to score that tree without a separate holdout.012
BoostingFit each new learner to the residuals/gradients of the current ensemble; a stagewise additive model.013
Shrinkage (learning rate η)Scale each boosting step down so more, smaller steps generalise better.013
Gradient / hessian (g, h)First/second derivatives of the loss w.r.t. the current model score F, recomputed each round.014
Regularized objective (XGBoost)Loss + Ω = γT + ½λ‖w‖²; penalises leaf count and leaf-weight magnitude.014
Leaf weight w*Closed-form optimum w* = −G / (H + λ); λ shrinks it toward zero.014
Histogram splitsBin features once, split on bins — the speedup that made modern GBDTs fast (XGBoost-hist, LightGBM).015
Leaf-wise growthGrow the best-gain leaf next (best-first), so num_leaves — not max_depth — is the primary capacity knob.015
GOSSGradient-based One-Side Sampling: keep large gradients, sample the rest, amplify the sample by (1−a)/b to stay unbiased.015
EFBExclusive Feature Bundling: pack mutually-exclusive sparse features into one, shrinking the feature count.015
Ordered target statisticsCatBoost's leak-free category encoding: encode row i from its permutation prefix + a prior, never its own label.016
Ordered boostingCompute a row's gradient from a model that never saw that row — kills prediction shift.016
Oblivious treeA symmetric tree using the same split across a whole level (a decision table); regularized and fast (CatBoost).016
Grid vs random searchAt equal budget under low effective dimensionality, random search tries ~n distinct values on the key axis vs a grid's √n — so it wins.017
Low effective dimensionalityOnly a few hyperparameters actually matter; the premise that makes random search beat grid.017
StackingA meta-learner trained on base-model predictions; must use out-of-fold preds or it leaks.018
Out-of-fold (OOF) meta-featuresBase predictions for a row made by models that didn't train on it — the honest input to a stack.018
BlendingSimple (often averaged) combination of base models; weaker than stacking but needs no meta-learner.018
Inductive biasThe kind of function a learner reaches for first: trees → axis-aligned piecewise-constant; MLP → smooth, rotation-invariant.019
Rotational invarianceLearning the same thing under a rotation of feature space; a virtue on images, a weakness on tables where columns are individually meaningful.019
Fair-comparison contractFix data, split, metric, tuning budget, and preprocessing scope up front; report the verdict + gap honestly. The reviewer stance from the Q2 checkpoint.020

Q3 · Evaluation rigor & benchmark literacy (L021–L030)

TermDefinitionLesson
i.i.d. / exchangeable rowsThe assumption every shuffled split makes: rows are independent and identically distributed, so which rows land in test vs train does not matter. Broken when data is time-ordered and the world drifts.021
Temporal splitOrder rows by time and cut once: train on the past, test on the future — mirrors deployment. The default posture when a time order or drift exists.021
Concept driftThe feature→label rule changes over time (distinct from a shifting class balance). Makes a model trained on the past stale on the future.021
Covariate shiftThe input feature distribution changes over time while the rule may stay fixed; a second, separate kind of distribution shift.021
TimeSeriesSplitExpanding-window CV: each fold trains on an earlier block and validates on the next, never shuffled — the time-respecting analogue of KFold.021
Optimism gapThe amount a random split overstates deployment performance versus a temporal split (here random-CV 0.846 vs temporal 0.758 → +0.088).021
Data leakageAnything the model learns at training time that it could not legitimately know at prediction time; inflates the test score too, so CV looks fine. Kapoor & Narayanan's taxonomy: 8 types in 3 families.022
Illegitimate feature (L2)A column that proxies the label or would not exist at prediction time (computed from/after the outcome). Passes every pipeline/split check — caught only by auditing provenance.022
Non-independence (L3.2) / duplicates (L1.4)The same underlying record (patient, device) appears in both train and test, so the model half-memorises the answer; the unit of independence is the record, not the row. Fix: a grouped split.022
Reproducibility collapseWhen an apparent complex-vs-simple win vanishes once a leak is removed (demo: RF 0.935 vs LR 0.719 → 0.712 vs 0.721). A large gap is a leak hypothesis first.022
Model info sheetKapoor & Narayanan's prescribed defence: a structured form with a question per leak type, filled before publishing an ML claim, so leaks surface early.022
Paired significance testBecause two models are scored on the same folds, test the per-fold differences d_i = score_A(i) − score_B(i); pairing cancels fold-difficulty and is more powerful than comparing independent columns.023
Anticonservative testA test that rejects the null too often (too many false positives) because it underestimates variance — e.g. a paired t-test on correlated CV folds.023
Corrected resampled t-testNadeau & Bengio (2003): k-fold training sets overlap, so fold scores are correlated; inflate the variance of the mean by (1/n + n_test/n_train) — for k-fold, + 1/(k−1) — so the naive p-value stops lying (demo: 1.2e−5 → 0.19).023
Friedman testNon-parametric repeated-measures ANOVA on ranks: over N datasets, asks whether k models' average ranks differ more than chance. The omnibus step before a post-hoc (Demšar 2006).023
Nemenyi critical difference (CD)Post-hoc all-pairs test: two models differ significantly only if their average ranks differ by at least CD = q_α·√(k(k+1)/6N). Drawn as a CD diagram (a bar joins models that are not different).023
Random-search budget curveGrinsztajn's fair comparison (2022 §4): plot the expected test score of the best-validation config found after k random-search iterations, averaged over draw orderings. Shows both the default (k=1) and the tuned ceiling — not one number that hides tuning effort.024
Per-dataset (affine) normalizationRescale each dataset's scores so the worst model → 0 and the best → 1 ((s−worst)/(best−worst)) before averaging across a suite, because raw accuracies are incommensurable across datasets (echo of Demšar).024
Dataset-selection criteriaExplicit, pre-registered inclusion rules (real, tabular, medium-sized, heterogeneous columns, not too easy) applied to a large pool so a benchmark's verdict is not a dataset-selection artifact. Curation is half the experiment.024
Heterogeneous columnsEach column is a distinct, meaningful feature (not pixels or repeated sensor channels). The defining property of tabular data; homogeneous columns are perceptual data in disguise where neural nets have a natural edge.024
Default vs ceilingA model's untuned performance (budget 1) versus its best tuned performance (large budget). One tuned number collapses these into one; the budget curve keeps them separate — a strong default is cheaper to deploy.024
Smoothness (spectral) biasA neural net trained by gradient descent fits low-frequency (smooth) structure easily and high-frequency (jagged) detail slowly or not at all (Rahaman 2019). It can represent sharp functions, just not cheaply on finite data — so it over-smooths irregular tabular targets.025
Piecewise-constant fitA model that predicts a constant within each axis-aligned region (a decision tree). A single split makes an arbitrarily sharp step, so it can follow a jagged target — the opposite disposition to a smooth MLP.025
Target smoothing (Gaussian)Grinsztajn's §5.2 diagnostic: replace each target by a distance-weighted average of neighbours' targets, w_ij = exp(−‖x_i−x_j‖²/2h²). Growing h erases the target's high-frequency structure; the tree-vs-MLP gap collapses as that structure (variance) is removed — proving the smoothness bias is the mechanism. An ablation, never a production fix.025
Rotational invarianceA learning procedure is rotationally invariant (Ng 2004) if applying the same orthogonal matrix Q to the train and test features (X → X·Q) leaves its test performance unchanged. MLPs and ResNets are invariant (a linear first layer absorbs the rotation: W·(Qx)=(WQ)·x); decision trees are not (axis-aligned splits are tied to the original basis), and neither are FT-Transformers (pointwise tokenizer).026
Natural basisThe original feature axes of a table, where each column is individually meaningful (age, balance, store_id). Because tabular signal is aligned with this basis, a random rotation — which mixes columns into arbitrary combinations — destroys the alignment; unlike images, tabular data has a privileged basis, so rotation invariance is a liability, not a virtue.026
Random rotation (feature basis)Grinsztajn's §5.4 diagnostic: draw a random orthogonal Q (e.g. from a QR decomposition) and apply it to train + test features. The transform is lossless (Q is invertible), so any accuracy change isolates a model's bias: it collapses axis-aligned trees but leaves invariant MLPs unmoved, and can reverse the model ranking.026
Ng's sample-complexity boundNg (2004): any rotationally-invariant learning procedure has a worst-case sample complexity that grows at least linearly in the number of uninformative features — to drop a junk column it must first recover the original orientation, which rotation erases. The theoretical bridge from rotation invariance (L026) to fragility under uninformative features (L027).026
Uninformative (junk) featureA column statistically independent of the label (in experiments, a pure-noise Gaussian). Real tables are full of near-junk columns (surrogate IDs, audit fields, unrelated measurements). Grinsztajn §5.3 (Finding 2): MLP-like models are not robust to them; trees are.027
Implicit feature selectionA tree grows greedily, splitting only on the highest-gain feature, so a ~0-gain junk column is never chosen near the top — the tree selects the useful features as a side-effect of how it grows, with no separate selection step. The mechanism behind its robustness to junk; an MLP has no equivalent gate.027
Split gain (gate)The impurity a candidate split removes: gain = parent_impurity − weighted children impurity. A tree keeps only the highest-gain split, so a noise column (whose best split leaves the children as mixed as the parent, gain ≈ 0) loses to a real feature. Root-split gain was ~118× higher on informative than junk features — the gate that gives implicit feature selection.027
Root-split gain (vs MDI)The gain of a feature's best single threshold on the full data — where the tree's gate is real (junk ≈ 0). Preferred over impurity-based (MDI) importance for showing the gate, because deep in a tree spurious high-gain noise splits appear on small subsets, so MDI over-credits noise features.027
MLP (multilayer perceptron)A stack of linear (fully-connected) layers with a non-linearity (ReLU) between them: Linear → ReLU → … → Linear. Gorishniy's tabular MLP block is Dropout(ReLU(Linear(x))). The simplest neural baseline; still carries the L025–L027 inductive-bias debts.028
Residual / skip connectionA block that outputs x + f(x) instead of f(x): the input is added back through a shortcut that bypasses the layers, so the branch f only learns a small correction. Introduced by He et al. 2015; it makes the identity map free, so stacking blocks can't hurt.028
Degradation problemHe et al. 2015: a plain deep network gets worse as it gets deeper — and its training accuracy falls too, which rules out overfitting. It is an optimization failure (the extra layers can't easily learn the identity), distinct from vanishing gradients (which BatchNorm already fixes). The problem a skip connection solves.028
Tabular ResNetGorishniy 2021's residual net for tables: Linear_embed → [ResNetBlock]×N → Head, with ResNetBlock(x)=x+Dropout(Linear(Dropout(ReLU(Linear(BatchNorm(x)))))) and Head=Linear(ReLU(BatchNorm(x))). One of the two honest neural baselines a tabular-DL (or RDL) result must beat.028
BatchNormBatch normalization: per feature, subtract the minibatch mean and divide by its standard deviation, then rescale by two learned parameters. Stabilizes activation scale so training is faster and less sensitive to initialization/learning rate; largely fixes vanishing gradients (which is why the degradation problem is a separate issue).028
DropoutA regularizer that randomly zeroes a fraction p of activations during training (rescaling the rest) and is turned off at test time, so the network can't lean too hard on any one unit. Reduces overfitting; unrelated to the depth/degradation problem.028
Honest (neural) baselineA properly-tuned simple model used as the comparison bar. Gorishniy 2021's methodological finding: many "SOTA" tabular-DL papers failed to beat a tuned MLP/ResNet, so a claimed win against a weak baseline proves little. The single-table bar an RDL result must clear is a tuned GBDT and a tuned ResNet.028
No universal winnerGorishniy 2021's headline conclusion: across their benchmark, GBDT wins some datasets and DL wins others (ensembling both helps) — there is no category winner. On small categorical data (credit_g) the tuned GBDT still leads; the two neural baselines tie.028
AutoMLAutomated machine learning: a system that takes a raw dataset + a metric and produces a fitted model, choosing the algorithm, hyperparameters, and (some) preprocessing automatically. Canonical system: Auto-sklearn (Feurer 2015). It automates search, not domain feature engineering, and does not change the data representation.029
CASHCombined Algorithm Selection and Hyperparameter optimization (Thornton 2013, Auto-WEKA): treat "which algorithm" as a top-level categorical hyperparameter sitting above each model's own knobs, and search the whole nested space at once — A*, λ* = argmin_(A,λ) ValidationLoss(A(λ)). The core of what AutoML automates.029
Bayesian optimization (SMAC)The search strategy AutoML uses instead of grid/random: fit a cheap surrogate (Auto-sklearn uses a random forest, SMAC) that predicts a config's validation score + uncertainty, then pick the next config by trading exploitation vs exploration (an acquisition function). More sample-efficient than random search per trial.029
Meta-learning / warm-startLearning across datasets: describe each dataset by cheap meta-features (rows, features, imbalance, skew…), record which configs won on ~140 reference datasets, and warm-start a new search from the winners of the most similar past datasets. Auto-sklearn's first extension over Auto-WEKA; changes where the search begins, not what it searches.029
Ensemble selection (Caruana 2004)Auto-sklearn's second extension: build a weighted ensemble greedily from the pool of already-trained models — start empty, repeatedly add the model that most improves validation AUC, with replacement (so strong models get more weight). Leak-free (selected on validation), no meta-learner to overfit — the simpler cousin of L018 stacking. Gave +0.007 on credit_g.029
Benchmark reportThe one-page artifact a skeptic reads before believing "model A beats model B". A defensible report is fair (curated dataset, deployment-matched split, one metric + prevalence, disclosed budget, per-fold preprocessing), audited (a model info sheet on every feature's provenance), proven (a corrected significance test + effect size, and a budget curve rather than one tuned number), and explained (the ranking attributed to the three inductive biases) — ending in an honest verdict, including "no significant winner". The exact form in which every RDL claim must eventually be argued.030
Model info sheetKapoor & Narayanan's leakage checklist: before publishing, answer one question per leak type — most importantly, is each feature knowable strictly before the label's timestamp, and is any feature illegitimate/target-derived. Filling it (not assuming it) is what makes a benchmark report's feature set defensible.022, 030
Statistical tie (no significant winner)The honest verdict when the effect size, tested correctly, cannot be distinguished from noise. A reported gap is a random variable and k-fold scores overlap, so a bigger mean is not a win: on credit_g the GBDT led the neural baseline by +0.0081 ROC-AUC over 25 paired folds but the corrected resampled t-test gave p=0.64 → a tie. Being willing to report a tie is what makes an eventual "RDL wins" verdict from the same protocol credible.030

Q4 · Consolidation & bridge to neural tabular (L031–L040)

TermDefinitionLesson
Categorical encodingTurning a categorical column (labels from a finite set) into the numbers a model can consume. Four ways with different trade-offs: one-hot, ordinal, target, entity embedding. The choice is a representation decision — the axis Q4 opens after Q3 exhausted search and architecture.031
CardinalityThe number of distinct levels a categorical has (checking_status: 4; a zip_code/product_id: thousands). High cardinality is what makes the encoding choice matter — and is the property of the foreign-key IDs the relational thesis cares about.031
One-hot encodingA level of a k-level column becomes k binary columns (one 1, rest 0). Asserts nothing false (all levels equidistant) but is wide (+k columns per categorical; +54 on credit_g) and captures no similarity. Safe from leakage; infeasible at very high cardinality.031
Ordinal (label) encodingEach level → an integer (0,1,2,…): one compact column, but integers carry an order and spacing, so it invents a false order. A linear/neural model must honour it (credit_g: linear AUC 0.782→0.739); a tree splits around it (0.778→0.774), which is why GBDT libraries accept integer-coded categoricals.031
Out-of-fold (OOF) target encodingThe leak-free recipe: encode each fold's rows using level means computed only from the other folds, never a row's own label, and fit the encoder inside the CV fold (same discipline as L003/L005). Restored a signal-free id from a leaked 0.891 AUC to 0.504 (chance).031
Target-encoding smoothing (shrinkage)Shrink each level's mean toward the global prior by its count: enc(L) = (n_L·mean_L + m·global)/(n_L + m). A level with many rows keeps its mean; a rare level falls back to the prior, so it can't memorise a handful of rows. Distinct from the boosting learning-rate "shrinkage" (L013).031
Entity embeddingEach level → a short learned dense vector (dim ≈ min(50,(card+1)//2)), trained by backprop jointly with the model (Guo & Berkhahn 2016). Levels that behave alike end up close together — a similarity structure one-hot and ordinal lack; target encoding is the 1-D special case. The first learned representation and the atom of RDL (embedding foreign-key entities).031
Embedding dimensionThe width d of an entity-embedding vector. The Guo & Berkhahn / fast.ai heuristic is d = min(50, (cardinality+1)//2): far narrower than one-hot's k at high cardinality, and a knob trading capacity against overfitting on rare levels.031
Learned representationA numeric form of the raw data that is learned from the objective rather than hand-specified (an entity embedding vs one-hot). Q3 showed single-table search and architecture are exhausted; the learned representation is the open axis — and on a small flat table it ties, because there is little structure to learn (the payoff is at scale / on relational structure).031
Self-attentionThe core Transformer operation. Each input vector (token) emits a query, key and value (learned linear projections); a token's output is a weighted average of all tokens' values, with weights softmax(Q·Kᵀ/√d) (≥ 0, summing to 1). "Self" = the tokens attend to each other. In TabTransformer the tokens are a row's categorical columns.032
Contextual embeddingAn embedding whose vector depends on the rest of the input, unlike a context-free entity embedding (L031) that is the same everywhere. TabTransformer makes each categorical column contextual w.r.t. the other columns in the same row (the "bank" = river-bank vs savings-bank analogy) by passing the embeddings through self-attention.032
TabTransformerHuang et al. 2020 architecture: categorical entity embeddings → a stack of N Transformer self-attention layers → contextual embeddings; continuous features bypass the Transformer (LayerNorm only) and are concatenated with the flattened contextual vectors before an MLP head. Honest verdict: matches tree ensembles on supervised tabular (+1.0% is over other DL); real wins are robustness to noise/missingness and a +2.1% semi-supervised lift. Only categoricals are contextualised (FT-Transformer, Y2, tokenises numerics too).032
Diminishing returns (of feature engineering)The pattern where the first few hand-crafted features buy most of the achievable gain and later ones buy progressively less — the curve of held-out score vs. effort flattens, and in the extreme turns negative (extra features lower the score). Model-relative: large for a weak model missing the hypothesis (L009), near-zero for a GBDT that already synthesises interactions.033
Marginal returnThe change in a model's honest held-out score from adding one more feature (or hour of effort), holding everything else fixed: s₁ − s₀. The quantity the feature-engineering budget rule watches — spend while it is large, stop when it sinks into the CV noise band.033
CV noise band (±1σ)The interval mean ± σ around a cross-validation score, where σ is the standard deviation across folds. A change smaller than σ is within noise — indistinguishable from luck of the split (the L023 discipline). The stopping signal for feature engineering: stop when the next feature's marginal gain falls below σ.033
Feature-engineering budget ruleGiven fixed modeling time, front-load effort on the handful of features domain knowledge favours (the steep part of the returns curve), stop when the marginal held-out gain drops below the CV std σ (not when you run out of ideas), then reallocate to more data ("more data beats a cleverer algorithm", Domingos 2012) or tuning. Grounds the thesis's ceiling: single-table FE returns die fast — the value moved across the join.033
Relational databaseData stored across multiple tables (grids of rows and named columns) linked by shared key columns, rather than one flat table. The natural form of most real data; everything in Q1–Q3 assumed the flat table was already extracted from one.034
Primary key (PK)The column(s) that uniquely identify each row of a table (customers.customer_id). No two rows share a PK value — it is a row's stable name, and the target a foreign key points to.034
Foreign key (FK)A column in one table holding the primary-key value of a row in another, creating a link (orders.customer_id → customers.customer_id). Foreign keys are the edges of the database — and, in Year 3+, the edges of the relational entity graph.034
Fact / dimension tableKimball's split: a fact (event) table records timestamped events/measurements and holds foreign keys (orders, order_items); a dimension table describes the entities those keys point to (customers). Facts are long and grow; dimensions are comparatively static descriptions.034
Star schemaThe dimensional layout of one central fact table surrounded by its dimension tables, joined by PK/FK links (it looks like a star). The default mental model for reading any analytics database: find the events, find the entities they point to.034
GrainWhat one row of a table means — its unit of observation (order_items: one line item; orders: one order; the training table: one customer as of a cutoff t). Choosing the training grain is the first modelling decision; the GROUP BY key sets it.034
One-to-many relationshipA link where one row on the PK side connects to many on the FK side (one customer, many orders; 1 : ∞). Exactly what forces aggregation: to describe the "one" with the "many" you must summarise the many into fixed-width columns.034
Flatten (join + aggregate)Turning a relational schema into one design matrix: join neighbour tables via foreign keys, then aggregate (COUNT/SUM/AVG/MAX) the one-to-many rows into columns at the chosen entity grain. Lossy by construction and rebuilt per task — the single-table paradigm the thesis critiques; each aggregate is a hand-built DFS primitive (L009).034
Point-in-time (PIT) correctnessEvery feature for a row tied to prediction time t must be computable from data available at or before t — in code, filter order_ts < t before aggregating. Omitting it averages in future events: the L002/L021/L022 leakage, committed at the feature-construction step of a relational flatten.034
Lossy mapA transformation you cannot invert: several distinct inputs produce the same output, so the original is unrecoverable (contrast a lossless map like a rotation, L026, whose Q is invertible). Join + aggregate is lossy — the exact property that makes the single-table flatten discard signal.035
Aggregation collisionWhen two different entities (different related rows) produce the identical aggregated feature vector — the sharpest proof of lossiness. Demo: Ada (spend $10→$30→$50, 3 products) and Bo ($50→$30→$10, 1 product) both flatten to n=3/total=90/avg=30/max=50, so any model gives them the same prediction though their labels differ. No tuning or capacity can undo it; the loss is before the model.035
Fine-grain signalPredictive structure held in an entity's individual related rows — the sequence, identity, and multi-hop paths of its events — that a low-granularity aggregate erases. Fey 2024 §2 issue (4): "forcing data into a single table aggregates into lower-granularity features, thus losing out on valuable fine-grain signal."035
Structure a flatten discardsFour named dimensions: cardinality (how many related rows), event/entity identity (which products/merchants), temporal order within a neighbour set (the sequence, distinct from PIT eligibility), and higher-order / multi-hop paths (signal ≥2 joins away). Each can be recovered by a bespoke per-task aggregate, but not all at once — the treadmill RDL replaces.035
Relational entity graph (REG)Fey et al.'s reframing of a database as a graph: one node per row in every table, one edge per primary-/foreign-key link; nothing is flattened, the schema is the graph (temporal + heterogeneous). RDL learns representations by message passing over the REG — the alternative to the lossy flatten. (Full treatment: Years 3–4.)035
Pipeline auditA read of an already-finished pipeline against a fixed checklist, done in source order (load → join → label → encode → split → fit → select → report) rather than by reading the write-up, because a defect lives in the code that ran and the prose is the last place it shows. Ends in a ranked list of defects plus a re-measurement, not a list of vibes.036
Consequence classWhat a defect actually costs, chosen before you estimate its size — it inflates the reported number (a metric computed downstream of the leak), degrades the shipped artifact (the number is honest; the thing you deploy is worse), changes the decision (every number correct, the inference from them wrong), or is a declarable limitation (nothing to fix; you owe the reader a sentence). Triage by class first: only the first class means "the result was a lie".036
Group straddle (nested-split leak)An inner/nested split that forgets the grouping the outer split respects, so one entity's rows land on both sides of the inner boundary. Canonical instance: CalibratedClassifierCV(..., cv=5) defaults to an ungrouped StratifiedKFold, so a person trains the base model while their other rows fit the isotonic map. Confined to the training block ⇒ it degrades the artifact, not the reported metric — pass cv=StratifiedGroupKFold(...).split(X, y, groups).036
Transductive preprocessingFitting any statistic — imputer medians, scaler means, one-hot vocabulary, KMeans centroids — on all rows including the folds you will score on. "It's unsupervised so it's safe" is a claim about labels only; the real cost is that the resulting CV number is not a deployment estimate, because at inference time on a genuinely new row those statistics could not have been computed. Fix: put every fitted step inside a Pipeline and let cross_validate fit it per fold (L005).036
Winner's curse (selection bias)The maximum (or argmin) of several noisy, correlated estimates is optimistically biased: picking the best of k models on the same folds partly picks the luckiest, so the winning score overstates what that model will do next. Diagnostics: is the margin inside one fold's σ? does the winner take a majority of folds? does the pick survive leave-one-fold-out? A choice that flips when one fold is dropped was never a choice about the models — give the tie to the simpler one.036
Repeatability / reproducibility / replicabilityThree distinct claims, in ascending difficulty. Repeatability — the same team, the same setup, gets the same result. Reproducibility — a different team, running your artifacts (code, data, environment), gets your result. Replicability — a different team, using independently written artifacts, gets your result. ACM swapped the latter two in v1.1 (2020) to match the wider sciences, so the terms are literally reversed across sources published either side of it: when precision matters say same artifacts or independent artifacts and skip the noun. A baseline package targets the middle rung.037
Constraint vs pin vs lockThree strengths of dependency statement, routinely conflated. A constraint (lightgbm>=4.0) says what you tolerate; a pin (lightgbm==4.6.0) says what you want; a lockfile records the resolved version and content hash of every package actually installed, transitive dependencies included. Only the third describes what you ran. Measured cost of stopping at the first: lightgbm 4.5.0 + scikit-learn 1.9.0 — both satisfying this workspace's constraints — raise TypeError: check_X_y() got an unexpected keyword argument 'force_all_finite'.037
Run manifestA machine-written record emitted by the run itself, naming everything needed to interpret its output later: git commit and dirty flag, resolved package versions, host and CPU count, a content hash of the input data, a canonical hash of the config, every seed by role, the results and the wall time. Written by hand it is documentation and rots; emitted by the pipeline it is the file a verification step diffs. Implements three ML Reproducibility Checklist items at once (Pineau et al. 2021).037
Output fingerprintA stable hash of the full prediction matrix (dtype and memory layout normalised first), used as the reproduction gate in place of comparing a summary metric. Strictly stronger: two runs can agree on mean log-loss to five decimals while disagreeing on hundreds of individual predictions. Needs no tolerance, admits no argument, and cannot be quietly widened after it fails — prefer it whenever bitwise reproduction is achievable.037
Perturbation probeChange exactly one input to a run, hold all others fixed, re-run, and compare the output fingerprint — the empirical alternative to asserting which knobs matter. Report four things, because a hash alone is an alarm and not a diagnosis: bitwise identity, largest single-probability change, count of rows whose predicted class flipped, and change in the reported metric. On this pipeline eight of nine perturbations were byte-identical.037
Inert seedA seed that provably changes nothing, because the code path that would consult it is never taken. LightGBM's random_state here is inert: it is read only when the learner samples (bagging_fraction<1, feature_fraction<1, extra_trees), and this configuration sets none. Meanwhile the same literal RANDOM_STATE = 0 passed to StratifiedGroupKFold(shuffle=True) moves mean log-loss over a 0.0166-nat range — 5× the margin that chose the shipped model. "All randomness is seeded" is therefore true and uninformative; name each seed by the role it plays.037
Estimator of recordThe aggregation rule, bin count and sample size that turn a metric into a number — and which must travel with it. "Top-label ECE" on one model's one set of out-of-fold predictions reads 0.0332 averaged over five folds and 0.0178 pooled once; both are correct and the name does not distinguish them. Emit {"metric": "ece_top", "estimator": "pooled_oof", "bins": 15, "n": 5587} and the ambiguity is unrepresentable.037
Noise floor (of an estimator)What a metric reads for a model that is exactly right, at the sample size you are using — measured, not derived, by scoring a control that is perfect by construction (for calibration: resample each row's label from that row's own predicted probabilities, so true ECE is zero). Because ECE sums absolute gaps over bins, sampling noise accumulates instead of cancelling and the floor rises as bins thin: 0.0149 at n = 5,587, 0.0335 at n = 1,117, 0.1071 at n = 107. Any reported value below its own floor is a measurement of the ruler; any threshold below it is a gate no model can pass.037
Reproduction toleranceThe tol in |observed − expected| ≤ tol, chosen and written down before the first failure, because a tolerance widened to make a red run go green is not a test. Calibrate it against measured landmarks rather than taste: on this pipeline an undocumented float32 cast moves the number 0.00133, the margin that chose the shipped model was 0.0032, re-drawing the folds moves it 0.0166, and one fold's σ is 0.035 — so a gate above ~0.003 can no longer protect a decision, and one above 0.035 cannot fail at all.037
Configuration debtSculley et al.'s (NeurIPS 2015, §6) name for the knobs that govern a result while living outside the place a reviewer would look — a .astype(np.float32) in a notebook cell, a thread count in a shell alias, a seed reused for two unrelated roles. Diagnostic question: can a reviewer see every value that could move the headline number by reading one diffable file? Repayment is a single baseline.yaml whose entries carry the measured consequence of changing them.037
Reviewer's stanceYou review the reported evaluation, not the author's intentions — so you reason only from what is on the page plus what a competent author must have done, which makes omissions findings (an undescribed split or unnamed estimator is a defect, because an unstated choice cannot be trusted). Adversarial toward the claim, generous toward the person; extend the author no benefit of the doubt you would deny a rival's paper.038
Severity (blocker / major / minor / nit)The four grades a review sorts findings into. A blocker means the central claim is not supported as written (no acceptance until resolved); a major materially weakens the work but leaves the headline standing; a minor should be fixed but changes no conclusion; a nit is cosmetic. The commonest review failure is grading everything the same — a wall of nits buries the one blocker.038
Conclusion-impact vs artifact severityThe two independent axes a review triages on. Conclusion-impact: would fixing the defect change the paper's claim or the shipped decision? Artifact severity: how broken is the thing itself, regardless of the headline? They come apart both ways — a training-block group-straddle is severe yet leaves the reported number honest (high severity, low impact); a 0.0032-nat selection margin decides everything while every number is correct (low severity, high impact). Grading only one axis either nukes a sound paper over a nit or waves through a fatal flaw dressed as a small number.038
VerdictThe required output of a review, in four grades — accept, minor revision, major revision (claim overstated but salvageable with named changes), reject (unsupported and unrescuable by revision) — each with the specific required changes that would move it. A review without a verdict is a mood; a verdict without required changes is a veto. Match the grade to what revision can fix: reject only when no revision rescues the claim.038
Sequential overfitting (over-hyping)Lones' name for the leak that is almost never written down: training model after model, using each one's test-set score to choose the next, so the test set silently joins training and the final number is optimistic. The informal cousin of the model-selection bias nested CV fixes (L004); a reviewer catches it in the process ("how many models did you score on this test set, and did any earlier result guide a later choice?"), not in the code.038
Hyper-parameter (HP) budget parityA fair comparison optimises every compared model to the same degree and reports the budget. A tuned model against a defaults baseline measures a tuning-effort gap wearing a model-quality mask (Lones: "do not assume a bigger number means a better model"). The reviewer's question is not "did you tune?" but "did you tune both, equally?" — the reason L024 reports a budget curve, not one peak.038
Multiplicity effect (multiple comparisons)Each 95 %-confidence test has a 1-in-20 false-positive rate; run twenty and one is likely spurious. A benchmark comparing many models on one test set — or a community comparing thousands on a shared one — runs exactly this gauntlet, so a marginal "win" is the expected behaviour of noise. Fixes: a correction (Bonferroni/Holm) and refusing to read significance into a small lead. Single-dataset version: L023.038
Meaningful vs naive baselineA naive (dummy) baseline — majority class, last value — proves only that the model is non-trivial; a meaningful baseline is the strong established approach a skeptic reaches for (a tuned GBDT; a tuned MLP/ResNet, L028). Beating a weak baseline proves nothing. Lones' rule: freshly implement and equally tune every compared model — the single-table bar an RDL result must clear.038
Significance vs effect sizeTwo questions a review demands together: significance asks "is the difference distinguishable from noise?" (a corrected test, L023); effect size asks "is it big enough to care?" (the raw magnitude). With enough samples a trivial difference is significant; with few, a real one is not — so "p<0.05" with no magnitude, or a mean gap with no test, is half an answer.038
REFORMSKapoor, Cantrell, … Lones, Malik et al. (Science Advances, 2024): a consensus-based reporting checklist for ML-based science, the descendant of the leakage model info sheet (L022). A checklist's whole mechanism is that it makes you answer a question rather than assume it — which is how review catches what taste misses. The peer-review checklist built here is a task-specific instance.038
Synthesis essayA short written argument that assembles prior results into a single claim a reader can accept, reject, or revise — organised by the logic of the claim, not by the order you learned the pieces. Contrast a recap (chronological coverage). Year 1's synthesis answers "what trees beat and why" in four moves: measurement → incumbent → mechanism → frontier.039
Claim (of a synthesis)One sentence a hostile reader could falsify. For Year 1: on typical flat tables a leak-free tuned GBDT matches or beats honest neural baselines and AutoML because of three inductive biases; further single-table cleverness has tied or failed; the claim flips under smooth/rotated/low-junk regimes and is silent on signal a lossy join destroyed; whether keeping relational structure beats the fair flat bar remains open.039
Boundary conditionA stated regime where the claim is not supposed to hold. Without boundaries, "trees win" is a slogan; with them, it is a scientific sentence. Grinsztajn's flips (smooth targets, rotated features, low junk) and "after a lossy flatten" are the Year-1 boundaries.039
Open burdenThe part of the mission the essay must not pretend Year 1 has discharged. Here: no result yet shows a relational model recovering discarded structure to beat the fair flat bar (tuned GBDT + honest neural + AutoML under the peer-review checklist). Naming it keeps the synthesis honest.039
Evidence of recordA number or finding you are willing to cite because it was measured under a disclosed protocol in this course (or in a ★ paper), not recalled as folklore. Prefer verified figures from L010 / L019–L038 over vibes.039
Exhaustion cascadeThe Q4 pattern that successive single-table upgrades — tuned MLP/ResNet (L028), AutoML (L029), entity embeddings (L031), TabTransformer (L032), hand-crafted FE (L033) — repeatedly tie or fail against a tuned GBDT. The unpaid upside is therefore not "try harder on one table" but representation across the join.039
Opponent ladderThe ordered list of baselines a "trees beat X" claim must climb: dummy → weak/untuned net → honest MLP/ResNet → AutoML → embeddings/attention/FE. Distinguishing win from tie from within noise at each rung is what makes the synthesis precise rather than sloganeering.039
Year 1 exit examThe curriculum gate that closes Year 1: a regenerable tuned/fixed tree baseline under a fair protocol plus a written understanding of Grinsztajn's three inductive biases. The lab fork is beat XGBoost on a flat task or explain why not — ties and explanations are full passes.040
Exit fork (BEAT / TIE / EXPLAIN)The three legitimate Year-1 exit outcomes. BEAT = challenger clears the XGB bar by more than a disclosed noise band under a fair protocol. TIE = within noise (modal on typical flat tables). EXPLAIN = no beat, with a written inductive-bias + exhaustion account. Soft-selling a tiny positive as a beat fails the exit.040
Noise band (exit)The disclosed tolerance inside which a challenger–reference gap is called a match, not a win. On OpenML adult under the L020 protocol this exit uses ±0.002 ROC-AUC (the same tolerance L020's CHECK cells used). Smaller positives are TIEs — the antidote to winner's-curse shipping (L036).040
Essay stance (STAND / REVISE)The exit's explicit link back to the L039 synthesis claim. STAND = the regenerable number agrees with the working claim; REVISE = name what changed (a real beat, a broken boundary, a protocol defect). Revising to invent an RDL fair-bar win Year 1 has not shown is not allowed — the open burden stays open.040

Year 2 · Q1 · Neural tabular architectures (L041–L050)

TermDefinitionLesson
Strong simple baselineA cheap, unglamorous model that — tuned under the same protocol as the fancy model — is genuinely hard to beat. Gorishniy 2021's is a well-tuned ResNet (MLP + residual connections), which alone matches many published "novel" architectures. The precondition for believing any deep-tabular result: run it first, or a "win" may just be a weak-baseline artifact (L038 meaningful-baseline rule).041
Shared tuning protocolOne fixed hyper-parameter-search recipe — search space, budget, optimiser, validation split, metric — applied identically to every compared model. Without it, "model A beat model B" can just mean "A got more trials" (a tuning-effort gap wearing a model-quality mask). Promotes L017's fair-budget rule and L038's HP-budget parity to a field standard; it is why Year 2 fixes one protocol for the whole quarter.041
Feature TokenizerFT-Transformer's input layer: it turns every feature into a d-dimensional embedding token. A numeric feature x_j becomes T_j = x_j·W_j + b_j (a learned per-column weight vector and bias scale the single number into a vector); a categorical value is an embedding-table lookup (L031). Its significance: unlike TabTransformer (L032), numerics are tokenised too, so continuous and categorical features can attend to each other.041
[CLS] tokenA single extra learnable token (borrowed from BERT) prepended to the sequence of feature tokens. It carries no input feature; after the Transformer layers its output vector is a pooled summary of the whole row, and the prediction head reads only it. The mechanism that turns a set of per-feature tokens back into one prediction.041
FT-TransformerGorishniy et al. 2021's headline architecture: Feature Tokenizer → prepend [CLS] → L Transformer self-attention layers → read [CLS] → linear head. Its one new idea over TabTransformer is tokenising numeric features, making it the strongest, most universal classic neural single-table model — the neural bar an RDL result must eventually beat fairly (full treatment L046).041
ResNet (tabular)An MLP whose blocks add a residual (skip) connection, output = x + f(x), so deep stacks stay trainable (gradients flow, identity is easy to represent). Not exotic — the point (Gorishniy 2021) is that tuned under a shared protocol it is a strong baseline. First met in L028.041
No universal winnerThe empirical fact that no single tabular architecture beats all others on all datasets — the best model is dataset-dependent, and a tuned GBDT remains a top contender. Gorishniy 2021 reaches it from the architecture side; Grinsztajn 2022 (L024) from the inductive-bias side. The honest framing is "we now have a strong reproducible DL baseline that ties or trades wins with GBDT", not "DL is finally better" (M50).041
rtdl"Research on Tabular Deep Learning": the tested reference PyTorch implementations released with Gorishniy 2021 (MLP, ResNet, FT-Transformer; models in the rtdl_revisiting_models package). Used so neural baselines are strong and standard rather than home-made — a win against a reference implementation means something; a win against your own buggy MLP does not.041
Baseline-first rule ("do these first")Gorishniy 2021's practical instruction: compute the tuned MLP and ResNet baselines, to the shared protocol, before any novel architecture, and report them alongside it. A tuned ResNet alone matches many published "novel" models, so a comparison that skips the strong simple baselines — or pits the fancy model only against a GBDT or an untuned net — leaves the load-bearing question unanswered. Beating a weak baseline is a tuning-effort gap wearing a model-quality mask (L038).042
Shared frame vs search spaceThe two halves of a shared tuning protocol. The frame is identical for every model — same train/valid/test split (L020), same metric, same hyper-parameter search budget, selection by validation. The search space is each model's own knobs (a ResNet varies n_blocks/widths/dropout/lr/weight-decay; a GBDT varies depth/lr/subsample/…). Fairness is equal budget, not equal knobs: change the frame between two models and "A beat B" may just mean "A got more trials."042
Degradation problemHe et al. 2015: a deeper plain network reaches a higher training error than a shallower one — the optimizer cannot find the identity-preserving solution that would make depth harmless (an optimization failure, not overfitting; verified: plain train 1.000→0.927 over depth 1→32, L028). The residual skip fixes it by making that identity solution free (x + f(x), set f≈0) — the entire reason ResNets exist.042
AdamW · weight decay · early stoppingThe neural-baseline training recipe. Adam adapts a per-parameter step from running gradient statistics; weight decay shrinks weights toward zero each step (L2-style regulariser); AdamW applies it decoupled from the adaptive step. Early stopping keeps the best-validation-epoch weights and halts after a patience — the neural analogue of a GBDT's early-stopped n_estimators, so neither model is under- or over-trained by accident.042
sparsemaxMartins & Astudillo 2016: the Euclidean projection onto the probability simplex. Sort descending, find the threshold tau such that max(z − tau, 0) sums to 1, then shift and clip. Like softmax it produces a distribution; unlike softmax it produces exact zeros, because exp(z) is strictly positive and can never switch a feature off. That single property is what lets TabNet's mask be a selection rather than a weighting — a zeroed feature also receives no gradient at that step.043
Decision stepOne of TabNet's N_steps sequential stages. Each step selects a sparse feature subset with a mask, transforms only those features, and adds its own contribution to the prediction (aggregated as ∑ ReLU(d[i])). Mask → transform → sum is a soft, learned analogue of "split on this feature, then on that one" — an attempt to give a neural net the tree-like inductive bias L025–L027 says tables reward.043
Attentive transformerThe block that produces each step's mask: M[i] = sparsemax(P[i−1] · h_i(a[i−1])), where h_i is Linear → BatchNorm and a[i−1] is the previous step's attention output. It converts "what the last step learned" into "which features to look at next".043
Prior scale (γ)TabNet's memory of how much each feature has already been spent: P[i] = ∏_{j≤i} (γ − M[j]) with P[0] = 1. It multiplies the next step's logits, so used features are discounted and the steps divide the features between them. This — not sparsemax — is what makes the attention sequential: sparsity and sequentiality are different properties. The relaxation factor γ is the strictness knob: at γ = 1 the leftover budget is exactly 1 − M, so a fully-used feature is banned from all later steps; larger γ permits reuse (a larger N_steps favours a larger γ).043
Feature transformerTabNet's per-step processing block: Linear → GhostBatchNorm → GLU units, two shared across all steps plus two step-dependent, wired with sqrt(0.5)-scaled residual connections (which keep the variance of a sum of two paths roughly constant). Its output splits in two: d[i] feeds the prediction, a[i] feeds the next step's attention.043
Ghost BatchNormBatchNorm computed independently over small virtual sub-batches of size virtual_batch_size instead of over the whole (very large) batch. With big batches ordinary BatchNorm averages away the noise that helps generalisation; ghost BN keeps some of it. TabNet applies it inside the feature transformer but deliberately not to the raw input features.043
Aggregate mask (M_agg)TabNet's global/local feature attribution: the per-step masks summed with weights η[i] = ∑_c ReLU(d_c[i]) (how much each step contributed to the decision) and normalised to sum to 1 per row. It comes straight out of the forward pass — no separate SHAP/LIME run. Treat it as evidence to validate against known-answer data, not a free explanation (M53): verified global recovery on Syn2 (76.8% of mass on the truth) but only partial instance-wise recovery on Syn4 (15.6% / 97.9%).043
Instance-wise feature selectionSelecting a different relevant feature subset per row, rather than one fixed subset for the whole dataset (global selection). The distinction only becomes testable on data built for it — e.g. Syn4, where X11's sign switches which group of features generates the label, so no single fixed subset is right for every row and a global selector must waste capacity on both.043
Unmet burden vs significantly worseTwo claims to keep apart when a new model loses. Statistical: with few datasets a large p (L043: Friedman p = 0.127, N = 4) licenses only "cannot distinguish on this sample" — neither "significantly worse" nor "equivalent", since failing to reject is not evidence of equality (L023). Evidential: the baseline-first rule puts the burden of proof on the new model, so ranking behind the baselines it was designed to beat (TabNet 2.50 vs MLP 1.75 / ResNet 2.00) means the burden was not met. The bar stays testable even when the test is under-powered.043

Relational entity graph (REG) — the graph whose nodes are rows and edges are foreign keys. Message passing — how a GNN propagates information along those edges.
