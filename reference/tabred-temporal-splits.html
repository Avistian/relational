The split is part of the claim

Skill: choose a test that estimates the deployment quantity, then audit every information boundary used to fit and select the model.

QuestionOperational rule
Same-period interpolation?Random holdout may match this target if rows are suitably exchangeable. Check groups and repeated entities.
Train now, predict later?Historical train → later validation → later test. Respect retraining and selection dates.
Strict timestamp boundary?train: t<a; val: a≤t<b; test: t≥b. Keep tied timestamps together, accepting changed counts.
Past event, available label?Label arrival must be no later than fitting/selection deadline; features must be available at prediction.
Preprocessing scope?Fit imputation/scaling on training only; apply the frozen state later.
Model-selection scope?Choose checkpoint and hyperparameters with validation. Compute selected-model test predictions afterward.
Random vs temporal gap?Report protocol sensitivity; both training and test populations change. It is not isolated causal drift evidence.
Uncertainty?Training seeds condition on fixed rows. Rolling origins probe other periods. Windows may overlap and are not automatically independent.
Cross-task ranks?Average seeds and windows within each dataset before ranking models. Do not count seeds as datasets.

Temporal prediction contract¶

Boundary Required record
Split Stable row IDs, cutoff convention, tie policy
Feature Value and availability at prediction time
Label Outcome horizon and label arrival time
Selection Validation period and frozen decision rule
Refit Exact eligible history used after selection

An event on day 10 with an outcome available on day 20 cannot supply that outcome to a day-12 prediction. Random and temporal tests estimate different deployment questions; preserve separate panels. A temporal score change motivates a diagnosis, not an automatic claim about the cause of drift.
