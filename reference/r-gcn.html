R-GCN: routing, sharing, evidence

Recall the equation before using this sheet. A relation specifies an edge role and direction; endpoint types alone can be insufficient.

One layer, row-vector convention

H_next = activation(Σ_r S_r H W_r)
S_r[i,j] = 1 / degree_r(i) for a message j → i
W_r: d_in × d_out; H: N × d_in
Include identity support once for the self path.

Normalize each relation separately. Empty relation neighborhoods contribute zero. For buys={2,8}, returns={8}, self=1 and weights 2,−1,1: the output is 2×5−8+1=3. Moving the feature2 edge from buys to returns changes it to 2×8−5+1=12.

Three parameterizations

ChoiceWeightsParametersRestriction
IndependentOne W per relationR d_in d_outNo cross-relation sharing

Here R counts all supports if self is included. Basis coefficients are unconstrained, not probabilities. B is not a bound on each W's matrix rank. Block counts require divisible dimensions.

Featureless does not mean information-free

Identity input gives a separate coordinate to each known node. Compute S_r W_r directly instead of allocating I. A two-layer model needs the roots' two-hop context. The released pruning keeps rows for labeled roots and their one-hop neighbors and retains their source columns.

Failure checklist

  • Are adjacency rows receivers, and are inverse relations separate?
  • Did you accidentally normalize across all relations or add self twice?
  • Do basis coefficients receive gradients through the actual trainer?
  • Are target-generating predicates gone before training?
  • Does loading RDF twice preserve blank-node identities and ordering?
  • Did held-out labels influence gradients, hyperparameters or seed selection?
