# Parent source audit for lesson 069

Sources independently read: [paper v1, 22 May 2025](https://arxiv.org/html/2505.16226v1), including §§3–5 and Appendices D–H; [released evaluation snapshot](https://github.com/LAMDA-NeSy/Evaluation-on-Tabular-Model-in-Open-Environments/tree/744c010457f68284faa7ae6ded793a8b3f3e03a4), especially `newclass.py`, `run_experiment.py`, and `distribution_objectives.py`.

The repository's entire visible history starts on 19 June 2026. Its README names v2.5 and its requirements name a later package. It is useful evidence about the released implementation, but it cannot establish which code generated the May 2025 paper's tables. The lesson must keep current-source findings separate from historical result claims.

## Claims requiring correction or qualification

- §5.1 claims TabPFN wins novelty detection across all four datasets. Table 1 gives Wine-Red MLP ROC-AUC/AP of .700/.658 versus TabPFN .533/.521; CMC MLP also exceeds TabPFN. Several results are near the .5 balanced-test baseline. A potential confidence signal is narrower than demonstrated robust open-world recognition.
- `newclass.py` turns maximum probabilities in [.4,.6] into binary decisions before `roc_auc_score` and `average_precision_score`. Binary-score AUC is `(TPR + TNR)/2`. Average precision is not trapezoidal integration of a precision–recall curve. With at least three known classes, a maximum probability of .34 lies outside this interval while .50 lies inside it, so the detector is not monotone in uncertainty.
- The novelty source truncates every feature to integers, uses a fixed seed of 42, and overwrites rather than accumulates each held-class result. TALENT branches also reserve 10% of known context for validation while plain TabPFN/XGBoost branches use all remaining known examples. These are current-source discrepancies, not proof that the published table was generated with these defects.
- Appendix F defines a relative performance gap; Table 2 displays absolute differences. Example: .852 to .809 is −.043 absolute, approximately −.05047 relative. The regression .928 to 1.034 annotation +.104 is also arithmetically inconsistent with the printed endpoints (+.106).
- Feature source `least`/`most` selects from correlations computed using the whole labeled frame, including test labels. It repeatedly appends the same mutable DataFrame, so the saved levels alias one object. Numeric degrees count the label column; degree 1 requests more features than exist and leaves no frames to concatenate. The random/all branch instead enumerates every subset, creating repeated measurements of the same test rows.
- §5.2's fixed-dimensional-parameters explanation is misleading for a model accepting variable feature counts. A fitted context and query still need aligned feature meaning; ignoring a newly arrived feature is a chosen compatibility policy, not evidence that its information is usable without context support.
- §5.3 calls XGBoost best for distribution shift, whereas Table 3 ranks CatBoost 2.00 versus XGBoost 2.25 on that axis. §5.5 says RandomForest outperforms TabPFN generally, whereas its displayed overall rank is 3.93 versus TabPFN 3.53 (lower is better).
- `distribution_objectives.py` samples without `stratify`, mutates the retained source/target cohorts inside its seed loop, and uses California for the 2010→2017 comparison; Table 10 identifies New York. Table 10's NE→LA row's printed counts do not sum to its total.
- Source F1 is macro averaged. Table 11's TabPFN BRFSS accuracy .875 and F1 .044 cannot describe binary macro F1 on the same predictions: for binary accuracy `a`, macro F1 is at least `a/(1+a)`, here .4667. The source and paper therefore require a metric-definition reconciliation. Do not silently treat one as the other.
- FDD of fixed classifier activations `f(X)` cannot detect a pure change of `P(Y|X)` when the distribution of `X` is identical. Reusing exactly the same feature rows and flipping their labels leaves these activations and their FDD unchanged. The paper's activation-distance proxy does not by itself identify conditional shift. DISDE's risk decomposition is a separate construction requiring conditional risk estimates and overlap.
- Appendix H compares several metrics on fixed predictions; it does not establish that the model was retrained for four losses. Claims of statistical significance or general architecture superiority require more than comparing those printed metric values.

## Independent check design

The parent operator `labs/_evidence_l069.py` imports neither lesson evaluator nor lesson model. It reconstructs source CSV identities, partitions, required-row targets, class mapping, tied-rank AUC, stepwise AP and all-row losses. Original TabPFN 2.0.9 supplies complete model predictions, using an independently checked compact attention adapter with the historical float32-rounded scale to bound CPU memory. A separate unmodified original-source check covers whole-model outputs and all parameter gradients. XGBoost predictions are independently refitted using the declared recipe. Actual run outcomes belong in the JSON acceptance reports, not this source-reading note.
