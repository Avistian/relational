# Review — PluRel-to-RDB-PFN: Schema-Guided Synthetic Relational Pretraining

- **arXiv:** [2607.29129](https://arxiv.org/abs/2607.29129) (v1, cs.LG, Jul 2026)
- **Authors:** Mohammad Sadeq Abolhasani, Viswanath Ganapathy
- **Tag:** [RDL]

## Problem

Relational Foundation Models (RFMs) need large-scale synthetic relational
databases for pretraining, but existing approaches **tightly couple data
generation to the training pipeline**. This companion study to "Curriculum
Matters" (2607.29120) asks whether a *general-purpose* synthetic generator,
PluRel, can serve as an **external** data source for RDB-PFN — which was
originally pretrained with a ~600K-task single-table warm-up followed by a
~1.8M-task relational adaptation — and how the training curriculum should be
ordered with respect to real-world schema exposure.

## Method

- **Conversion pipeline.** Map PluRel-generated databases (including externally
  constructed binary prediction tasks) into the RDB-PFN training format,
  decoupling generation from the model pipeline.
- **Three curricula.**
  - **Schema-Guided First:** real-world schema first, then fully synthetic.
  - **Fully Synthetic:** diverse synthetic schemas throughout.
  - **Schema-Guided Last:** fully synthetic first, then real-world schema.
- **Budget.** Only ~5,500 relational databases (~33K tasks), ~55× fewer tasks
  than the original protocol, and **no single-table warm-up**.
- **Evaluation.** 19 real benchmark tasks at 1024-shot and 64-shot context.

## Key results

- **Schema-Guided First wins.** Best curriculum reaches **0.6346 avg ROC-AUC**
  at 1024-shot, recovering **87.6%** of published RDB-PFN performance (0.7245)
  using ~55× fewer tasks and no single-table warm-up.
- **Gap narrows in low-shot.** At 64-shot context the recovery rises to **93.8%**
  (0.6116 vs. 0.6517) — the external-generator recipe is relatively stronger when
  context is scarce.
- **Early schema exposure beats late adaptation.** Seeing a real-world schema
  *early* in training is substantially more effective than late-stage schema
  adaptation (Schema-Guided First > Fully Synthetic > Schema-Guided Last).

## Fit with the tabular curriculum

Feeds the **Y5 Q2 relational pre-training-pipeline design** lectures: it shows
the data generator can be *decoupled* from the RFM training loop, and that
curriculum ordering — specifically *when* a real schema is introduced — is a
first-class design lever. Complements 2607.29120: that paper isolates
single-table→relational curriculum effects; this one isolates generator
decoupling and schema-timing. Together they argue the synthetic-prior design
space, not raw scale, governs RFM quality.

## Caveats / limitations

- **Recovers ~88% (1024-shot), not parity.** Still a measurable accuracy gap vs.
  the full-scale protocol; framed as data-efficiency, not SOTA.
- **Compared to reported RDB-PFN numbers.** No identical-condition re-run of the
  original 2.4M-task recipe.
- **Single generator + single target model.** Generality to other RFMs/generators
  untested; three fixed curricula, not a searched schedule space.
- **Binary tasks, 19-benchmark slice.** Narrower task scope than production RFM
  evaluation; "real-world schema early" is demonstrated, not yet mechanistically
  explained.

## Take-home

An off-the-shelf synthetic relational generator (PluRel) can pretrain RDB-PFN to
~88% of its published accuracy with ~55× fewer tasks and no single-table warm-up
— provided the curriculum exposes a real-world schema *early*. Evidence that RFM
pretraining pipelines can be modular, with curriculum ordering as a key knob.
