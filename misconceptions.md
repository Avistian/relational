# Misconceptions Ledger

A living record of misconceptions surfaced (and corrected) during lessons and labs. Each entry is a
durable re-test target: the spaced-retrieval bank (`assets/retrieval-pool.js`) draws from these so a
mistake made once keeps coming back until it is genuinely gone.

**How to use.** When a lab CHECK, warm-up, or check-in exposes a wrong belief, add a row here with the
*wrong* belief, the *correct* one, and the origin lesson. Then add a matching question to
`assets/retrieval-pool.js` tagged `"misconception": true` so it enters the spaced rotation. When the
learner answers a misconception question correctly across ≥2 spaced sessions (Leitner box ≥ 3), mark it
**retired** here (keep the row for history).

Status legend: **active** = still re-testing · **retired** = answered correctly across ≥2 spaced sessions.

## Q3 (Lessons 021–030)

| # | Lesson | Wrong belief | Correct belief | Status |
|---|--------|--------------|----------------|--------|
| M18 | L021 | A random (shuffled) split is the default-safe way to evaluate any tabular model | On time-ordered / drifting data a random split leaks the deployment period into training and is **optimistic** (random-CV 0.846 vs temporal 0.758); use a **temporal split** (train past → test future) / `TimeSeriesSplit` whenever a time order or drift exists — assume temporal until you can argue the rows are truly i.i.d. | active |
| M19 | L022 | A very predictive feature (or a big complex-vs-simple win) is good news | It is a **leak hypothesis first**: an **illegitimate feature** (L2, knowable only at/after the outcome) passes every pipeline/split check yet hands the model the answer, and a flexible model exploits it harder than a linear one — so removing it can collapse a huge apparent win (RF 0.935 vs LR 0.719 → 0.712 vs 0.721). Audit feature **provenance** with a model info sheet | active |
| M20 | L023 | A mean-accuracy gap (or a paired t-test / Wilcoxon over CV folds) tells you model A is really better | k-fold training sets **overlap**, so fold scores are **positively correlated**; a naive paired t-test (and Wilcoxon) treat them as independent and **over-reject** (naive p=1.2e−5 vs corrected 0.19 for a +0.0098 gap). On one dataset use the **corrected resampled t-test** (inflate variance by `1/n + 1/(k−1)`); across many *independent* datasets use **Friedman + Nemenyi CD**. Report an effect size, not just a p-value | active |
| M21 | L024 | Comparing two model families by each one's single best tuned score is a fair benchmark | One tuned number **hides how much tuning each model needed** and its **default quality**, flattering the model that is hardest to tune. Report a **random-search budget curve** (select by validation, report test, avg over orderings) that shows both the default (k=1) and the ceiling; on credit-g the GBT leads at **every** budget (default gap +0.062 → tuned +0.015). Aggregate across datasets via **per-dataset min-max normalization**, and curate datasets by explicit criteria first | active |
| M22 | L025 | Trees beat MLPs on tabular data because trees are simply more powerful / higher-capacity models | It is an **inductive-bias mismatch**, not raw strength. An MLP trained by gradient descent has a **smoothness (spectral) bias** — it fits low-frequency structure easily and high-frequency detail poorly (Rahaman 2019) — while typical tabular targets are **irregular**; a piecewise-constant tree follows the jags. Proof: **Gaussian-smoothing the target** deletes the high-frequency structure and the gap **collapses in lockstep with the variance removed** (repro: +0.33 R² → ~0, MLP even edges ahead once smooth). On a genuinely smooth target the MLP ties or wins | active |
| M23 | L026 | Rotation invariance is an elegant, desirable property — a model that doesn't care about the feature basis is more robust | On **tabular** data it is a **liability**: columns carry individual meaning (age, balance), so the original basis aligns the signal with the axes. An MLP/ResNet is rotationally invariant (linear first layer: `W·(Qx)=(WQ)·x`); a tree and an FT-Transformer are **not**. A random rotation is **lossless** (Q invertible) yet collapses a tree while leaving the MLP unmoved — **reversing the ranking** (repro: tree 0.987→0.747 vs MLP 0.862→0.869, +0.008). Ng 2004: an invariant learner's sample complexity grows **≥ linearly in the number of uninformative features**. Invariance is good on images (rotated cat = cat), bad where a natural basis exists — which is why numeric-feature embeddings that *break* invariance (SAINT, FT-Transformer) help | active |
| M24 | L027 | Pure-noise features carry no signal, so every model just ignores them | Only a **tree** ignores them — via **greedy, gain-gated split selection** (a ~0-gain noise column is never chosen = implicit feature selection). An **MLP is not robust to uninformative features** (Grinsztajn §5.3, Finding 2): it wires every column into its first layer and, being rotationally invariant, has no gate to tell a useful axis from a useless one, so (Ng 2004) it needs **≥ linearly more samples per junk feature** and instead leaks capacity onto the noise. Repro: on a smooth target where the MLP *wins* clean (0.986 vs GBT 0.945), adding 100 junk cols costs the MLP **0.084** vs the GBT **0.032** — the ranking **reverses**; removing junk helps the MLP more. Gate is visible as root-split gain ~**118×** higher on informative vs junk (use root gain, **not** MDI — MDI over-credits noise) | active |

| M26 | L029 | AutoML replaces feature engineering and beats a hand-tuned model — just point it at the data | AutoML (Auto-sklearn) automates the **CASH** search (which algorithm + its hyperparameters, selected by validation) plus meta-learning warm-start and Caruana **ensemble selection** — it does **not** do domain **feature engineering** and does not change the **representation**. On typical tabular data it **ties** a competently tuned GBDT: the big gain is tuning *at all* (credit_g: default XGB 0.775 → tuned 0.806, +0.031), after which a 4-algorithm AutoML with ensembling only matches it (0.803, bands overlap) at far higher compute. It buys automation/robustness, not new accuracy — remaining upside must come from a better representation (the relational thesis), which AutoML never touches | active |
| M25 | L028 | Adding more layers to a neural net always helps (more capacity), and if a deep net does worse it must be overfitting | A deep **plain** MLP gets *worse* with depth — the **degradation problem** (He et al. 2015) — and its **training** accuracy falls too, which rules out overfitting (that would keep train accuracy high). It is an **optimization** failure: the extra `Linear→ReLU` layers cannot easily learn to reproduce their own input. A **residual/skip connection** (output `x + f(x)` instead of `f(x)`) fixes it by making the **identity map free** — `f≈0` is trivial, so a deep ResNet can fall back to a shallow solution and depth can't hurt. It is **not** vanishing gradients (both nets use BatchNorm, which fixes those). Repro: same net, skip OFF plain test 0.917→0.866 & TRAIN 1.000→0.927 (d1→d32); skip ON ResNet holds ~0.90 / train ~1.00. And building the honest baseline does **not** make DL win — a tuned GBDT still leads on small categorical data (credit_g GBDT 0.793 vs MLP 0.752 ≈ ResNet 0.743) | active |
| M27 | L030 | A benchmark must crown a winner; a report that ends in "no significant difference" is a failed or uninformative experiment | A **correctly-established tie is a valid, valuable result.** A reported gap is a random variable, and k-fold scores overlap, so a bigger mean is not a win — you must run a **corrected resampled t-test** (or Friedman + Nemenyi across datasets) and report the effect size. On credit_g the GBDT led the honest MLP baseline by only **+0.0081 ROC-AUC** over 25 paired folds, and the corrected test gave **p=0.64** (naive p=0.22) → **no significant winner**. Writing "GBDT wins" from the +0.008 mean is exactly the L023 mistake. Being willing to report a tie is what makes an eventual "RDL beats the incumbent" claim from the same protocol credible | active |
| M28 | L031 | Target (mean) encoding is a safe, powerful way to handle categoricals — just replace each level with its mean target | It is powerful **but leaks** because it is built *from the label*. Computed naively (a level's mean includes the row's own label, or the encoding is fit over all data before the split), a **near-unique id becomes a copy of the answer**: a signal-free customer_id scored test AUC **0.891** on credit_g-sized data, collapsing to **0.504** (chance) once encoded **out-of-fold**. Fix: encode each fold from the *other* folds only, **smooth** toward the global mean by count `(n·mean+m·global)/(n+m)`, and fit the encoder **inside** the CV fold (same L002/L022 leakage discipline). The danger grows with cardinality — worst on the foreign-key ids that point into other tables | active |
| M29 | L031 | Entity embeddings are a strictly better categorical encoding — a learned representation beats one-hot | On a small flat table they **tie**. An entity-embedding MLP scored **0.774 ± 0.033** vs a **fair** one-hot MLP **0.798 ± 0.043** on credit_g (overlapping bands); only an **undertrained** one-hot baseline (0.728) made embeddings look like a +0.07 winner — the L028 weak-baseline trap. Embeddings add **similarity structure** (a learned d-dim vector per level; target encoding is the 1-D case) and **compactness at high cardinality**, but a 1000-row single table has little similarity/cardinality to exploit. The payoff is **representational** and shows up at scale and on high-cardinality foreign keys — the bridge to RDL, not a free accuracy win here | active |
| M30 | L032 | TabTransformer's self-attention beats gradient-boosted trees on tabular data | It **matches** (ties) tree-based ensembles on supervised tabular data. The paper's headline **+1.0% mean AUC is over other DEEP methods** (like L028's honest-baseline story), *not* over trees; its genuine advantages are **robustness** to noisy/missing features and a **+2.1% semi-supervised** lift from pre-training on unlabeled data. The tie is expected — attention over a row's columns is still single-table cleverness (L028/L029/L030/L031), and the thesis bets the untapped value is the relational structure across tables, where the same aggregate-over-neighbours operation (a GNN over foreign keys) is headed | active |
| M31 | L032 | A "contextual" embedding is just a bigger / better entity embedding | It is a **different** object: L031's entity embedding is **context-free** (a level gets the same vector everywhere), while a **contextual** embedding's vector **depends on the other columns in the same row** (the 'bank' = river-bank vs savings-bank analogy). Self-attention computes it as `softmax(Q·Kᵀ/√d)·V` — each column (token) emits a query/key/value and its output is the **weighted blend of every column's value vector**. Not wider, not merely tuned — *row-contextualised*. And "contextual" ≠ "more accurate" on a flat table: a tuned tree already captures column interactions, so the extra machinery pays off under noise/missingness or with unlabeled data | active |
| M32 | L033 | Feature engineering always helps — keep adding hand features until you run out of ideas | Returns **diminish and then go negative**: each added feature raises variance (Domingos 2012, "overfitting has many faces"), so held-out score eventually **falls**. On credit_g with a fixed strong GBDT, hand features peaked at just **k=3** (0.7911 vs 0.7865 baseline, **+0.0046 — inside the ±0.032 CV band**, i.e. not significant, L023/L030) then **declined to 0.7659 below baseline** by k=8. The stopping rule is **not** "ran out of ideas" but "the marginal held-out gain sank below the CV std σ" (entered the noise band); past that you only pay the overfitting tax. Then reallocate the budget to more **data** ("more data beats a cleverer algorithm") or tuning | active |
| M33 | L033 | Diminishing returns from feature engineering is a fixed property of the dataset | It is **model-relative**. The *same* engineered feature can be worth +0.35 R² to a **linear** model that cannot synthesise it (L009: Ridge 0.64→1.00) and ≈0 to a **GBDT** that already builds interactions through its splits. On credit_g the GBDT drifted **−0.011** over 0→10 features while the linear model drifted **+0.006** — both inside their noise bands, but for opposite reasons. Always ask "diminishing returns **for which model?**"; FE budgets differ by model family | active |
| M34 | L034 | The flat training table is just how the data comes — you load it and start modelling | The design matrix is the **output of a hand-built flatten**, not a given. Someone chooses the **grain** (one customer as of `t`), writes each **join** over foreign keys, picks each **aggregate** (COUNT/SUM/AVG/MAX to collapse the one-to-many orders), and guards each with a point-in-time filter. It is a per-task pipeline of DFS-style primitives (L009) that **deliberately discards** relational structure (cardinality, event order, identity, multi-hop paths). Getting the grain wrong (e.g. forgetting the `GROUP BY`) trains on duplicated order-level rows; an inner join silently drops zero-order customers (use `LEFT JOIN` + `fillna(0)`). This flatten is exactly what RDL proposes to replace by learning over the PK/FK graph | active |
| M35 | L034 | A point-in-time feature is safe as long as you don't include the label / target column | PIT correctness is about **every feature**, not just the label. An aggregate over a customer's orders leaks if it includes orders placed **after** the prediction time `t` — the future is baked into the *feature* even though the label is untouched. The guard is a filter (`order_ts < t`) applied **before** aggregating, re-imposed on every aggregate and re-imposed each time the same DB is flattened for a new task (demo: dropping it moved C1 from n=3/total=125 to n=4/total=1124). Dropping the timestamp column afterwards does **not** undo the leak — the future values are already inside the aggregate | active |
| M36 | L035 | If a flattened design matrix loses signal, a better / bigger model can recover it | It **cannot** — the loss happens **before** the model, in the aggregation. Join+aggregate is a **lossy (surjective) map**: two customers with different histories (Ada rising $10→$30→$50 over 3 products; Bo falling $50→$30→$10 on 1 product) flatten to the **identical** row `n=3/total=90/avg=30/max=50` (an **aggregation collision**), so a fitted model gives them the **same** P(churn)=0.502 though their true labels differ (0 vs 1). Identical input ⇒ identical output for **any** learner; the discarded structure (temporal order, event identity, multi-hop paths) is not a capacity/tuning/leakage problem but Fey 2024 §2 issue (4): "forcing data into a single table aggregates into lower-granularity features, losing fine-grain signal." "Just use XGBoost / a deeper net" is no answer | active |
| M37 | L035 | You can just add more aggregates until the flatten captures everything | Each bespoke aggregate recovers **one** lost dimension for **one** task (`spend_trend`=last−first restores temporal order: +40 vs −40; `n_distinct_products` via a 2-hop join restores identity: 3 vs 1) — but the space of collisions is **unbounded** (a third customer Zoe with orders 30/10/50 collides on the same four aggregates), the features are per-task, and each must be re-derived and **re-leak-checked** when the schema/task drifts (Fey issue 5). Hand-built aggregates chase losses **one at a time**; RDL keeps the PK/FK **graph** (row=node, key=edge) and learns the aggregations end-to-end, addressing the whole **class** of loss rather than patching collisions individually. (Also: "lossy" ≠ "leaky" — a pipeline can be perfectly point-in-time correct and still discard the structure of its legitimate pre-`t` rows) | active |

| M38 | L036 | Finding a leak means the reported metric was inflated | A leak only inflates a number **computed downstream of it** — so name the contaminated quantity before estimating damage. In the audited homework pipeline the outer CV is correctly person-grouped, but `CalibratedClassifierCV(estimator, method="isotonic", cv=5)` takes a **nested** split of the outer *training* block with a plain `StratifiedKFold` that has no `groups` argument, so one situation of a person fits the base LightGBM while another fits the isotonic map. Because it all happens **inside** the training block, the outer test fold never enters the calibrator's fit: the reported log-loss (1.4248) and ECE (0.0363) are **honest**. What is damaged is the **artifact** — the isotonic map was tuned against optimistically sharp scores and is mis-shaped for unseen persons (re-measured with a grouped inner split: 1.4232 / 0.0360, correctly directed and far inside the 0.039 fold σ). Four consequence classes exist: inflates the **number**, degrades the **artifact**, changes the **decision**, or is only a **caveat** you owe the reader | active |
| M39 | L036 | The model with the lowest mean CV score is the best model — that's what "best" means | The **maximum of several noisy correlated estimates is optimistically biased** (the winner's curse), so an argmin over models scored on the same few folds is a *decision*, not a measurement, and it can be wrong while every number is right. The audited pipeline shipped **M2a over M1 on Δ = 0.0032 nats** — **8 % of one fold's std**, losing **2 of 5 folds**, naive paired p = 0.64 and Nadeau–Bengio corrected p = 0.75 — and the winner **flips to M1 when fold 2 is dropped** (fold 2 supplies M2a's entire margin). Worse, the report justified the pick by a tie-break rule that `pick_winner` never actually fired (M2a was already the log-loss argmin). A tie should go to the **simpler** model; and the report's one "significant" claim (M1−M0, naive p = 0.0146) does **not** survive correction (0.0514) or Holm over its 4 tests (0.0583) — believe the effect (M1 wins 5/5 folds by 0.055 nats), drop the word "significant" | active |
| M40 | L036 | Fitting an imputer / scaler / KMeans on all rows is safe because it's unsupervised | "Unsupervised ⇒ safe" is a claim about **labels only**, and it is doing more work than it can bear. Fitting on all rows is **transductive**: the medians, scaler means and one-hot vocabulary were computed from rows including every outer test fold, so the CV number is **not a deployment estimate** — at inference time on a row that does not exist yet, those statistics could not have been computed. The audited pipeline calls `pipe.fit_transform(X_all)` on all 119,498 rows *before* the CV loop exists, and the same sentence then licenses `unsup.fit(X_all)` (KMeans centroids placed using test rows — in the **shipped** M2a) and `propensity.fit(X_all, mask)` (whose internal OOF split is an **ungrouped** `StratifiedKFold(5)`, so a person's other situations help predict their own labelling probability). Price each use separately by re-measuring, rather than reusing the defence | active |

| M41 | L037 | Setting a random seed makes a pipeline reproducible | Seeding is necessary, not sufficient, and "all randomness is seeded" can be **true and completely uninformative**. Two failure modes were measured on the audited pipeline. (1) **The seed can be inert.** LightGBM reads `random_state` only when it *samples* — `bagging_fraction<1`, `feature_fraction<1`, `extra_trees` — and this configuration sets none, so seeds 0–4 give a **bitwise identical** out-of-fold matrix. (2) **Things that were never seeded still move the number.** Removing one undocumented `.astype(np.float32)` — a cast that lives in a notebook cell, mentioned in neither the README nor `src/` — flips the predicted class for **258 of 5,587 people** (max Δp = 0.326) while moving mean log-loss by only **+0.00133**, i.e. 42 % of the 0.0032 margin that chose which model shipped. And the *same literal* `RANDOM_STATE = 0`, handed instead to `StratifiedGroupKFold(shuffle=True)`, spans **0.0166 nats** over five draws — 5× that margin. Reproducibility is an empirical property you **probe** (perturb one input, hash the full output), not a property you assert by calling `seed()` | active |
| M42 | L037 | Two runs that agree on the headline metric reproduced each other | A summary statistic is a **lossy** comparison: it can agree while the underlying predictions disagree substantially, because a mean over 5,587 rows absorbs offsetting per-row changes. The float32→float64 probe moved mean log-loss by 0.00133 — a number most reproduction gates would wave through — while changing **258 argmax decisions**, i.e. 258 people who would receive a different intervention. Gate on a **hash of the full prediction matrix** (dtype and memory layout normalised first) whenever bitwise reproduction is achievable; on this pipeline eight of nine perturbations were byte-identical, so the bitwise gate is both attainable and free of false alarms. Fall back to `|observed − expected| ≤ tol` only when something genuinely stochastic enters, choose `tol` **before** the first failure, and keep it below the smallest difference you would act on | active |
| M43 | L037 | ECE is ECE — if two places report it for the same model, the difference must mean something about the model | The metric name is not the estimator, and the same predictions legitimately yield **0.0332** (binned inside each of 5 folds, then averaged) and **0.0178** (all 5,587 rows pooled and binned once) — a **1.87×** spread that says nothing about the model. Cause: ECE bins first and then sums **|accuracy − confidence|** weighted by bin population, so the absolute value stops hot and cold bins cancelling and the estimate is biased **upward** as bins thin. Log-loss, a plain per-row mean, agrees to five decimals either way. Verify with a control that is perfect **by construction** (resample each row's label from its own probability vector, so true ECE = 0): the floor is 0.0149 pooled but **0.0335** at fold size — meaning the per-fold 0.0332 is essentially **all ruler**. The submission's one failed ship-gate (107-row `age = missing` slice, ECE 0.094 vs a 0.05 threshold) sits **below** its own floor of 0.1071 ± 0.0297: that gate cannot be passed by any model. Counter-intuitive corollary: the estimator choice matters **least** when the model is badly calibrated (at ECE ≈ 0.093 the two agree within 1 %) and **most** when it is good — i.e. exactly when you are about to ship | active |

## Q4 · peer review (Lesson 038)

| # | Lesson | Wrong belief | Correct belief | Status |
|---|--------|--------------|----------------|--------|
| M44 | L038 | A good peer review is a thorough list of every flaw you can find | A review **triages**, it does not enumerate. Grade each finding **blocker / major / minor / nit** on **two independent axes** — *conclusion-impact* (would fixing it change the claim?) and *artifact severity* (how broken is the thing itself?) — because they come apart: the audited pipeline's ungrouped inner calibration split is high severity (the shipped isotonic map is mis-shaped for strangers) but low conclusion-impact (the leak is confined to the training block, so the reported 1.4248 / 0.0363 are honest; grouped re-measure 1.4232 / 0.0360 is inside the 0.039 fold σ), while the M2a-over-M1 selection on **0.0032 nats** is low artifact severity (every number is correct) but maximal conclusion-impact (it *is* claim 1, and it does not survive correction, p=0.75, flipping on dropping fold 2). The output is a **verdict** (accept / minor / major / reject) **with required changes**; a wall of ungraded findings buries the one blocker under the nits and lets fatal flaws through | active |
| M45 | L038 | When reviewing your own result that beats a baseline, focus your scrutiny on the novel model — it is the contribution | The mission's claim is **comparative**, so it needs **two** pipelines reviewed to **one** standard, and the baseline you want to beat is the one you are **least motivated** to scrutinise. A generous review of the model you love plus a lazy one of the baseline is how honest people publish false wins. Hold the GBDT baseline to identical **HP budget parity**, the same 8-type leakage sweep, and the same **corrected** significance test (+ effect size). The classic unfair moves a skeptic re-checks: reporting the **max** over many runs (winner's curse), tuning the novel model **harder**, and **metric cherry-picking** — all named by Lones 2024. Do the hostile review first, because the reviewer of your eventual RDL paper certainly will | active |

| M46 | L039 | A Year 1 synthesis is a chronological recap of lessons 001–038 | A synthesis is an **argument** organised around a **falsifiable claim**, not a tour of what you studied. ## Q4 · Year 1 exit exam (Lesson 040)
