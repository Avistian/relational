A table-aware architecture changes what can be shared¶

Your goal is to explain the Nature-v2 computation and audit its accuracy/cost claim on a declared protocol. The primary source is Hollmann et al., Accurate predictions on small data with a tabular foundation model, especially Figure 1 and Methods. The paper reports strong downstream performance in the studied small-data regime, including comparisons with substantially tuned baselines. It does not establish that every released TabPFN version beats every tree recipe on every table.

Version identity is part of the experiment. A present-day default constructor can load a newer model than Nature v2. This lesson uses tabpfn==2.0.9 and a pinned v2 classifier checkpoint, not a moving default. Later checkpoints are separate arms with separate access, preprocessing, capacity and cost contracts.

A row token and a cell token expose different structure¶

In the row-token route, a feature encoder compresses an entire row into one vector before context attention. In the local axial route, each feature cell retains a token, and a separate target token represents the label role. Attention can then alternate between relationships within a row and relationships across rows at a fixed token position.

Let B be the number of task episodes in a batch, C context rows, Q query rows, N=C+Q, F features and D hidden width. With one target token, G=F+1 token positions per row. The hidden array has shape B×N×G×D. These axes represent different semantic objects; a correct reshape must preserve their identities.

The official v2 system contains additional encoders, feature grouping/identity mechanisms, pretraining choices and inference procedures. The local AxialPFN isolates alternating feature and context-row attention. It is useful because you can inspect the information graph, but it is not a complete architectural reproduction of the pretrained system.

Think of the target token as a readout location that can gather information, not as a hidden copy of the query's true label. Context target tokens receive observed labels; query target tokens receive an unknown representation. The model must infer the query target from legal inputs.

Model architecture: alternate the two table axes¶

Instead of reducing each whole row immediately to one token as in v1, v2 constructs representations for feature cells or feature groups, plus a target representation. Think of a hidden tensor with axes [batch, rows, feature_groups_plus_target, hidden_width]. A feature-attention operation mixes feature representations within each row. A sample-attention operation mixes the corresponding feature-group representations across eligible context rows. Feed-forward transformations, normalization and residual paths accompany these operations in repeated blocks. The query's final target representation feeds the prediction head.

The released model also contains feature grouping, specialized preprocessing/encoders and identity features. Those details matter for duplicate rows, heterogeneous values and the precise symmetry of the system. “Table-aware” does not imply that every preprocessing-plus-ensemble configuration has exact arbitrary permutation invariance. Our reduced AxialPFN shows one scalar per feature, a separate unknown-target token and explicit feature/sample attention. It omits those released implementation details and does not load the official weights.

Reshaping declares which objects may communicate¶

For feature attention, reshape B×N×G×D into (B·N)×G×D. Every row becomes an independent sequence of G tokens. Its feature and target tokens can exchange information, while other rows remain in separate batch items.

For sample attention, first permute to B×G×N×D, then reshape to (B·G)×N×D. Every token position becomes an independent sequence of rows. The context mask allows these receivers to read labeled-context row positions and blocks query sender positions.

The permutation before reshaping is load-bearing. A bare reshape does not logically swap axes; it reinterprets the current storage order. If you merge the wrong adjacent dimensions, the output can have the desired shape while mixing different features and rows. Use a tensor whose entries encode their row and feature IDs to test the round trip.

For example, assign a scalar diagnostic value 10r+f to row r, feature f. After moving features into the batch axis, the sequence for feature 2 should contain 2,12,22,… across rows. Seeing 20,21,22 instead means you preserved a row sequence rather than a feature sequence.

The attention block returns the same sequence shape it received. Restore the grouped axes, then permute back to B×N×G×D. Shape preservation is necessary, but the identity-coded fixture is what checks semantic preservation.

Residual paths keep information available¶

Attention mixes values, while residual connections retain a direct route from each token's previous state. Feed-forward transformations then act on hidden coordinates. The complete block is not just a matrix of averages; normalization, projections and nonlinearities can transform what the values mean.

The local implementation applies an attention/feed-forward block on each axis. Its precise block arrangement differs from a schematic that draws one shared feed-forward box after both axes. Read the local class when tracing code, and reserve official architecture claims for the pinned source.

Trace a query feature through both axes¶

Suppose a query row has two feature tokens and one target token. During feature attention, the unknown-target representation can read both feature tokens in its own row. During sample attention, its target-position token can read the target-position representations of labeled context rows. After another feature step, information that traveled through different feature positions can interact again. This alternating route builds relationships that a single isolated scalar encoder cannot express.

The context/query mask applies on the sample axis, not indiscriminately on both axes. Context rows may read context rows; queries may read context, but query labels are absent and query rows must not become context keys in the reduced inductive path. A transpose bug can accidentally apply the row mask to features while still producing a tensor of plausible size. The lab tests query isolation and permutation behavior, and exposes the reshapes between [B*N,F,D] and [B*F,N,D].

Follow feature evidence into the prediction location¶

At the start, a query's target token is unknown, but its feature tokens contain the query values. Feature attention lets the target token read those features within the row. Context rows simultaneously mix their own feature and observed-target tokens.

Sample attention then lets each query token position read the corresponding context-token positions. The query target token can read context target states that already incorporate their rows' features. Query feature tokens can read context feature states. Repeating the axes allows these kinds of evidence to be exchanged again.

The mask prevents one query row from becoming a sender to another through sample attention. Context rows also cannot read queries. With fixed preprocessing and deterministic blocks, changing an unrelated query should therefore leave the existing query's output unchanged in this reduced path.

This does not mean that query features are ignored. Each query retains its own residual state and mixes its own features within the row. Isolation means independence from other query rows under the declared interface, not independence from the query's own input.

To test the boundary, compare an existing query alone, beside another query and beside a modified version of that other query. Keep context features, context labels, checkpoint state and preprocessing fixed. Then separately perturb one context label to confirm that a legal information route can affect the prediction. A model that ignores everything could pass isolation while failing to learn.

A legal receptive field is not a guarantee of useful inference¶

The receptive field of a token is the set of inputs that can influence it through the computation graph. After feature attention, a query target token can depend on its own row's features. After context-only sample attention, it can also depend on context target states. Repeated alternating stages expand how those pieces of information can interact.

This establishes possibility, not successful learning. Attention weights might concentrate on irrelevant records, projections might discard useful coordinates, or the pretrained prior might favor an unsuitable relationship. A diagram showing a legal path cannot establish that the trained model uses it effectively.

Use two kinds of checks. Structural checks verify that forbidden inputs cannot influence the output under the declared implementation. Sensitivity checks perturb legal inputs and inspect the response. Then predictive evaluation determines whether the learned responses improve held-out targets. These checks answer progressively stronger questions.

For a debugging fixture, assign distinct values to every row/feature token and temporarily replace an attention block with a known averaging operator. You can then calculate exactly which inputs should appear in each output. After the axis routing is verified, restore the learned blocks. This separates a reshape bug from an unintuitive but correctly routed learned transformation.

Why caching and attention shape matter¶

Let C be context rows, Q query rows, N=C+Q and F the number of feature/target tokens. Ignoring constants, the reduced layer forms about N*F² feature-attention scores and F*N*C sample-attention scores per head. These are score-element counts, not measured peak memory. Fused attention, chunking, cached context states, hidden projections, feed-forward activations, layer count and precision all change actual resource use.

Because context states do not depend on new query rows, an implementation can cache reusable context computation. This can make repeated queries much cheaper than the first prediction. Measure cold model loading, context preparation and warm inference separately before translating a paper's timing into a deployment budget. A small query batch can reduce peak memory but add repeated work when caching is absent.

Count score elements before guessing memory¶

Ignoring batch and heads, feature attention forms roughly N·G² score elements. Context-only sample attention forms roughly G·N·C. If an implementation materializes full square row scores before masking, its allocation can instead involve G·N². Distinguish the mathematical allowed graph from the actual allocated implementation.

For N=100, C=80 and G=11, the simplified feature count is 12,100 and the context-only sample count is 88,000 per head. Doubling G approximately quadruples the first term and doubles the second. Doubling both N and C doubles the feature term and quadruples the sample term.

These counts are not peak GPU memory. Projections, activations, residuals, precision, attention kernels, caching and layer count also matter. Training retains different intermediates from inference. Use the formulas to predict which knob should matter, then measure the actual system.

Caching can reuse context-side work when the context and model remain fixed across queries. It trades preparation and storage for cheaper repeated prediction. Changing context labels, feature order or model weights can invalidate the cached state. A cache benchmark should state whether construction is included in the timer.
