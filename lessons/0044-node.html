NODE (differentiable oblivious trees)

Lesson 044 · Phase 2 · Q1 · primary reading: Popov, Morozov & Babenko 2019, Neural Oblivious Decision Ensembles for Deep Learning on Tabular Data

Last lesson, TabNet tried to give a neural net a tree's instinct with sparse attention over features, and did not clear the baseline-first bar. NODE, published the same year, attacks the same problem from the opposite end: instead of making a neural net act tree-like, it takes an actual ensemble of decision trees and makes it differentiable, so it can be trained end-to-end by gradient descent and stacked into deep, hierarchical layers like any other neural network.

This is the most direct architectural rhyme with a model you already tuned. NODE's trees are oblivious — the same split feature and threshold at every node of a level — which is exactly CatBoost's symmetric tree from L016. So NODE and CatBoost are the same tree shape; the only difference is how the splits are chosen: CatBoost grows them greedily, NODE learns them by backprop. That makes the comparison unusually clean, and it is the comparison this lesson is built around.

Its single skill: describe an oblivious differentiable decision tree — the entmax feature choice, the entmoid soft split, and the outer-product leaf routing — build it from scratch, and say when making a tree differentiable actually buys you anything over a GBDT that is already cheap and strong.

One sentence. Making an oblivious tree ensemble differentiable is elegant and it trains — but on four small real tables our from-scratch NODE lands last of four models (mean rank 3.50, behind CatBoost 2.50, MLP 2.00, ResNet 2.00) while costing ~70× more compute than the CatBoost it is imitating, so the honest verdict is the differentiability is the point, not the accuracy: it matters when you need the tree to compose with other learned modules, not when you just want the best number on one table.

Warm up — recall before you read

Where NODE comes from: the oblivious tree

A standard decision tree chooses a different feature and threshold at every internal node. An oblivious decision tree is deliberately more rigid: at each level of the tree it uses one feature and one threshold, shared by every node on that level. You met this in L016 as CatBoost's symmetric tree — a weaker individual learner that CatBoost leans on precisely because it regularises, and because it turns the tree into something with a very regular structure.

Oblivious (symmetric) decision tree. A tree of depth d in which level i tests the same (feature, threshold) pair for all its nodes. A row's path is then fully described by d yes/no answers, so the tree has exactly 2^d leaves and is completely specified by d features, d thresholds, and 2^d leaf values. That regularity is the hinge of this whole lesson: it is what makes the tree cheap to evaluate (it is a lookup into a 2^d table) and what makes it possible to write down as a smooth, differentiable function.

Why does anyone want a tree to be differentiable? Because a GBDT is a dead end for representation learning. Its splits are chosen by a greedy, discrete search — you cannot take a gradient of "which feature to split on" — so a GBDT cannot be a layer inside a larger model, cannot learn embeddings jointly with its splits, and cannot be stacked into a hierarchy that composes features. NODE asks: what if we keep the tree's inductive bias but replace every discrete choice with a differentiable one, so the whole ensemble is just another neural network?

The mechanism, piece by piece

Three discrete operations have to be softened. We define each one fully, then the visualization lets you drive the whole tree.

1. entmax — the differentiable feature choice

A tree level "picks a feature." NODE replaces that hard pick with a weighted average over all features, f̂ᵢ(x) = ⟨x, choiceᵢ⟩, where choiceᵢ is a learned distribution over the input columns. For this to behave like a real choice, the distribution must be able to put exactly zero on most features — otherwise every column leaks into every split and the tree bias is gone. That is the same requirement TabNet had (L043), and NODE solves it with the same family of functions, one notch softer.

α-entmax, and why α = 1.5. entmax_α is a whole family of simplex maps controlled by a knob α: it returns the distribution that maximises ⟨p, z⟩ + H_α(p), where H_α is the Tsallis entropy of order α. The knob interpolates between the two maps you already know: α → 1 : softmax (dense, no zeros) α = 1.5 : entmax15 (sparse, the middle ground) α = 2 : sparsemax (sparsest, L043) All three have the same closed shape pᵢ = [ (α−1)zᵢ − τ ]₊^{1/(α−1)} for a single threshold τ chosen so the result sums to 1. At α = 1.5 the exponent is 2, so survivors grow quadratically above the threshold — sparser than softmax (there are real zeros) but gentler than sparsemax (fewer of them, and a smoother gradient). Popov et al. found this middle setting trained best for feature choice, and it is the paper's default.

Concretely, on the logits z = [2.0, 1.5, 0.5, 0.0, −1.0] the three maps place their weight very differently:

2. entmoid — the differentiable split

Having chosen a feature value f̂ᵢ(x), a tree compares it to a threshold: go left or right. That hard comparison is the second thing to soften. NODE replaces 1[f̂ᵢ > bᵢ] with a smooth, temperature-controlled probability of going right:

cᵢ(x) = entmoid( (f̂ᵢ(x) − bᵢ) / τᵢ ) ∈ [0, 1]
entmoid — the two-class entmax. Just as the sigmoid is the two-class softmax, the entmoid is the two-class entmax15: entmoid(x) is exactly entmax15([x, 0]) read off the first coordinate. Because it is entmax, once the gap |x| is large enough it saturates to an exact 0 or 1 — a genuinely committed left/right decision — but it reaches that decision smoothly, so a gradient flows. The per-level temperature τᵢ is the softness knob: small τ makes the split nearly hard (a real tree), large τ spreads the row across both sides.

3. Outer-product routing — how a row reaches 2^d leaves at once

A hard oblivious tree sends a row down one path to one leaf. A soft tree sends a fraction of the row to every leaf. Because the tree is oblivious, the weight of a leaf is just the product, over the d levels, of the per-level choice that leads there:

leaf ℓ has bits (r₁,…,r_d); wₗ(x) = ∏ᵢ [ cᵢ if rᵢ = right else (1 − cᵢ) ]

Stacking [cᵢ, 1−cᵢ] for each level and taking the outer product gives all 2^d leaf weights at once, and they automatically sum to 1 — the row is a probability distribution over leaves. The tree's output is then just the weighted average of the leaf responses R:

ĥ(x) = Σ_ℓ wₗ(x) · R_ℓ ( = a smooth lookup into the 2^d response table )

Every parameter here — the feature-choice logits, the thresholds bᵢ, the temperatures τᵢ, the responses R — sits inside differentiable operations, so the entire tree trains by backprop. Drive it below.

A depth-3 oblivious tree (2³ = 8 leaves) routing one row. The feature at each level is fixed here for legibility; in a trained NODE it is itself chosen by an entmax over all columns. Every number is computed live — the entmoid soft splits and the outer-product leaf weights (which always sum to 1). Drag τ to 0.1 and the 8 soft leaves collapse onto the single argmax leaf (an ordinary hard tree, which the toggle reproduces); push it to 3 and they spread toward uniform.

NODE the network: many trees, stacked DenseNet-style

One differentiable tree is weak. A NODE layer is an ensemble of many such trees run in parallel (the paper uses hundreds to a couple thousand), their outputs concatenated. NODE then stacks several layers DenseNet-style (Huang et al. 2017): each layer sees the original input plus every earlier layer's tree outputs, so later trees can split on the decisions of earlier ones — the "multi-layer hierarchical representation" the abstract advertises. The final prediction averages the responses of all trees across all layers. This stacking is the thing a GBDT structurally cannot do, and it is the only real reason to pay for differentiability.

The clean comparison: NODE vs CatBoost

NODE and CatBoost are the same tree shape — ensembles of oblivious/symmetric trees — differing only in how the splits are chosen (greedy vs gradient). So a head-to-head isolates one question: does learning the splits by backprop beat choosing them greedily? Predict before you look.

Read this the disciplined way (twice over). Two claims must stay separate, exactly as in L043. Statistically, p = 0.308 on four datasets means we cannot distinguish these four models on this sample — you may not say NODE is "significantly worse" (failing to reject is not evidence of equality, L023). Evidentially, the baseline-first rule puts the burden of proof on the new, expensive model, and ranking last behind the very CatBoost it generalises means the burden was not met here. So the honest verdict on these four tables is the same shape as TabNet's: interesting mechanism, unproven advantage.
And be fair to the paper — this is a down-scaled experiment (#20). NODE's published claim is that it beats GBDTs on most of 40+ datasets, by a small margin, at scale — with up to ~2000 trees per layer, multiple layers, and a large tuning budget. Our four small tables at 64–128 trees and a 4-trial budget are a demonstration of the method, not a reproduction of that benchmark, and small tables are exactly where simple baselines and cheap GBDTs are hardest to beat. We do not claim to have reproduced "NODE beats GBDT" — on this scale it does the opposite. What does reproduce robustly is (a) the mechanism (validated to machine precision, below) and (b) the cost.

Differentiability is not free, and here it bought nothing on the metric.

So when does differentiability matter?

Not for squeezing the last AUC out of one table — CatBoost already does that, cheaply. The honest answer is that NODE's differentiability is valuable exactly when the tree must stop being the whole model and start being a component of a larger differentiable system:

  • Joint representation learning. Because every split has a gradient, a NODE layer can be trained together with learned embeddings, an encoder, or another network — the splits and the features they split on co-adapt. A GBDT must take its input features as fixed.
  • Depth and composition. The DenseNet stacking lets later trees split on earlier trees' decisions, building a hierarchy of features. A boosted ensemble is a flat sum of trees; it cannot compose in this way.
  • Multi-modal and end-to-end pipelines. When tabular columns arrive alongside text or image features, a differentiable tree can be the tabular head of a single model trained by one optimiser — no two-stage "featurise, then boost."

This is the thread to hold onto, because it is the argument for the whole rest of the curriculum. On a single flat table the differentiable tree loses to the greedy one. The moment the data stops being a single flat table — the moment the useful signal lives in related rows that must be encoded and learned jointly — the ability to train the whole thing end-to-end stops being a luxury and becomes the only option. NODE is the first clean demonstration of both halves of that trade.

Thesis bridge

What today buys the thesis. Two things. Methodologically, this is the second consecutive famous architecture to fail the baseline-first bar on flat tables — reinforcing the habit you will need when the model on trial is a relational one: run the cheap strong baseline first, and be willing to write "did not clear the bar, and cost 70× more." Architecturally, NODE isolates the real dividing line in this field. On a single table, end-to-end differentiability is a liability you pay for and rarely recoup. Its value appears only when the tree must compose — learn jointly with encoders, stack into a hierarchy, sit inside a multi-part model. That is precisely the situation relational deep learning is in: the signal spans joined tables, the row encoders must be learned, and the whole pipeline has to train together. NODE is the toy proof that differentiability earns its keep exactly when a GBDT's greedy splits can no longer see the structure that matters.
