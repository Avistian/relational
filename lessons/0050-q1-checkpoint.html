Recall before reading

1. Specify the decision before fitting anything

You have learned several ways to turn a row into a prediction: tree ensembles, ordinary neural layers, attention over features, attention across rows, and explicit products. The research question now changes from “how does this block work?” to “what evidence would justify choosing it?” For our relational-learning mission, this is a prerequisite: an apparent gain from relationships is not persuasive if the single-table alternative was weak or evaluated differently.

The experimental unit is the object that supplies a distinct comparison. Here we compare model families within each dataset, so the dataset is the unit for the across-task rank summary. A random seed repeats training on that dataset; it does not create another dataset.

Our question is concrete: under the declared numeric preprocessing and two-candidate validation search, how do a from-scratch FT-Transformer and XGBoost compare on diabetes, blood transfusion and phoneme? An MLP supplies a simple neural baseline and a third arm for the Friedman procedure. These three real OpenML tasks are affordable substitutes, not the paper’s benchmark. Their selection favors small numeric binary problems. Neither categorical tables nor relational prediction is tested.

Primary reading: Gorishniy et al., §4.5, then Appendix D.2. The paper compares deep models in Table 2; its neural-versus-GBDT comparison in Table 4 uses ensembles. Here each seed produces one selected fitted model. Mean performance across seeds is not ensemble performance: an ensemble averages predictions first, then evaluates that combined predictor.

Freeze this contract: datasets and rows; target and positive class; split IDs; fit scope; metric; candidate lists; training caps; selection rule; seeds; uncertainty unit; and the language allowed in the conclusion. Changing these after reading test results creates a new exploratory experiment.

The object being compared is a training procedure¶

“Transformer versus tree” sounds like a comparison between two functions. In an experiment it is a comparison between two procedures that produce functions. A procedure includes preprocessing, candidate configurations, initialization, training, checkpoint selection and prediction. Changing any of these can change the result even when the model's name stays the same.

Let D be the available training data and A the complete procedure. The fitted predictor is f=A(D). Our question is about the loss of that predictor on a specified population of future examples. This target of estimation is the estimand. For a random split, the intended population is usually exchangeable with the sampled table. For a temporal split, it is a later population. These are different estimands; an average of their scores has no automatic deployment meaning.

Write a decision sentence before opening the results: “On these datasets, under this split rule and this candidate budget, which procedure gives higher held-out AUROC?” That sentence is deliberately narrower than “Which architecture is best?” It tells a reader what your evidence could establish and what additional experiments would be needed for transfer.

Consider two apparently fair budgets. Giving each family ten configurations equalizes the number of validation comparisons. Giving each family one hour equalizes a resource constraint. They can produce different winners because configurations have different runtimes. Neither budget is universally correct. Choose the one that corresponds to the decision, record both realized time and candidate count, and explain the consequence.

The lab makes this concrete by saving the selected configuration and row identities with the scores. A naked AUROC value cannot tell you whether one method used extra validation feedback, fitted a transform on test features, or received a different target definition. The experimental artifact must identify the procedure that generated the number.

Distinguish replication from a new trial¶

Repeating the same split with a different neural initialization measures one source of algorithmic variation. Drawing another split changes which observations are available for learning. Sampling another dataset changes the task. These repetitions answer different questions. Preserve their identities in the results table instead of flattening them into an undifferentiated list of runs.

If a method wins on three seeds of one dataset, it has shown repeatability on that dataset. It has not acquired three independent pieces of evidence about new datasets. This distinction becomes essential when you summarize the checkpoint across tasks.

2. “Same protocol” is an information boundary

A training set estimates preprocessing parameters and model weights. A validation set selects candidates and stopping points. A test set measures the already selected procedure. Our split is stratified 60/20/20, using split seed 50 for both partition calls. Stratification approximately preserves class proportions. Exact row IDs are saved, so another reader need not infer the partition from its seed alone.

For numeric feature j, fit its median on training rows and use it to replace missing values. Then calculate the training mean μⱼ and population standard deviation σⱼ. Transform every partition using zⱼ=(xⱼ−μⱼ)/σⱼ; replace a zero σⱼ with one. An entirely missing training feature triggers an error requiring an explicit policy. The arrays have shape [B,C]: B rows and C numeric columns. The test set receives the transformation; it cannot estimate it.

Worked example: training values [0,2] have mean 1. Centering 2 gives 1. Add a held-out observation 100: fitting the mean on all three gives 34, so the same training value becomes −32. Nothing about the training observations changed; the held-out feature value changed their representation. No labels were necessary for this contamination. Its existence does not imply that every metric must improve.

Predict: move the held-out value to 200. Which mean is allowed to move?

The L046 verification harness used full-frame preprocessing before splitting. L050 does not reuse that data preparation. It also uses a different model implementation and different tasks; its scores must not be interpreted as a controlled before/after estimate of that earlier issue.

All three arms receive the same standardized numeric arrays. This keeps this checkpoint’s information and representation fixed. It is a disclosed choice, not a universal definition of fairness: a production comparison can legitimately allow each family its own training-only preprocessing. The paper uses neural quantile preprocessing and untransformed GBDT inputs (Appendix B.2).

Follow one validation row through the pipeline¶

Suppose the training values of a numeric feature are 0 and 2. Their mean is 1. A validation value of 100 must be transformed using that training mean. If you first concatenate all three rows, the mean becomes 34, and information from the validation distribution has entered the fitted transform. No label was used, but the procedure has still changed from the declared inductive pipeline.

The rule is fit on the training partition, transform every partition with the fitted state. “Fit” includes estimating quantiles, imputing missing values, selecting features and building category vocabularies. It is not limited to gradient descent. A numerical transformer can have many learned preprocessing parameters before the first neural weight is updated.

For categorical columns, an unseen validation category must follow a policy chosen in advance: an unknown-category index, a hashing scheme, or another explicit treatment. Rebuilding the vocabulary on the full table makes the implementation convenient but obscures the prediction contract. Keep the vocabulary in the artifact so a future row is encoded the same way.

Fairness does not require forcing identical representations onto every family. Trees and transformers can have different sensible preprocessing. It requires comparable information access and an honest description of the recipes. If FT-T uses a training-fitted quantile transform while the tree uses raw numeric values, explain that these are family-specific procedures; do not pretend the only difference is an attention layer.

Why the target transform belongs in the audit¶

For regression, standardizing targets changes the units of the optimization loss. A squared error of 0.2 in standardized space is not an RMSE of 0.2 in original units. Predictions must be inverted using the training target mean and scale before an original-unit metric is computed. The inverse transform is part of inference, not a cosmetic plot adjustment.

An effective check follows one row manually: raw value → fitted transform → model input → output → inverse target transform → metric contribution. If you cannot explain where each stored parameter came from, the protocol is not yet auditable.

3. Model architecture — audit the FT-T variant

This is a review of FT-Transformer, with a more faithful numeric path than L046’s GELU teaching variant. A scalar xⱼ becomes a learned vector xⱼwⱼ+bⱼ, where wⱼ and bⱼ each have d coordinates. Stack C vectors and prepend the learned classification token, CLS, to obtain [B,C+1,d]. CLS begins independent of the input and collects row information through attention.

Within a head, learned query, key and value maps produce Q, K and V. The weight matrix is softmax(QKᵀ/√dₕ), where dₕ=d/heads. Softmax exponentiates and normalizes each receiver’s scores across senders. Multiplying by V forms weighted sums. Concatenate heads, project back to width d, and add the incoming tokens: this is a residual connection. Attention weight dropout is 0.1 during training; evaluation disables it.

Next comes a featurewise feed-forward update. Layer normalization rescales coordinates within a token and learns a scale and offset. A linear map produces 2h coordinates, split into a and b; ReGLU returns a⊙max(b,0), with h=floor(4d/3). The symbol ⊙ denotes coordinatewise multiplication. For a=[2,−1] and b=[3,−4], the result is [6,0]. Dropout 0.1 and a second linear map return to d coordinates; add the residual. Skip the first attention normalization, but retain later attention normalizations and every FFN normalization. Paper Appendix E.

After the blocks, select CLS: [B,d]. LayerNorm → ReLU → linear d→1 gives one logit, an unrestricted score per row. Sigmoid converts it into a probability; binary cross-entropy trains directly from logits. XGBoost instead adds decision trees to improve a loss; its tree count and depth play different roles from neural epochs and width. The MLP is two linear/ReLU/dropout hidden layers of width 64 followed by one logit.

The paper fixes eight heads; this learning variant uses four. Its two blocks and width 32 also differ from the paper’s tuned configurations. The copied-weight check compares our complete numeric path to rtdl_revisiting_models 0.0.2 in double precision, including input gradients. We retain all queries in the last layer; the reference computes only the final CLS query, which yields the same readout in the checked evaluation path. This is model-function evidence, not full training parity. It does not validate categorical embeddings, stochastic dropout alignment, the original training environment or benchmark results. Reference implementation.

Follow a value through a residual block¶

The architecture figure's scalar 2 becomes the two-coordinate token (1.1,−1.7) under the illustrative weights (0.5,−1) and bias (0.1,0.3). Different columns have different learned vectors: the number 2 in “age” need not receive the same representation as 2 in “balance.” Token identity is learned through these column-specific parameters; there is no temporal ordering of tokens implied by column order.

For a separate projected-attention fixture, hold a receiver's two sender scores at (0, ln 3) and value coordinates at (2,6). Softmax produces (1/4,3/4), so this output coordinate is 1/4×2 + 3/4×6 = 5. If that coordinate enters the residual at 1, the residual result is 6, assuming identity output projection for this illustration. Attention supplies an update; it does not replace the incoming representation. Actual learned Q/K/V and output projections couple coordinates, and actual attention includes every feature token plus CLS. The fixture isolates the weighted sum, not an entire trained model.

The FFN then applies another update separately to each token. With width d=32, hidden width h=floor(4d/3)=42: the first linear map emits 84 numbers, ReGLU reduces them to 42, and the second map returns 32. The split is essential: a 32→42→32 ReLU network is not the same parameterization. The FFN does not directly communicate between tokens; the preceding attention provides that communication. Its parameters are shared across token positions within a block, while different blocks own separate parameters.

Why can the reference compute only the last CLS query? At that final attention step, each output receiver reads keys and values from the incoming tokens. Computing another receiver's output cannot alter the CLS output in the same step. The remaining normalization, FFN and head operate tokenwise, and only CLS is read. Earlier blocks must still update feature tokens, because later attention needs their updated keys and values. Dropping all non-CLS queries in every block would therefore change the model.

Know what the parity check leaves open¶

Copied-weight evaluation asks whether two implementations calculate the same function at the tested inputs. It deliberately removes initialization differences and turns off dropout. Training also depends on initialization, minibatch order, dropout masks, optimizer state, precision and checkpoint selection. Retaining all final-layer queries changes the shape of dropout draws during training; exact seeded training trajectories need not match the reference even though the checked evaluation function agrees.

In evaluation, the first row's output must remain fixed when other batch rows change. The lab now verifies this directly. This is a stronger test of the pictured information boundary than merely observing an output of shape [B]. It does not prove all possible inputs or variants correct: the source check covers one numeric configuration and the training recipe remains separately audited.

4. Let validation select; let test evaluate

A hyperparameter is a configuration chosen outside weight optimization. Each model family receives exactly two declared candidates per training seed. FT-T and MLP try learning rates 0.001 and 0.0003. XGBoost tries maximum depths 3 and 6 at learning rate 0.05. This is a small fixed search, not comprehensive tuning. Reusing seeds 0,1,2 pairs each family’s run by index; it does not make their random operations equivalent.

Neural candidates train at most 35 epochs, in batches up to 256 rows, with AdamW. An epoch visits the training rows once. Restore the checkpoint with highest validation AUROC; stop after eight epochs without improvement. XGBoost trains at most 160 trees and stops after 20 rounds without validation improvement; its sklearn prediction interface uses the selected best iteration. Exact validation ties choose the earlier checkpoint or first candidate. See XGBoost early-stopping documentation.

AUROC measures how well scores rank positives above negatives across thresholds. A random ordering has expected AUROC 0.5; 1 means perfect ranking on the evaluated rows. It does not measure calibration or fix a deployment threshold. Selection uses validation AUROC for every arm. Only after choosing the candidate do we produce that arm’s test probabilities. No rejected candidate gets a test score in the actual experiment.

For synthetic candidates A and B, validation AUROC is [0.80,0.86] while test AUROC is [0.91,0.82]. Candidate B must win selection. Reading the test column to choose A turns it into another validation set. Predict: why does the reported number rise when the procedure becomes less trustworthy?

Equal trials do not mean equal compute. Two transformer fits can cost more than two tree fits, and two handpicked points cover different fractions of each family’s useful search space. Record training time and distinguish “best under this candidate count” from “best within 15 minutes.” Comparing those policies would be a new experiment with its own frozen rules. The paper’s Appendix D.2 studies time budgets explicitly.

Trace the selected candidate all the way to test¶

Keep the same two-candidate AUROC example as the widget: validation scores (0.80, 0.86) select B. The synthetic audit exposes test scores (0.91, 0.82), so the reportable selected score is 0.82. Reporting 0.91 uses test information to change the procedure. In the actual lab, rejected candidates never receive test predictions. Higher AUROC is better throughout this checkpoint; for a loss metric the ordering would be reversed.

Early stopping is the same operation at a finer scale. Each epoch is a candidate checkpoint. Validation chooses one; test evaluates that choice. A model trained for 100 epochs can therefore make many adaptive uses of validation even if only one hyperparameter configuration was launched.

Ties need a declared policy too. “First maximum” and “latest maximum” are reproducible rules, but they can choose different checkpoints. Floating-point closeness is not automatically equality: adding an undocumented tolerance changes the selection procedure. Read the implemented rule and record it rather than silently substituting your preferred one.

The selection function in the lab should reject missing or nonfinite candidate scores. Treating a failed candidate as AUROC 1 would reward failure. Treating it as absent without recording that fact would hide an incomplete search. Save failures separately, then apply the selection rule only according to the stated policy.

After inspection, you may reasonably want to change the search. That is a new development round. The original test has supplied feedback and cannot simultaneously remain an untouched estimate for the revised procedure. Preserve the first result and obtain new independent evaluation evidence for the revision.

5. Pair the differences; count the datasets

For one task, let aₛ and bₛ be FT-T and XGBoost test AUROC for seed s. Calculate δₛ=aₛ−bₛ before summarizing. The paired mean δ̄ is the average of these differences. Its sample standard deviation is sδ=√[Σ(δₛ−δ̄)²/(S−1)], where S=3 is the number of training seeds. Dividing by S−1 gives sample SD, not the population SD used earlier to scale inputs.

A conventional 95% t interval for the conditional seed mean is δ̄ ± t₀.₉₇₅,S−1 sδ/√S. For three seeds the multiplier is about 4.303, which warns how little precision three runs provide. The t model assumes suitably independent, approximately normal seed differences. With S=3 that assumption cannot be assessed well. These intervals describe initialization, minibatch and stochastic fitting variability on one fixed split and selected search procedure. They do not include alternative test samples, new hospitals, future periods or new datasets.

Worked example: FT-T scores [0.80,0.82,0.84] and tree scores [0.79,0.81,0.83] give paired differences [0.01,0.01,0.01]. Each model’s scores vary, but the paired difference does not. Overlapping separate error bars would miss this structure. A zero-width seed interval still says nothing about uncertainty over a new test population.

Next average each model’s seed scores within each task. Rank those means from best (rank 1) to worst, sharing ranks for exact ties. Average those ranks across the three tasks. A rank treats a 0.001 margin and a 0.10 margin alike, so retain actual differences beside it. Averaging ranks avoids making a high-score or large-row-count task silently dominate, but it also discards effect size.

The Friedman test checks whether three or more models’ ranks differ systematically across datasets. The Nemenyi critical difference is a threshold for differences between average ranks, CD=qα√[k(k+1)/(6N)], with k models and N datasets. Here k=N=3 and qα≈2.344, giving CD≈1.914. This small-N asymptotic procedure is a teaching diagnostic, not strong confirmatory evidence. Do not count nine seed fits as nine datasets. Demšar (2006).

For the primary two-family comparison, also report the exact two-sided sign test over non-tied dataset means. Even a 3–0 sweep yields p=2×(1/2)³=0.25 under equally likely independent win directions. That makes the sample-size limitation tangible. The convenience sample also limits the population being generalized to. Neither test’s failure to reject proves equality. Equivalence would require a predeclared practically negligible margin and an appropriate design with sufficient precision.

Pair first, average second¶

For a synthetic three-task example, suppose transformer AUROCs are (0.81, 0.85, 0.90) and tree AUROCs are (0.80, 0.90, 0.85). Transformer minus tree gives +0.01, −0.05 and +0.05: positive means the transformer is better. Pairing keeps both models exposed to the same task. It does not guarantee variance reduction when seed numbers refer to unrelated random operations in different software libraries.

Across datasets, metric scales or task difficulties may differ; even AUROC differences have different practical implications across applications. Ranking within each dataset makes the comparison ordinal: first place is 1, second is 2, and ties receive average ranks. Here the transformer's ranks are 1, 2, 1, with mean 4/3. This describes frequency of relative position, while discarding whether a win was large or tiny. Keep per-dataset effect sizes beside ranks so the summary cannot hide that distinction.

A paired dataset bootstrap draws dataset indices with replacement and carries all model scores for each selected dataset together. If it selects datasets [2,2,0], both models use those same indices. Resampling each model independently destroys the pairing and estimates a different uncertainty distribution.

With only a few datasets, a narrow seed interval can coexist with substantial uncertainty about transfer. A Friedman test or critical-difference diagram does not manufacture more task diversity. Failure to reject an equal-performance null is also not proof of practical equivalence. Equivalence would require a meaningful tolerance and a design capable of resolving it.

For the exit report, give three separate statements: the observed difference on each task, how stable it was under the repetitions actually run, and how far you are willing to generalize. The last statement should follow from dataset coverage, not from the number of decimal places in the table.

Three levels of aggregation answer three different questions¶

First, average seed scores within a task to describe the selected training procedure over the random seeds you ran. Second, rank those means within each task, then average ranks across tasks. Third, to deploy an ensemble, average the selected models' probabilities for each test row, then calculate the metric once. That third operation changes the predictor. It cannot be recovered from a table of scores alone.

Use a four-row synthetic example with labels (0,0,1,1). Model A predicts (0.9,0.8,0.7,0.1): neither positive outranks either negative, so AUROC=0. Model B predicts (0.1,0.2,0.8,0.9): all four positive-negative pairs are correct, so AUROC=1. The mean of these two scores is 0.5. Averaging their probabilities produces (0.5,0.5,0.75,0.5). One positive beats both negatives; the other ties both. Counting each tie as half a win gives (2+0.5+0.5)/4=0.75. Ensembling need not improve every dataset; this fixture demonstrates why the operations differ.

The lab adds this operation using your already selected models. It is labeled a post-hoc diagnostic because the historical test results were already available when this audit added the exercise. No ensemble weights or members are chosen using test outcomes. There is only one three-model ensemble per family and task, so you cannot report its uncertainty by reusing the SD of the three single-model scores. A future confirmatory ensemble comparison requires a frozen aggregation rule and fresh evaluation evidence.

Interpret the baseline before explaining the winner¶

On blood transfusion, both neural procedures are near 0.81 while this XGBoost procedure is near 0.78. That pattern does not single out attention: the MLP is also competitive. On phoneme, FT-T improves over this MLP while the tree remains ahead. Both observations are compatible with several explanations, including representation and tuning sensitivity. A causal claim about attention needs a controlled architectural intervention with a comparable training and selection budget.

The quarter's mechanisms imply different information access. An MLP mixes a row's coordinates through fixed learned matrices. FT-T lets that row's tokens compute input-dependent mixing weights. SAINT's intersample branch additionally reads other rows; DCNv2 makes products explicit. None of these local single-table comparisons establishes the benefit of joining historical entity records. For the relational mission, first freeze a strong flat-table procedure, then evaluate whether added relationships improve the same target under a point-in-time boundary.

Choose a useful follow-up¶

Inspect the saved validation histories and selected candidate indices before proposing a larger search. If the best checkpoint frequently hits the training cap, the cap may be binding; if both candidates plateau early, simply adding epochs may do little. Neither observation identifies the best future hyperparameters. Declare a follow-up using validation evidence, preserve the original test result, and obtain a fresh evaluation for any revised procedure.
