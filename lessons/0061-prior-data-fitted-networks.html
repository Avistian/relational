Learn an inference procedure¶

A conventional classifier learns one mapping from features to labels on one training dataset. A prior-data fitted network (PFN) learns across many sampled supervised-learning tasks. Its input includes a new task's labeled context and an unlabeled query. Its output approximates the label distribution implied by the prior and that context. Read Müller et al., Sections 2–3.

Separate three objects: the prior over tasks, the distribution of examples within a task, and the neural weights shared across tasks. During pretraining, gradients update those weights. At ordinary in-context inference, the weights are fixed; context examples alter the computation and therefore the answer. Calling the latter “no training” is shorthand for no downstream parameter optimization, not zero learning cost or no use of labels.

The training examples are whole learning problems¶

In ordinary supervised learning, a training example is a feature vector paired with a target. In prior-data fitting, one training episode contains a context dataset and one or more query examples. The network is trained to predict query targets from the context. Across episodes, the underlying task changes.

For the coin example, each task has a latent success probability θ. Sample θ once, generate all context labels from that θ and generate the query label from the same θ. The context provides evidence about the task. Sampling a fresh unrelated θ for the query would remove the relationship the learner is supposed to exploit.

The prior describes which θ values are plausible before observing the context. The likelihood describes how labels arise given θ. The posterior combines both after seeing data. A PFN aims to learn the predictive consequence of that update over the task distribution used in pretraining.

The neural parameters change across synthetic training episodes. At deployment in the basic PFN setting, those parameters stay fixed while the context changes. This is why a new dataset can alter predictions without a new gradient-descent run. The model has learned an inference procedure rather than storing one fitted coin probability.

The local count-based network is a controlled teaching model. It exposes the objective with an analytic answer available. It is not the full Transformer architecture from the PFN paper and should not inherit claims about general tabular inference.

Derive a posterior you can check exactly¶

Let a task be an unknown coin probability theta. Draw theta from a Beta distribution with positive shape parameters alpha and beta. Conditional on theta, each observed label is a Bernoulli draw: 1 with probability theta, otherwise 0. For a context with s successes and f failures, multiplying the prior density by its likelihood gives exponents alpha+s−1 and beta+f−1. The posterior is therefore Beta(alpha+s, beta+f).

To predict the next label, integrate over this posterior instead of plugging in one fitted theta. The next-success probability is (alpha+s)/(alpha+beta+s+f). For a uniform Beta(1,1) prior and labels [1,0,1], the prediction is 3/5=.6. The empirical success rate is 2/3; the Bayesian answer shrinks it toward the prior mean .5. With no observations, it returns the prior mean. More observations reduce the prior's relative contribution.

The output .5 alone does not distinguish a well-known fair coin from uncertainty between nearly deterministic coins. A posterior predictive probability mixes uncertainty about the task with randomness within it. If you need a posterior distribution over theta, that is a different output contract.

Derive the update from the probability density¶

A Beta(α,β) prior has density proportional to θ^(α−1)(1−θ)^(β−1) on θ between zero and one. A context with s successes and f failures has likelihood proportional to θˢ(1−θ)ᶠ. Multiplying prior and likelihood adds their exponents, giving a posterior proportional to θ^(α+s−1)(1−θ)^(β+f−1).

This is the kernel of Beta(α+s,β+f). The posterior predictive probability of the next success is the posterior mean of θ: (α+s)/(α+β+s+f). We integrate over uncertainty about θ rather than selecting one latent value and pretending it is known.

Under Beta(1,1), three successes and one failure give Beta(4,2), whose predictive mean is 4/6=2/3. The empirical success fraction is 3/4. The difference comes from the prior's regularizing influence, which is strongest with little data.

With empty context, the answer is α/(α+β). This is a useful edge case: a PFN should still produce a prior prediction before receiving task evidence. The analytic function should reject nonpositive prior parameters because they do not define the stated proper Beta distribution.

The update can be written as a weighted average of prior mean and empirical rate when the context is nonempty. The prior contributes weight (α+β)/(α+β+n), and the observed rate contributes n/(α+β+n). As n grows, the data's relative influence increases. This explains shrinkage without interpreting the prior as literally observed extra rows.

Counts are sufficient statistics for this exchangeable Bernoulli model: once s and f are known, label order contains no additional information about θ. That property justifies the local network's two-number input. It would fail for a task where order or time changes the success mechanism.

Uncertainty about the coin differs from randomness of its next flip¶

The posterior describes uncertainty about θ. The posterior predictive describes the next label after integrating over that uncertainty. These are different distributions: θ is continuous, while the next label is binary.

For Beta(4,2), the posterior mean is 2/3 and the variance of θ is ab/[(a+b)²(a+b+1)]=8/(36·7)=2/63≈0.03175. The next Bernoulli label has variance p(1−p)=2/9≈0.22222. A network output of 2/3 is a predictive probability; it is not the variance of θ or a complete explicit posterior density over θ.

The law of total variance separates the next-label variance into expected within-task randomness and posterior uncertainty about the task probability. Here E[θ(1−θ)]=4/21 and Var(θ)=2/63; their sum is 2/9. As context grows, uncertainty about θ can shrink while an intrinsically random coin remains unpredictable on individual flips.

This distinction prevents a common interpretation error. A confident estimate that θ is near 0.5 still predicts highly uncertain individual labels. Conversely, a predictive probability near one can arise from strong context evidence or a strong prior. The single probability does not tell you which source dominated unless you inspect the inference setup.

Why query-label loss learns the Bayesian answer¶

Sample a task, draw context labels and draw an independent query label from the same task. Train a network to predict the query from the context using binary cross-entropy, −y log(q)−(1−y)log(1−q). Conditional on a particular context, let p be the true posterior predictive probability. Expected query loss is −p log(q)−(1−p)log(1−q).

Differentiating with respect to q gives −p/q+(1−p)/(1−q), which vanishes at q=p. Equivalently, expected log loss is the true predictive entropy plus a nonnegative KL divergence between the true prediction and the model's prediction. Finite capacity, optimization and the sampled training distribution determine how closely a neural network reaches that optimum. The theorem does not say an arbitrary trained Transformer has become an exact Bayesian engine for every real table.

The context and query must share the same sampled theta. If you redraw theta for the query, context labels contain no information about it; the best predictor collapses to the prior mean. The lab asks you to construct this broken generator as a negative control.

Cross-entropy makes the conditional probability optimal¶

Fix a context D and let p be the true conditional probability that the query label is one under the task generator. If the learner predicts q, its expected binary cross-entropy is −p ln q−(1−p)ln(1−q). Differentiating with respect to q gives −p/q+(1−p)/(1−q).

Setting that derivative to zero yields q=p. The second derivative is positive for interior probabilities, so this is the minimum. Thus, in the idealized limit of sufficient capacity, optimization and task coverage, minimizing query-label cross-entropy targets the posterior predictive probability induced by the generator.

The training target is still a sampled binary query label, not the analytic posterior mean. Many episodes provide noisy supervision whose expected optimum is the conditional probability. Training directly on analytic probabilities would be a different distillation experiment, even if it sought the same function in this toy problem.

Three limitations separate the ideal argument from a trained network. Finite episodes leave sampling error; a finite architecture may not represent the desired function accurately; optimization may not find the best available approximation. The proper-loss derivation establishes the objective's target, not that any particular run reached it.

A fourth limitation is prior mismatch. Even a perfect posterior predictor for the synthetic generator can be inappropriate for deployment tasks outside that generator. Bayesian optimality is conditional on the assumed task distribution; it is not a universal guarantee.

Model architecture: isolate the PFN objective¶

The local CountPFN uses the exact sufficient statistics [successes, failures], divides them by 32, and passes them through 2→32→32→1 affine layers with GELU nonlinearities. A sigmoid turns the final logit into a next-success probability. A sufficient statistic retains all information about theta that these exchangeable Bernoulli observations provide. Using it removes representation learning from this first experiment.

This is a complete PFN-objective demonstration, not a Transformer or TabPFN implementation. The paper's general architecture embeds examples and learns set-conditioned prediction using attention. Lesson 62 introduces that row-token route; the count encoder here is an intentional decomposition so you can independently verify the learning objective before adding attention and richer priors.

Fit on sampled tasks, evaluate against analysis¶

Each of three author runs takes 1,500 optimizer steps, with 256 independently sampled coin tasks per step and context lengths from 1 through 32. Training targets are sampled query labels, not analytic posterior values. The evaluation grid checks every success count at context lengths 4, 16 and 32, then challenges extrapolation at length 64. The analytic formula appears only in the evaluation path.

Predict whether a small average approximation error inside the training range guarantees accurate length-64 predictions. It does not: the network has learned a function over a sampled range of counts, while the analytic rule holds at every valid length. Test the learned rule against an exact grid¶

For every allowed context length n, enumerate success counts s=0,…,n and compute the analytic target. Feed the corresponding (s,n−s) counts into the trained network. This removes query-label sampling noise from the evaluation of approximation error and reveals systematic regions of failure.

Inspect absolute errors as a function of both count and context length. A single mean can hide poor behavior on empty contexts, unanimous labels or larger n. Check symmetry under swapping successes and failures when the prior is symmetric: the analytic predictions should complement to one. A generic MLP is not forced to satisfy that identity exactly.

The local input normalization divides counts by the declared training scale. A context length beyond the training range can therefore create inputs outside the region seen in optimization. A network that fits the in-range grid well need not extrapolate the rational formula correctly at n=64.

Compare three kinds of success. An implementation check establishes that the analytic update and generator are correct. In-range approximation establishes that the trained network learned the checked portion of the rule. Out-of-range evaluation probes transfer beyond that training support. None should substitute for the others.

For the exit explanation, identify one grid location where the network is least accurate and propose a targeted cause: insufficient episode coverage, representation, optimization or extrapolation. Then design an intervention that distinguishes that cause from the others. The analytic oracle makes this a rare setting where “what should the model predict?” has an exact answer.
