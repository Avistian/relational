DCNv2: make the interaction an operation

Build a cross network. Trace its polynomial terms. Audit what a reproduction actually reproduces.

In SAINT, another row could change a prediction by supplying a key and value. Today we do something different. We keep the whole computation inside one row and change the operation instead. The new operation multiplies a row's original features by learned mixtures of its current representation. Your tangible win is a cross layer you can derive, implement, and distinguish from an ordinary residual layer.

In plain terms. A cross layer is a way to let features multiply each other, on purpose, inside the network. SAINT let rows talk to each other; DCNv2 keeps to a single row but lets that row's own fields combine multiplicatively. By the end you should be able to write the update by hand and say exactly what it computes.

1. Why explicitly multiply features?

In plain terms. A plain linear model gives each feature a fixed effect. But often one feature should change how much another matters — age might matter more for one movie category than for another. Capturing that requires multiplying features together, not just adding them. This section shows why that multiplication is worth building directly into the operation.

Imagine predicting whether a user will click a movie recommendation. A linear score of age and movie category can add an age effect and a category effect. It cannot, without a new feature, make the effect of age depend on category.

Worked example. Start with the score s = a·x₁ + b·x₂. Its response to x₁ is the constant a, whatever x₂ happens to be. Now add a product term to get s = a·x₁ + b·x₂ + c·x₁x₂. The response to x₁ becomes a + c·x₂. The second feature now changes the effect of the first.

What a feature cross is. A feature cross is such an interaction term. A product such as x₁x₂ is degree two. A product such as x₁²x₂ is degree three, because its exponents sum to three. Repeated coordinates count: “degree three” does not require three distinct columns.

What “explicit” means. These products are explicit when multiplication appears directly in the computational rule. An MLP — a stack of learned affine transformations and nonlinear activations — can learn interaction behavior only indirectly. An explicit cross changes which functions are easy for the architecture to represent.

That distinction matters to the mission. Before crediting a relational model for learning useful interactions, compare it with a strong single-row model that can already multiply informative fields. DCNv2 is one candidate for that baseline.

Scope check. Making the cross explicit does not guarantee higher held-out accuracy. DCNv2 also cannot retrieve a missing history or invent a database join; it only recombines fields already present in the row.

What is x₀? A categorical embedding is a learned vector looked up by category ID. Concatenate those vectors and normalized numeric values into one vector x₀ of width d. If two categories have embedding widths 3 and 4 and there are two numeric values, d = 9. The coordinates being crossed are these nine numbers, not nine raw columns. No CLS summary token is added. Category IDs index embeddings; their integer magnitudes are not multiplied as numeric measurements. §3.1.

Derive an interaction from a prediction question¶

Suppose a score uses two features: visits x and average purchase value z. In a linear model, s = a*x + b*z + c, increasing visits by one changes the score by a, regardless of purchase value. That is the additive assumption. Adding w*x*z changes the visit effect to a + w*z: a visit can matter more for a customer whose purchases are valuable. This dependence of one feature's effect on another is the interaction we want the model to represent.

A neural network with nonlinear hidden layers can already approximate interactions. DCNv2 is useful because it gives multiplicative structure a direct parameterized route. The question is about how the representation and optimization encourage useful interactions under a finite budget, rather than whether one model class is mathematically capable of multiplication in principle. An explicit product can also be a poor inductive preference when the relevant relationship is mostly additive or the observed product is dominated by outliers.

The input to the cross network is x₀, a vector that combines normalized numerical coordinates and learned categorical embedding coordinates. A product of two embedding coordinates is not necessarily a human-readable conjunction such as “country is Poland AND plan is premium.” The representation is learned, so the cross network operates on a coordinate system that changes during training. Explain a cross in terms of those coordinates before giving it a business interpretation.

Scaling matters immediately. If one normalized coordinate lies near 1 and another raw coordinate lies near 100,000, their product and the corresponding gradients can have very different magnitudes from the intended initialization regime. Fitting preprocessing on training data controls the numerical problem without making it statistically harmless to use validation or test values. The vocabulary, imputation values, and scaling parameters are all fitted state; they travel with the final model.

Why retain the original vector?¶

The cross stack keeps two vectors with different roles. x₀ is the original embedded row, used as an anchor at every layer. xₗ is the current representation, which already contains earlier interactions. Multiplying a learned mixture of xₗ by x₀ extends those interactions while retaining a consistent connection to the original coordinates. Overwriting x₀ with xₗ changes the recurrence. It might still train, but it would no longer be the operator whose degree and factorization we analyze here. Dense cross definition and architecture.

2. Derive the cross layer from one coordinate

Now open the cross block from the diagram. Its matrix first mixes the current coordinates; multiplication by the saved original input turns that mixture into feature products; the residual retains the previous state. Deriving one output coordinate will show exactly which interaction coefficients DCNv2 can learn, rather than treating “cross layer” as a label.

In plain terms. The cross update does three things in a row: it blends the current features into a new mixture, multiplies that mixture by the original input coordinate by coordinate, and then adds the old state back so nothing is lost. The multiplication is what creates the interaction; the addition is a safety wire that keeps information and gradients flowing.

The symbols. Let xₗ be the current d-dimensional state at layer l, starting at x₀. Let Wₗ be a learned d-by-d matrix and bₗ a learned length-d bias vector. The symbol ⊙ means elementwise multiplication: coordinates in corresponding positions multiply. With those names fixed, DCNv2’s basic update is:

xₗ₊₁ = xₗ + x₀ ⊙ (Wₗxₗ + bₗ)

Read it in three steps. First, form a learned mixture of the current coordinates, a different mixture for each output coordinate. Next, multiply each mixture by the corresponding coordinate of the original input. Finally, add the current state back as a residual. The residual preserves a direct route for information and gradients, as in L042. What is new is that the update now carries an explicit multiplicative structure. §3.2, Eq.1.

Worked example. Take x₀ = xₗ = [2,3], W with rows [1,1] and [0,1], and b = [1,−1]. First the matrix product Wxₗ is [5,3]. Add b to get [6,2]. Multiply coordinate by coordinate with x₀ = [2,3] to get [12,6]. Add the residual xₗ = [2,3] to obtain [14,9]. Now perturb one weight: moving W₁₂ changes only the first output coordinate in this one-layer example, and its change is exactly 2 × ΔW₁₂ × 3.

To see the products the update creates, expand coordinate i in the first layer, using j for the coordinate being mixed:

x₁,ᵢ = x₀,ᵢ + b₀,ᵢx₀,ᵢ + Σⱼ W₀,ᵢⱼx₀,ᵢx₀,ⱼ

The first two terms are linear in x₀. The sum contains quadratic products, including a square when i = j. Note what we did not do: we never allocated a vector of all d² products. The matrix multiplication followed by elementwise multiplication computes their weighted contributions directly. The entry Wᵢⱼ is learned and shared across examples. It is neither a probability nor an attention score normalized over the row’s features.

Two code traps. First, placing b outside the multiplication changes the function. Second, replacing the anchored x₀ with xₗ changes the recurrence after the first layer. A shape check catches neither mistake. For orientation in code: in row-batch notation X has shape [B,d], and the affine operation is XWᵀ + b when W is stored as [out,in], the way PyTorch stores it. B is the batch size; it is not part of the feature-interaction matrix.

What changed from the original DCN?

The original vector cross uses a scalar wₗᵀxₗ, multiplied by all coordinates of x₀, plus an outside bias and the residual. Its multiplicative part corresponds to a matrix with the same row vector repeated: every output coordinate receives the same mixture before multiplication by its own x₀ coordinate. DCNv2 gives each output coordinate its own mixture through Wₗ. The comparison is about freedom in the interaction coefficients; do not erase the difference in bias placement when matching complete equations. §4.2.

A matrix with rank one is not automatically the original vector cross: a general rank-one matrix U Vᵀ may have differently scaled rows. The repeated-row structure is a more specific restriction. Conversely, giving W d² free parameters makes the layer more expressive, but also increases the estimation and optimization burden. More representable functions do not imply a better fit from a short training run.

3. Why the degree grows by one per layer

The one-layer expansion exposed quadratic terms. Repeating the block raises a new question: which higher-order products can it create? The answer depends on the unchanged x₀ connection in the diagram. Because that multiplier is always degree one, we can bound how quickly the degree grows instead of assuming that any recurrent multiplication is equivalent.

In plain terms. Each cross layer multiplies by one more copy of the original input, so the highest polynomial power the model can build climbs by one at each layer. Stack L layers and you can reach degree L+1 — no higher. The argument below is a short proof by induction: check the starting case, then show one extra layer adds at most one degree.

Start the induction at the beginning of the recurrence, where x₀ has degree one in itself. Now suppose every coordinate of xₗ is a polynomial of degree at most l+1. Multiplying by the constant learned matrix Wₗ and adding bₗ cannot raise that maximum degree. Multiplying by one coordinate of x₀ raises it by at most one. Adding the residual cannot raise it further. Therefore L basic cross layers produce degree at most L+1 in x₀. The phrase “at most” allows zero coefficients and cancellations. This is a direct induction on Eq.1, not a statement about every possible learned network.

Worked example. A single scalar input makes the recurrence visible. Set w = 1 and b = 0 in every layer, so the update is xₗ₊₁ = (1+x)xₗ. One layer gives x+x². Two layers give x+2x²+x³. At x = 2 the correct two-layer value is 18. For contrast, reusing the current state as its own multiplier would instead produce 6+6² = 42 at layer two — a different architecture with different degree growth.

What the bias and residual do. The bias contributes degree-one terms after multiplication by x₀. The residual carries already-created terms forward.

Scope check. Neither the bias nor the residual promises that every possible polynomial coefficient can be chosen independently at depth L. The recurrence shares and factors coefficients along computation paths. Bounded degree describes representational structure, not a universal accuracy guarantee. See the paper’s polynomial analysis for its formal claims.

The boundary of the degree statement: it applies to the basic linear cross stack as a function of its embedding coordinates. A sigmoid output, a ReLU MLP, an input-dependent softmax gate, or nonlinear operations inside an expert do not generally form a single polynomial of degree L+1. Learned categorical embeddings also mean this is not a polynomial in the raw category IDs.

What changed from the original DCN?¶

Set every row of W to the same vector wᵀ and temporarily set all biases to zero. Then every coordinate receives the same scalar mixture t = wᵀxₗ, and the update is x₀*t. This is the original DCN's multiplicative restriction. V2 gives each output coordinate its own row of W, hence its own mixture. The comparison concerns the cross operation; arbitrary bias conventions and final neural networks require separate comparisons. Paper §3.2 and §4.2.

For x₀=xₗ=[2,3] and w=[1,−1], the shared mixture is −1. Both original coordinates are multiplied by −1, giving update [−2,−3] and residual output [0,0]. Instead choose V2 matrix [[1,−1],[0,1]]. Its mixtures are [−1,3], so its update is [−2,9] and output [0,12]. No shared scalar can produce both update ratios −1 and 3 for this nonzero anchor. This exhibits extra freedom at the vector-valued layer; it is not a proof that every trained V2 classifier outperforms every original DCN classifier.

Read coefficients after the prediction head¶

For a one-layer cross-only score, let q be the linear readout vector and c its intercept. Expanding s=qᵀ[x+x⊙(Wx+b)]+c gives a linear term Σᵢ qᵢ(1+bᵢ)xᵢ and a quadratic term Σᵢⱼ qᵢWᵢⱼxᵢxⱼ. The coefficient of a square xᵢ² is qᵢWᵢᵢ. For distinct coordinates i and j, the coefficient of xᵢxⱼ is qᵢWᵢⱼ+qⱼWⱼᵢ, because multiplication commutes. A single matrix entry is therefore not the whole prediction-level interaction coefficient.

With q=[1,1], a skew-symmetric change A=[[0,a],[−a,0]] changes the vector representation but contributes a*x₁*x₂−a*x₂*x₁=0 to its summed score. This is a precise example of non-unique weights for the same function. It prevents treating a large entry or block norm of W as causal feature importance. At greater depth, coefficients also collect products along multiple layer paths. The paper's §7.6 weight-block visualization is an inspection aid; it does not identify causal effects. A nonlinear deep head or learned embeddings further complicate interpretation.

Expand a two-layer example all the way to the output¶

Use one scalar input x, zero biases, and cross weights 0.5 and 0.25. The first layer gives x₁ = x + 0.5*x². The second layer still multiplies by the original x: x₂ = x₁ + 0.25*x*x₁. Substituting the first expression gives x₂ = x + 0.75*x² + 0.125*x³. This is a polynomial containing first-, second-, and third-degree terms. At x=2, the first layer gives 4 and the second gives 4 + 0.25×2×4 = 6; the expanded polynomial gives the same 6.

The argument generalizes by induction. “By induction” means establish a starting case, then show that one additional layer preserves the proposed rule. Before any cross layer, each coordinate has degree one in x₀. A linear mixture of coordinates does not increase the maximum degree. Multiplying that mixture by one coordinate of x₀ increases its degree by at most one. Adding the residual preserves the lower-degree terms. After L linear cross layers, the maximum degree is therefore at most L+1 in the embedded input coordinates.

“At most” is essential. Weights can be zero, terms can cancel, or the readout can ignore a coordinate. Depth makes higher-degree terms available; it does not guarantee that the fitted model uses every degree. Nor does it make all coefficients independently adjustable. The shared matrices and repeated recurrence impose structure on which polynomial coefficients can be represented together. A count of possible monomials is not a count of free model parameters.

The bias inside the cross multiplication adds a term proportional to x₀. Moving it outside would add a different constant term at that layer. For an original coordinate x₀,j=0, the multiplicative update at that coordinate is zero, including its inside bias, so its cross-stack residual is preserved. The later prediction head can still depend on other coordinates and have its own bias. This is a useful coordinate-level CHECK because it distinguishes two plausible-looking formulas with identical tensor shapes.

Follow the gradient through the residual route¶

Hold x₀ fixed temporarily and ask how a change in xₗ affects xₗ₊₁. There is a direct identity route through the residual addition and another route through the learned matrix followed by coordinate-wise scaling by x₀. In matrix notation, the derivative is I + diag(x₀)Wₗ. The diagonal matrix diag(x₀) places the anchor coordinates on its diagonal, so left-multiplying W scales its output rows.

This calculation explains the residual connection without promising easy optimization. The learned route can amplify, cancel, or distort the identity route. If you instead differentiate the complete network with respect to the original input, x₀ is not fixed: gradients also flow through its repeated appearances and through the embedding network. State which variable is being varied before using a derivative as an argument about stability.

4. Low rank: share directions, then count the cost

Depth controls the maximum interaction degree, but a dense matrix pays for d² mixing coefficients in every layer. Low rank addresses that cost by sharing a smaller set of directions. It leaves the original-input multiplication and residual untouched, so distinguish a cheaper or restricted mixing map from a change in the cross recurrence itself.

In plain terms. A full d-by-d matrix can mix every feature into every other, but that costs d² weights. A low-rank factorization forces the mixing through a narrow r-dimensional funnel: squeeze down to r numbers, then expand back to d. This shares structure across interactions and can save weights — but only when the funnel is genuinely narrow.

The factorization. A dense W has d² weights. A rank-r factorization writes W ≈ UVᵀ, where U and V each have shape [d,r]. The current state first maps down to r numbers through Vᵀ, then maps back to d through U. A matrix’s rank is the number of independent directions it can transmit. Constraining that number shares structure among interactions. The update becomes:

xₗ₊₁ = xₗ + x₀ ⊙ [Uₗ(Vₗᵀxₗ) + bₗ]

There is no activation between these two factors in the basic low-rank layer. It remains one linear transformation before the multiplication, so the same polynomial-degree argument from §3 still applies. If W exactly equals UVᵀ, the dense and factored forward passes should match, and so should their derivatives with respect to x₀ and xₗ. The lab checks this identity. If instead rank reduction discards part of W, a prediction difference is possible and must be measured. §3.5, Eq.2.

Worked example — when does it actually save? The two factor matrices contain 2dr weights, compared with d² for the dense matrix; both variants also carry d bias entries. Strict savings therefore require r < d/2. For d = 64 and r = 8, the matrix weights fall from 4,096 to 1,024. But for d = 4 and r = 2, both forms use 16 weights. So “factored” alone is not a cost reduction.

Reading the SVD picture. The picture uses a singular value decomposition (SVD): a matrix is expressed using orthogonal input/output directions and nonnegative strengths called singular values. Retaining the strongest r directions gives a standard approximation. Here the strengths are 4, 2, 1, and 0.25. The displayed Frobenius error is the square root of the sum of squared entrywise differences. In this constructed SVD it also equals the square root of the discarded squared singular values. With r = 1 that is √(4+1+0.0625) = 2.25.

Scope check. This visual is a post-training matrix approximation explanation only. In the training lab, U and V are learned directly from scratch, jointly with embeddings and the classifier; we do not first train a dense model and then compress it. Different initialization and parameterization can change optimization and regularization as well as cost. A smaller matrix error is not a guarantee of better test log loss.

A rank constraint is a shared bottleneck¶

A dense d-by-d matrix can mix every current coordinate into every output coordinate. The factorization W = U Vᵀ, with U and V of shape [d,r], first compresses xₗ to r intermediate coordinates, then expands those coordinates back to d. Here r is the rank budget. All output mixtures must be assembled through the same r-dimensional bottleneck, which restricts the possible matrix while reducing its stored parameters when r is small enough.

Take V=[1,2]ᵀ, U=[1,3]ᵀ, and current row [2,3]. The compressed scalar is 2×1 + 3×2 = 8. Expanding it gives [8,24]. The equivalent dense matrix is [[1,2],[3,6]]; applying it to the column form of [2,3] gives exactly the same vector. With anchor [2,3] and zero bias, the coordinate-wise product is [16,72], and adding the current row gives [18,75].

Computation Intermediate Shape for a batch
Compress with V Weighted directions from current representation [B,r]
Expand with U One proposed update per original coordinate [B,d]
Multiply by x₀ Anchor-dependent interaction update [B,d]
Add xₗ Retain the residual representation [B,d]

The two-dimensional example establishes equivalence, not savings: its two factors contain four numbers, just like the dense matrix. At d=128 and r=16, the dense weights contain 16,384 numbers while the two factors contain 4,096, excluding the same bias vector. The parameter reduction is fourfold. Actual runtime depends on the two matrix multiplications, batch shape, memory traffic, and hardware; a smaller parameter count does not guarantee the same factor of speedup.

A copied-weight equivalence test requires constructing W from the very same U and V. Comparing a separately trained dense network with a separately trained factored network is not an algebraic equivalence test, even if their scores are similar. Conversely, exact equality for a factorable W does not show that low rank can express every dense W or that either parameterization finds the same solution during optimization.

5. Where does the deep network read from?

We have varied the cross operator without changing its place in the model. Now vary the routing: should the MLP read the original features alongside the cross branch, or read the crossed representation after it? This is an independent design choice. The parallel diagram above fixes the local experiment’s choice; the next comparison makes the stacked alternative explicit.

In plain terms. DCNv2 pairs the cross branch with an ordinary MLP, and there are two ways to wire them. In the stacked wiring the MLP reads the cross output, so it works on top of the crosses. In the parallel wiring the cross branch and the MLP each read the raw input separately, and their outputs are joined at the end. The difference is which input the MLP sees.

DCNv2 combines explicit crosses with an MLP. The MLP alternates affine transformations, which mix and shift coordinates, with ReLU activations, which map negative values to zero. Fig.1 gives two layouts. In a stacked model, the MLP reads the final crossed state xL. In a parallel model, it reads x₀, while a separate cross branch also reads x₀; their final vectors are concatenated before the prediction head. §3.4 and Fig.1.

The head, then the loss. The head is a learned affine map to one scalar, the logit. The sigmoid function σ(z) = 1/(1+e⁻ᶻ) converts that scalar to a probability between zero and one. Binary log loss penalizes the negative log of the probability assigned to the correct class: −log(p) for y = 1, and −log(1−p) for y = 0, averaged over rows.

Worked example. Predicting p = 0.9 for a positive row costs about 0.105. Predicting p = 0.1 for that same positive row costs about 2.303. The gap shows how sharply the loss punishes confident mistakes. The training code uses a numerically stable loss computed directly on logits.

Our local models use the parallel layout. The MLP-only control uses the same embedding width and hidden widths.

Scope check. Adding a cross branch adds parameters and changes the representation reaching the head. So this is an architectural comparison under a shared procedure, not a parameter-matched experiment that isolates one operator. Both layouts are implemented and checked, including gradient flow to the cross weights.

Back to L047. This model contains no row attention and no batch normalization. With fixed weights, each row’s forward pass uses only that row. Re-batching can cause tiny floating-point differences from different matrix kernels, but it must not change the available information. The lab tests this distinction using actual predictions. Training still depends on mini-batches, because they determine the gradient updates.

Parallel and stacked are different hypotheses about useful representations¶

In the parallel model, the cross branch and the ordinary MLP both receive x₀. If the final cross vector has width d and the final deep vector has width h, concatenation gives width d+h. The head can use explicit cross features, deep features, or a combination. This adds capacity as well as a second representation route, so a fair ablation should say which dimensions and parameter counts changed when a branch was added.

In the stacked model, the MLP receives x_L, the final cross representation. Its input already contains the structured multiplicative features. The MLP can transform them nonlinearly, but there is no separate direct deep branch reading x₀ unless the implementation explicitly adds one. Merely reusing the same MLP class does not make the two models equivalent: the arrays supplied to that class differ.

Consider a wiring test with a deep function that doubles its input. If x₀ is [1,2] and x_L is [3,4], the parallel head receives [3,4,2,4], while the stacked head receives [6,8]. These values make the architectural distinction visible without training a model. A shape check alone would miss a bug if two alternate routes happened to have the same width.

Mixtures require a second layer of reasoning¶

A mixture of cross experts computes multiple proposed updates and combines them with input-dependent gate weights. With expert updates [1,2] and [-1,4] and weights [0.75,0.25], the mixture update is [0.5,2.5]. Adding current state [2,3] produces [2.5,5.5]. The weights sum to one, but the resulting coordinates need not lie between zero and one: the gate is a probability-like allocation over experts, not a class probability.

If gate weights depend on the input, changing the input changes both each expert's proposal and the choice between proposals. Nonlinearities inside the experts introduce further non-polynomial operations. The simple degree-at-most-L+1 argument for linear cross layers therefore cannot be transferred to the nonlinear gated mixture. A useful comparison isolates dense versus factored linear crosses before adding nonlinear experts and routing, because the latter changes several assumptions at once.

6. Extension: a mixture changes the function class

A single low-rank map trades freedom for cost. Multiple experts offer several such directions, with a gate choosing how much each update contributes. But the added nonlinearities and input-dependent gate change the function class: the simple polynomial bound derived for the linear cross block cannot just be carried over. Keep this extension separate from the dense and factored arms we actually train.

In plain terms. Instead of one low-rank cross, the paper offers several — called experts — plus a gate that decides, per input, how much to trust each one. This is more flexible, but the flexibility comes from nonlinear pieces (tanh inside the experts, a softmax gate). Once those nonlinearities are present, the clean “degree at most L+1” story from §3 no longer holds.

A single low-rank map may be too restrictive. The paper also proposes multiple experts, each with its own factors, and a gate that assigns input-dependent weights to their updates. Here K is the number of experts. The simplest expert computes Eₖ = x₀ ⊙ [UₖVₖᵀxₗ+b]. Eq.4 then adds a rank-by-rank matrix Cₖ and nonlinear activations inside the low-dimensional space. Eqs.3–4.

Eₖ = x₀ ⊙ {Uₖ tanh[Cₖ tanh(Vₖᵀxₗ)] + b}
xₗ₊₁ = xₗ + Σₖ gₖ(xₗ)Eₖ

In our provided extension, tanh maps values smoothly into (−1,1). The gate computes K learned logits from xₗ, and softmax maps them to nonnegative weights summing to one. At gate logits [0,0], two experts each receive weight 0.5.

How to combine the experts correctly. The diagram’s experts isolate coordinate 1 and coordinate 2. Both already include multiplication by x₀. The rule is: mix the updates first, then add xₗ once. Counting the residual once per expert is a mistake, and it is especially wrong for unnormalized gates.

Scope check. An input-dependent softmax or tanh means this extension no longer obeys the simple finite-degree polynomial description from §3. We implement and gradient-check it, but the trained local and MovieLens arms use dense or linear factored crosses; they do not reproduce DCN-Mix’s results.

Counting the cost. Cost now includes K factor pairs, K small C matrices, and the gate. Ignoring biases, our particular variant uses 2Kdr + Kr² + Kd weights. Never attach the single-expert 2dr count to the entire nonlinear mixture.

7. The local evidence: learn from the experiment we ran

The architecture now suggests testable contrasts: remove the cross branch, use a dense map, or factor that map while retaining the same parallel layout. The local experiment compares those complete procedures with a tree baseline. Inspect held-out error and variability to test whether the extra interaction structure helped; greater expressiveness alone does not determine the winner.

In plain terms. We ran a small, controlled bake-off: four models on three little tables, with every preprocessing choice fixed in advance. The goal is not to crown a winner but to practice reading a result honestly — noticing how little three datasets can prove, and resisting the urge to explain a ranking after the fact.

What we fit, and on what. We fit four models — MLP, dense cross + MLP, factored cross + MLP, and CatBoost — to three small real OpenML tables: credit_g, diabetes, and blood_transfusion. For each table, split seed 5 fixes a stratified 65/15/20 training/validation/test partition. Category vocabularies and numeric means/standard deviations are fitted on training rows only. Missing numeric values become the standardized training mean, which is zero; unseen categories receive code zero.

Scope check. These three tables are Tier-A substitutes, not the paper’s datasets. Model seeds 0, 1, and 2 are new initializations on one fixed split, not new populations, so they measure training variability rather than uncertainty over future data.

The training budget. The three neural arms each receive 20 epochs, batch size 64, Adam at 0.001, gradient-norm clipping at 10, two 32-unit hidden layers, and category embedding width 4. The cross arms have two layers. Factored rank is min(4, max(1, floor(d/4))). Validation log loss chooses the checkpoint. CatBoost receives a separate fixed budget of 300 iterations, depth 6, and learning rate 0.05, again with validation log-loss selection. No arm receives a hyperparameter search.

What the paper's experiments isolate¶

The paper's §6 starts with known target polynomials and inputs sampled uniformly from [−1,1]. In Eq.6, its second target is f₂=x₁²+0.1*x₁*x₂+x₂*x₃+0.1*x₃². Knowing the target distinguishes a representation problem from an unknown data-generating process. The authors compare original DCN, V2 and ReLU networks as cross patterns become less shared, then vary depth and remove residual/bias components. These are controlled synthetic experiments, not recommendation accuracy measurements. The notebook constructs this exact f₂ using your dense cross function, with biases −1 to cancel its linear residual and an all-ones readout. That verifies representability; it does not reproduce the paper's learned RMSE, optimizer behavior or five-run Table 1.

The later experiments ask different questions. Table 5 compares interaction components without a DNN and uses only Criteo's categorical fields. Table 6 restores the deep network and tunes whole models. Its narrowed performance gaps support taking a tuned MLP seriously. Table 7 varies memory budgets for CrossNet versus DNN; it is not the same comparison as giving every architecture the same width. In §7.5, the rank sweep uses three cross layers followed by three 512-unit hidden layers on Criteo. Its bend near rank 64 is an observation for that setup, not a default rank for arbitrary tables. The expert-count sweep holds total rank at 256: increasing expert count also reduces each expert's rank. It cannot isolate “more experts” while holding each expert unchanged. Experiments §6–7.

The Table 6 MovieLens training recipe reports Adam, batch 128, He-normal kernels, zero biases, clipping norm 10, parameter EMA .9999, embedding width 30 and five runs after coarse-to-fine tuning. Exact MovieLens search ranges and the winning configuration are not fully specified. Our closer run uses embedding width 16, three seeds, five epochs and no EMA; these are concrete deviations even though its dataset is full-sized. Its random interaction split also differs from Criteo's first-six-days training protocol. Neither should be presented as evidence for temporal relational prediction.

Determine what the comparison could actually answer¶

The three local tables provide a bounded check of the implemented training procedure. They are not automatically representative of the web-scale recommendation regime that motivated the paper. Their category counts, sparsity, target definitions, sample sizes, and validation procedures affect whether explicit crosses are useful. If the cross model loses, distinguish “this recipe lost here” from “multiplicative features cannot help.” If it wins, distinguish the measured gain from a guarantee about a future relational or ranking task.

The MovieLens task makes another distinction concrete. Predicting a raw rating with squared error and predicting whether a selected rating belongs to a binary class are different tasks. Dropping neutral ratings changes the population before splitting; the mapping of ratings to labels changes the prediction target. Sharing the source dataset name is insufficient for comparing the resulting score to a paper table. Record the transformation, split, metric, and selection rule alongside the name.

For model comparisons, a per-dataset paired difference preserves the actual effect size. A rank records only relative ordering. Suppose errors change from 0.20 to 0.19 on one task and from 0.45 to 0.30 on another: each is one win, but their error reductions are very different. Show both kinds of evidence, keep the metric direction explicit, and interpret the uncertainty using the unit that was actually repeated.

Your final explanation should connect a mathematical restriction to a testable prediction. A low-rank model might reduce variance under a small sample, but it might underfit useful interactions. Increasing r while keeping the data, validation procedure, and other settings fixed distinguishes those possibilities more directly than switching every part of the architecture at once. Predict which outcome would challenge your explanation before inspecting the next test score.

8. Reproduction: same architecture is only the first gate

The local comparison tests the mechanism under a small declared budget. Matching a paper result asks a larger question: are the dataset, target construction, split, embedding sizes, training and selection rules also aligned? Follow that chain before comparing the MovieLens scores. An identical cross equation is necessary for this implementation claim, but insufficient for a benchmark-reproduction claim.

In plain terms. Matching the paper's architecture is only the first of several gates. To claim you reproduced a result you also need the same data, the same split, the same preprocessing, and the same tuning search. This section keeps those gates separate, so a score that lands near the paper's is not mistaken for a reproduction of it.

What the paper reports. The paper’s Table 6 reports DCN-V2 MovieLens log loss 0.3170 ± 0.00036 and AUROC 0.8950 ± 0.00027, as means and standard deviations over five runs. Its DCN-Mix entry is a different model: log loss 0.3160 and AUROC 0.8964. The best layout also differs by dataset: the authors report stacked working better on Criteo and parallel on MovieLens. A single universal layout recommendation would overstate their evidence. §7.3, Table 6.

Same dataset name, different task. For the paper’s MovieLens task, remove rating 3; map ratings 1–2 to zero and 4–5 to one; randomly split 80/10/10. The text calls this regression, but its reported log loss and AUROC concern binary targets. The TFRS tutorial instead demonstrates raw-rating prediction with RMSE. Its roughly 0.93 RMSE is not a reproduction of Table 6’s 0.3170 log loss.

Our fields. Our reader uses six single-valued fields: user ID, movie ID, gender, age, occupation, and ZIP. The paper says six non-multivalent categorical features without publishing the exact mapping, so our interpretation is stated explicitly. Genres are multivalued and omitted. Rating and timestamp do not enter the model.

Scope check. A random interaction split can share users and movies across partitions. This is neither a cold-start evaluation nor a forecast of future interactions. A temporal relational benchmark needs its own availability rules.

9. What this contributes to the relational thesis

In plain terms. DCNv2 is here to be a tough baseline. If a row-only model that can already multiply its fields does well, then a relational model has to earn its keep by using something DCNv2 cannot see — other entities, joins, and time. This section frames that as the real research question.

DCNv2 asks whether the right within-row interaction bias makes a strong baseline. SAINT asks whether a row benefits from representations of other rows. Later relational models add typed entities, explicit relationships and time-dependent neighborhood availability. Those are different sources of information and different computational assumptions. A larger cross network can combine a history aggregate already in x₀; it cannot recover omitted events from a table it never reads.

The useful research question is therefore concrete: after building leakage-safe features and allowing competitive explicit crosses, does a relational model still add value from accessible relational structure? This lesson raises the standard of that baseline without assuming that dense crosses, low-rank crosses, attention, or trees must win.
