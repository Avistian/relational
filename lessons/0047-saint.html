SAINT: when other rows become inputs

Lesson 047 · Somepalli et al., 2021 · Row attention and contrastive pre-training

Your win: implement attention between entire rows, explain how it changes prediction, and write an evaluation protocol that makes the result reproducible. The lesson explains the paper’s supervised and pretraining paths; the lab implements the supervised path and the contrastive loss as a focused exercise.

Lesson 046 made every feature a token: a vector of learned coordinates. Attention then let one feature read other features in the same row. SAINT asks a second question: could another customer’s row help represent this customer? We will build that operation and test its consequences before deciding whether it improves prediction.

Primary source: Somepalli, Goldblum, Schwarzschild, Bruss & Goldstein, SAINT: Improved Neural Networks for Tabular Data via Row Attention and Contrastive Pre-Training. Read §3 with the shape diagram, §4 with the augmentation diagram, and Table 2 with the evidence audit below. This is a historical paper explanation, not a claim about today’s best model.

Warm up — retrieve before reading

1. Start from the row encoder you already understand

A sample is one row; a feature is one input column; an embedding maps a feature value to a learned vector. For example, a job category indexes a lookup table. Each column has its own embedding: “yes” in a mortgage column and “yes” in a default column need not mean the same thing.

A numeric scalar also becomes a vector. The paper describes a per-feature linear map followed by ReLU, which replaces negative coordinates with zero. Its released code instead uses a small network 1 → 100 → d, with ReLU between the linear layers. Here d is the number of coordinates in the final token. Our implementation follows that executable numeric embedding. Unlike L046’s affine token, it can bend as the numeric input changes. These are architectural differences worth recording, not interchangeable descriptions.

Prepend a learned [CLS] vector. It is a summary slot that starts identical across rows and becomes row-dependent through attention. It never contains the label. With B rows, n original features, and T = n + 1 tokens including CLS, the embedded batch has shape [B, T, d]. The final prediction head reads only the final CLS vector. Paper §3; released embeddings and prediction head.

Begin with what one number in the tensor represents¶

Imagine a customer table with age, annual spend, and subscription type. A cell such as “annual spend = 900” is one measurement, whereas a token is a learned vector representing that measurement. Its coordinates are not nine hundred different business facts. They are channels whose usefulness is learned through the prediction objective. Different columns need different encoders: the category “premium” in a subscription column should not automatically share a representation with the same word in an unrelated product column.

Write the token array as H[b,t,j]. The index b selects a row in the batch, t selects a feature token or the summary token, and j selects one embedding coordinate. If there are two customers, three feature tokens plus [CLS], and embedding width two, the shape is [2,4,2]. There are sixteen scalar entries. The three axes describe different things; moving an axis changes which objects the attention mechanism treats as its sequence.

The [CLS] token starts as a learned vector repeated across rows. Initially it does not contain a particular customer's values. It becomes a row summary because attention lets it read that row's feature tokens. This explains why a classifier can use only the final [CLS] vector without ignoring the other features: their information has had a route into that vector. It also explains a useful debugging check. If the feature tokens cannot influence [CLS], changing an input feature will not change the classifier through that route, however many layers the code declares.

The numeric encoders in the checked release are small feature-specific MLPs. A scalar goes through an affine map, a ReLU, and another affine map before entering attention. This can learn a piecewise nonlinear representation of age or spend. It does not create additional observations. A missing numeric value follows a learned missing-value representation instead of pretending that an observed zero and an unknown value mean the same thing. These are implementation details you can trace in tokenize, rather than properties you should infer from the word Transformer. The paper's architecture overview and the executable release are linked separately because their exact operation ordering differs. SAINT architecture and release.

Follow a prediction backward¶

The final head maps a row's summary vector to two class logits. A logit is an unrestricted score; applying softmax makes the two scores into probabilities that sum to one. For logits [0, log(3)], the positive-class probability is 3/(1+3)=0.75. Cross-entropy penalizes the log probability of the correct class. It is therefore the head's error signal that teaches the summary token which feature and companion information is useful. Neither an attention weight nor an embedding coordinate is already a class probability.

Read the path: each category uses its own embedding lookup; each numeric feature uses a small network with widths 1 → 100 → d and ReLU between its linear maps. Missing numbers use learned feature-specific tokens. Feature attention exchanges information within each row. Packing then makes each complete row one sequence element, allowing row attention to exchange information across the batch. Restoring the tokens lets the classifier select the final CLS vector. Its d → 1000 → 2 network, with ReLU between the linear maps, emits two logits (unbounded class scores); softmax converts them to probabilities. The training loss uses the logits and the labels.

Inside each stage: both attention operations and both feed-forward networks include normalization and residual addition. Our released-code mirror computes u = LayerNorm(x), then u + f(u) for each sublayer; §6 explains why this differs from adding the original x. 2. Two attention operations, two different sequences

Attention computes a learned weighted average. A query describes what a token is seeking; a key describes what a candidate offers; a value carries the information returned. Learned linear projections form Q, K, and V. The dot product between a query and key gives a compatibility score.

A = softmax(QKᵀ / √h)
output = A V

Here h denotes the width of one head’s query/key vector (not the number of heads). The transpose swaps the final two axes of K. Dividing by √h controls the scale of dot products as their width grows. Softmax exponentiates scores and normalizes across the candidate keys, so each query’s weights sum to one. Several heads learn different projections; their outputs are concatenated and projected back to the original width.

For feature attention, each row is its own sequence. Each head computes B separate T × T matrices. The question is “which of this row’s features should this token read?” A job token may use the age token, but it cannot inspect another customer.

For intersample attention, flatten all tokens of each row, including CLS, into one vector of width Td. Put the B flattened vectors into a single sequence. Now each head computes one B × B matrix. The question becomes “which rows in this batch should this row read?” After the operation, restore the token structure.

[B, T, d] → [1, B, T·d] → row attention → row feed-forward → [B, T, d]

Worked shape check: B = 32 customers, 10 features plus CLS, d = 8. Feature attention receives [32, 11, 8]. Row attention receives [1, 32, 88]; each row-attention head has 32 × 32 weights. The outer 1 means “one sequence of customers.” It is not a transpose to [11, 32, 8], which would make each feature column a separate sequence and implement a different mechanism.

The score projections can be narrower than 88. The released row-attention head width is 64; feature-attention head width is 16. Scale by the actual head width, then use an output projection to restore the required 88 or 8 coordinates. Algorithm 1 gives the reshape; RowColTransformer gives the executable dimensions.

Trace a complete stage

A feed-forward network transforms each sequence element independently; it does not create new attention edges. In the row block its element is the entire flattened row, so it can mix coordinates belonging to different features. The released network uses GEGLU: split a projection into value and gate vectors and multiply the value by GELU(gate). GELU is a smooth activation. This gate differs from simply applying GELU to the whole projection.

Each sublayer also has normalization and a residual path. Layer normalization subtracts the mean and divides by the standard deviation of the element’s coordinates, then applies learned scaling and shifting. A residual adds an input representation back to the transformed representation. The exact placement determines the function being computed; we audit it in §6.

Memory matters here. Row attention needs B² weights per head, but that is not the only expense. The released row feed-forward has input width Td and hidden width 4Td, so its dense weight matrices grow quadratically in Td. A wide table can be expensive even with a modest batch. “Only one stage” does not necessarily mean “few parameters.”

Queries, keys, and values have different jobs¶

A query is a vector describing what the receiving token is looking for. A key describes how a candidate source should be matched. A value is the information contributed if that source receives weight. Learned linear projections construct all three from the current representation. Calling them learned does not mean each has a human-readable role; their distinct roles come from the equations that consume them.

For one receiving token i, the score of source j is the dot product of its query and that source's key, divided by the square root of the key width. A dot product adds coordinate-wise agreements. The division keeps the typical magnitude of a sum of many roughly unit-scale terms from increasing merely because the embedding width increased. It is a scale convention, not a theorem that all trained attention scores have the same variance.

Softmax converts the score vector into nonnegative weights. Its denominator sums over candidate sources for this receiver. With scores [0, log(3)], the weights are [0.25,0.75]. If their scalar values are [2,6], the received value is 0.25×2 + 0.75×6 = 5. Keep those scores fixed and change the second value from 6 to 10: the output becomes 8. The weights did not change, but the representation did. An attention heatmap alone therefore does not tell you the magnitude or sign of each source's contribution.

Stage Receiver reads Score-array shape for one head Example normalization
Feature attention Feature tokens within its own row [B,T,T] Each length-T source row sums to one
Whole-row attention Packed representations of companion rows [1,B,B] Each length-B source row sums to one

The batch dimension B disappears into the sequence dimension in the second stage. That is the architectural change. It is not equivalent to running ordinary feature attention independently for every row, and it is not the same as attending across rows separately for each feature position.

Why the reshape deserves its own exercise¶

Suppose one row's two tokens are [1,2] and [3,4]. Packing the whole row should produce [1,2,3,4]. A transpose followed by a reshape can produce [1,3,2,4]; its shape is still valid, but the coordinate convention has changed. If unpacking uses the original convention, information returns to the wrong feature positions. An invertibility check catches one class of bug, while a named-coordinate fixture catches the subtler case where pack and unpack agree with each other but disagree with the intended architecture.

After attention, multiple heads' outputs are concatenated and projected back to the required width. A head is a separate learned matching-and-aggregation channel, not a vote for one class. The output projection and subsequent nonlinear transformation can combine these channels. Read the notebook's Attention.forward from the final output backward: verify the restored width, then the concatenation order, then the value aggregation, then the axis used by softmax.

3. Hold the query fixed; change its companions

In L046, evaluation mode removes dropout randomness, and one row’s prediction is independent of unrelated batch members. In SAINT, evaluation mode leaves row attention active. Predictions can therefore change when companions change. This follows from the equation; it is not evidence of a software bug.

In the toy above, the query has scalar q = 1. Its own key is 1 and value is 2. The companion has key 0 and value 8. Scores [1, 0] give weights [0.731, 0.269], so the query receives 0.731 × 2 + 0.269 × 8 ≈ 3.614. Move the companion key to 3: weights become approximately [0.119, 0.881] and the result becomes 7.285. The query did not change. These outputs are illustrative attention values, not trained probabilities.

If B = 1, the attention matrix is [1]. The row sublayer still applies learned projections, normalization, and a feed-forward network, but cannot borrow information from another sample. This is not the same as deleting the row block.

Another subtle distinction: permutation equivariance means reordering the same rows reorders their outputs correspondingly. Without row-position encodings, the operator has this property in evaluation mode. It does not imply independence from batch membership. Reordering a large test set before slicing it into mini-batches can change who meets whom, and therefore change predictions.

Turn that observation into an evaluation contract

Specify the companion policy before measuring performance. Our experiment uses separate validation and test batches, each in ascending stored row-index order, with batch size 64 including the final incomplete batch. No labels enter the encoder. Preprocessing learns means, scales, and category vocabularies from training rows only. The model sees test features only when making test predictions.

This is batch-context evaluation: a test row may read other test rows’ features. That is not automatically target leakage, but it assumes those features are jointly available at prediction time. For a system receiving isolated requests, a fixed training-only context bank is a different deployment policy that needs its own validation. Mixing future rows into a time-sensitive task can leak information even without labels. Record the available information, not just the random seed.

The paper investigates batch sizes 32–256 and reports relatively stable AUROC on five datasets. Aggregate score stability does not prove that each prediction is unchanged. The intervention above and our trained-model probe answer a different question. Appendix E.

Separate reordering, replacement, and new information¶

Take a fixed customer q and a batch containing q, customer a, and customer b. A permutation changes their order while preserving their values and membership. If the relevant operations are permutation-equivariant, the output for q follows q to its new position and retains its value. “Equivariant” means the output arrangement changes consistently with the input arrangement. It does not mean that all input arrangements or populations produce the same representation.

Replacement is a different intervention: swap b for customer c. Now the candidate keys and values available to q change. Even with dropout disabled, q can receive a different representation and prediction. Evaluation mode switches off training-only randomness; it does not remove the whole-row attention operation. If a model is meant to predict one customer at a time, the deployment procedure must still specify which companion rows, if any, are available.

There are at least three legitimate but different protocols: predict a row in isolation; predict it with a fixed reference batch; or predict all currently arriving unlabeled rows together. The last procedure uses other query features and is transductive with respect to that query batch. It is not automatically target leakage, because no query labels need enter the model, but it answers a different operational question from independent single-row prediction. These distinctions become essential when comparing SAINT with a model whose output is independent of test-batch membership.

For a controlled sensitivity experiment, hold model parameters, the query's values, preprocessing, and stochastic settings fixed. Vary only the companion set. Report a probability difference for the same query, rather than comparing two aggregate scores on different query populations. A large difference establishes dependence on context under that intervention. It does not establish improved accuracy, and a small difference for one query does not establish independence for every query.

What would count as an informative failure?¶

If shuffled batches change the query's prediction after outputs are aligned by row identity, inspect positional assumptions, the pack/unpack convention, batch-dependent preprocessing, and randomness. If replacement changes predictions but permutation does not, that is consistent with set-sensitive computation. If both changes have no effect, check whether the row branch is inactive, whether its projection is near zero, or whether this query happens to be insensitive. Distinct hypotheses need distinct interventions; calling every discrepancy “attention instability” explains none of them.

4. Why the paper also pretrains

Attention describes an architecture, not a source of supervision. When labels are scarce, SAINT adds training tasks defined from the input data itself. A view is a deliberately altered version of a row. The aim is to preserve useful identity despite corruption; that is a modeling assumption to test, not a guarantee that every tabular transformation preserves a target.

CutMix replaces selected raw feature values with values from another row in the batch. It chooses between categories; it does not average their arbitrary integer codes. For example, [age 40, job teacher] can become [age 40, job nurse]. The resulting combination may be uncommon or implausible. This is one reason augmentation strength must be validated.

Mixup then interpolates in embedding space, where values are vectors and interpolation is defined. For augmented embeddings p′ and q′, the mixture is αp′ + (1 − α)q′. Here α is the weight on the first vector. The paper’s standard configuration uses α = 0.2. It chooses a new partner for this second step. The clean original and its augmented view go through the same SAINT encoder, then separate projection heads. A projection head is a small network that forms vectors for the pretraining loss; it is not the final supervised classifier. §4, Eqs.3–4 and Fig.1b.

Two losses solve different problems

The contrastive task asks a clean row to identify its own augmented view among the batch’s views. Let zᵢ be the projected clean row and z′ₖ a projected augmented candidate. Their dot product measures similarity. A positive pair shares row identity, not necessarily class identity. The original row’s partner after corruption remains its positive; the donor used to make the corruption does not become the positive.

sᵢₖ = zᵢ · z′ₖ / τ
ℓᵢ = −log[exp(sᵢᵢ) / Σₖ exp(sᵢₖ)]

The temperature τ controls how sharply a fixed similarity gap changes the probabilities. The denominator includes the matching view and the other candidate views. With four equally plausible views the matching probability is 1/4, so loss is log(4) ≈ 1.386. Better identification reduces loss. The notebook uses the mean of these row losses; Eq.5 sums them. Neither operation requires target labels. Actual training must still address accidental false negatives, such as two rows that genuinely describe very similar entities.

The denoising task reconstructs original feature values from the corrupted representation. For a category, a decoder predicts a distribution and cross-entropy penalizes the wrong category. For a numeric feature, squared error penalizes distance from the original value. There is a decoder per feature, excluding CLS. This objective encourages retention of feature information; contrastive loss encourages discrimination between row identities. The total objective combines them with a weight λ. After pretraining, a supervised head on CLS is trained with the available labels. Eq.5 and finetuning.

Scope boundary: the lab implements the contrastive equation and tests its pairing, but the trained local models and Bank scale-up use supervised training only. They do not reproduce Table 3’s label-efficiency results. A full follow-up would add CutMix, embedding mixup, both projection heads, all denoising decoders, and the paper’s labeled/unlabeled split. A loss-function check cannot stand in for that experiment.

A positive pair is an identity claim¶

The contrastive exercise starts with two views of each original row. A view is an altered representation of that same example, constructed by an augmentation procedure. It is not another randomly selected row with the same class. If row i in the first view and row i in the second view are declared a positive pair, the loss assumes that their shared identity should survive the augmentation.

For one anchor, compute a similarity score with every candidate in the other view. Softmax turns those scores into probabilities over candidate identities, and cross-entropy rewards the matching identity. With two candidates and scores [2,0], the positive candidate in position zero receives probability exp(2)/(exp(2)+1)≈0.881, giving loss about 0.127. If the second view is accidentally permuted but the positive indices remain unchanged, the same confident scores can be rewarded for matching the wrong examples. Tensor shapes and decreasing training loss will not reveal that semantic error.

The temperature divides similarities before softmax. A lower temperature sharpens their relative influence. In the example, dividing [2,0] by two produces [1,0], positive probability about 0.731, and loss about 0.313. This does not mean colder temperatures always produce better representations: gradients, augmentation difficulty, false negatives, and feature scale also change the training problem. Vector normalization is another explicit choice. Dot products depend on both length and direction; cosine similarity removes the length contribution. The notebook implements the stated one-way dot-product objective and does not silently add a different normalized, symmetric variant.

Augmentations also encode assumptions. Replacing part of a row can teach robustness to missing or corrupted fields, but it can create impossible combinations if fields obey constraints. A representation objective cannot decide by itself whether replacing a birth date while preserving age is a meaningful example. Inspect what invariances the augmentation encourages before interpreting a good contrastive score as useful supervised knowledge. SAINT pretraining objective, Section 4.

5. What the paper’s results actually compare

The paper evaluates 14 binary tasks and two multiclass tasks. Its variants are SAINT-s (feature attention), SAINT-i (intersample attention), and SAINT (both). Table 1 gives the usual stage counts as 6, 1, and 1 respectively. Therefore their published comparison is not merely switching one sublayer on and off while holding everything else fixed.

For binary tasks, AUROC measures how well predictions rank positive examples above negative examples across thresholds. An AUROC of 0.933 is 93.3% in the paper’s table; it is not 93.3% classification accuracy. Multiclass columns report accuracy instead. Do not average those columns into the binary mean.

Read the supervised comparison as a chain of decisions¶

An architecture specifies possible computations. A training procedure selects parameters using a dataset, initialization, optimizer, and stopping rule. An evaluation procedure specifies preprocessing, query batches, and scoring. The reported AUROC belongs to that whole chain. A source-parity check can establish a matching forward operation while leaving the training and evaluation chains different from the paper.

AUROC asks how often a positive example receives a higher score than a negative example, with a tie convention. It does not evaluate whether a prediction of 0.8 corresponds to an 80% event rate. Log loss and calibration diagnostics ask different questions. A model can rank rows well while being badly calibrated, so preserve the intended prediction use when deciding which metric belongs in the report.

Three model seeds on a fixed train/test split expose some variation in optimization and initialization. They do not turn one dataset into three independent datasets, and they do not measure variation across alternate populations or future time windows. Compare models within each dataset first. A paired seed difference holds the evaluated rows fixed, reducing one source of accidental variation. Then average seed results inside a dataset before giving that dataset a vote in the cross-dataset ranking.

The strongest conclusion from this lab is conditional: the checked implementation behaves as specified, and the declared supervised procedure produced these outcomes on these tasks. To explain a disagreement with a paper, identify a candidate cause that an experiment could discriminate—pretraining, preprocessing, batch composition, model capacity, or selection budget. Merely listing all possible differences is not diagnosis. Choose one, hold the others fixed as far as practical, predict its effect, and retain the result even if it does not support your explanation.

9. What this contributes to the relational thesis

SAINT learns interactions among rows in one table, using the mini-batch as a complete candidate set. A relational model instead has database entities, explicit foreign-key relationships, and often timestamps restricting which neighbors exist at prediction time. SAINT’s learned similarities do not discover foreign-key semantics, and its batch membership is not a database join.

The useful bridge is more precise: a row representation can depend on other rows, and evaluating that representation requires defining which rows are available. That lesson survives whether SAINT wins today’s local benchmark. Later, the “companion policy” becomes a relational neighborhood and a temporal sampling policy. The baseline discipline from L042 still applies: stronger interactions need a fair comparison, not a predetermined winning story.
