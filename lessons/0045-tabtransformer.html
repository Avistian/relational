TabTransformer (training & self-supervised pre-training)

Lesson 045 · Phase 2 · Q1 · primary reading: Huang, Khetan, Cvitkovic & Karnin 2020, TabTransformer: Tabular Data Modeling Using Contextual Embeddings

Back in L032 you built TabTransformer's architecture and ran it forward only — embed the categorical columns, push them through self-attention to make them contextual, concatenate the continuous features, read out a prediction. We deliberately stopped there and promised the rest for Year 2. This is that lesson: we now train it, we test its distinctive lever — semi-supervised pre-training on unlabeled rows — and we hold it to the same baseline-first bar that TabNet and NODE both failed on flat tables.

There are two questions worth answering, and they are different. First: does making a categorical embedding contextual — letting a column's vector depend on the rest of the row — actually buy accuracy over the context-free entity embedding of L031? Second, and more interesting for the thesis: TabTransformer can be pre-trained on data with no labels at all, then fine-tuned on a few — a lever gradient-boosted trees structurally lack. Does that pay when labels are scarce?

Its single skill: train TabTransformer, show that contextual categorical embeddings give a small edge over context-free ones while both still lose to a tree on a flat table, pre-train it self-supervised with replaced-token detection to win back label-efficiency, and name its structural limitation — numeric features never enter the attention.

One sentence. Trained from scratch our TabTransformer's contextual embeddings edge the context-free static-embedding MLP on 2 of 3 categorical tables (mean rank 2.33 vs 2.67) but both lose to CatBoost on all 3 (rank 1.00) — yet TabTransformer alone can be pre-trained on unlabeled rows and, at 3 % labels, that pre-training lifts test AUC +0.008 on every seed: the accuracy on one flat table is a tie-or-loss, but the ability to learn from unlabeled data is the lever trees don't have — and the seed of the relational thesis.

Recap: the architecture you already built

TabTransformer (Huang et al. 2020, Fig. 1) is four stages. You wrote each one in Lab 032; here is the data-flow again, because the training and pre-training below act on specific pieces of it.

The paper's Fig. 1, walked stage by stage. (1) each categorical column becomes a learned d-vector (an entity embedding, L031); (2) a stack of N Transformer blocks lets those vectors attend to each other, so each becomes contextual; (3) the continuous features skip the Transformer and are LayerNorm'd; (4) the flattened contextual embeddings and the normalised numerics are concatenated and passed to an MLP head. Stage 2 is the only thing that is new over a plain entity-embedding MLP — and, crucially, it touches only the categorical columns.

Context-free vs contextual (the one idea). A context-free embedding (L031) maps checking = < 0 to the same fixed vector in every row. A contextual embedding rewrites that vector as a weighted blend of the whole row's columns via self-attention (softmax(Q·Kᵀ/√d)·V), so checking = < 0 gets a different vector next to housing = rent than next to housing = own — the tabular echo of "bank" meaning river bank vs savings bank. Setting n_layers = 0 (no Transformer blocks) turns TabTransformer back into the context-free MLP — which is exactly the ablation we use below to isolate what contextualisation buys.

Toggle before → after: the same column embedding changes once it can see its neighbours. Numbers are an illustrative 3-token toy. This is the mechanism; the next section asks whether it is worth anything on real data.

Does context help? Contextual vs context-free vs a tree

The cleanest experiment runs the same class two ways — with the Transformer (n_layers = 3, contextual) and without it (n_layers = 0, the L031/L032 context-free embedding MLP) — so the only variable is contextualisation. Then we add the honest bar: a CatBoost with native categorical handling. Predict before you look.

Read this the disciplined way. Two separate readings, same as L043/L044. On the contextual vs context-free question, the direction matches the paper (contextual embeddings help), but the margin is tiny — a rank of 2.33 vs 2.67 and near-identical means. On the vs trees question, the verdict is unambiguous on these tables: a well-tuned tree wins every one, and it is far cheaper. This is the paper's own honest framing — TabTransformer's headline "+1.0% AUC" is measured over other deep methods, and it only matches GBDTs on supervised tabular data (it does not beat them). Our small run reproduces exactly that shape: a small win over the deep baseline, a loss to the tree.

The structural limitation: numerics never see the attention

Look again at stage 3 of the architecture. The continuous features are LayerNorm'd and concatenated after the Transformer — they never become tokens, never attend, never get contextualised. All of TabTransformer's cleverness is spent on the categorical columns. On a table like churn (16 numeric, 4 categorical) most of the signal lives in features the attention never touches, which is a large part of why the contextual edge is so thin.

Why this matters, and where it goes next. This is not a tuning detail — it is the design's ceiling, and it is the reason L046 (FT-Transformer) exists. FT-Transformer's one upgrade is a feature tokenizer that turns each numeric feature into a token too (a learned linear embedding per feature), so numerics join the attention and the whole row is contextualised. Keep that thread: TabTransformer contextualises half the row; FT-Transformer contextualises all of it, and is the stronger neural baseline because of it.

The lever trees lack: self-supervised pre-training

Here is where TabTransformer does something a GBDT cannot. Because it is a differentiable encoder, it can be trained on rows with no labels using a pretext task — a fake supervised problem you can generate for free — and then fine-tuned on the few labels you actually have. The paper's best pretext is replaced token detection (RTD).

Self-supervised pre-training. Learning a representation from unlabeled data by inventing a task whose answer is knowable without human labels, then transferring the learned encoder to the real task. RTD (replaced token detection), borrowed from ELECTRA: independently, with probability p, replace each categorical cell with another value drawn from that column; a per-column binary detector must then predict, from each cell's contextual embedding, whether it was replaced. To solve it, the encoder has to learn which category values plausibly co-occur in a real row — structure that transfers. Fine-tuning then keeps those pre-trained embeddings + Transformer weights and trains a fresh classifier head on the labeled set.

The RTD pretext on an illustrative row. Drag the replace probability; tampered cells turn red. Note the subtlety the readout calls out: a uniform redraw sometimes lands back on the original value, so the effective replaced fraction is only p·(1 − 1/card) — those cells stay "real". No label is ever used; the corruption is the supervision.

Does it pay? The test: take a table with plenty of rows (adult, 16 000), hide almost all the labels, and compare training from scratch on the few labels against pre-training the encoder on all the rows' features (unlabeled) and then fine-tuning on those same few. Predict first.

Verified: labs/_verify_l045.py (semi-supervised section) — adult, 16 000 rows, unlabeled pool ~11 200, test ROC-AUC, mean over 3 seeds; a gentle fine-tune learning rate (5×10⁻⁴) avoids catastrophic forgetting of the pre-trained weights. At 3 % labels (~250 rows) pre-training lifts AUC +0.008 on every seed (0.825 → 0.833); at 10 % the gap nearly closes (+0.001). The lift is small at this down-scaled scale — the paper reports ~+2.1% with far more unlabeled data — but the shape is the point: free unlabeled data helps most exactly when labels are scarcest.

Thesis bridge

What today buys the thesis. Two things. Methodologically, this is the third famous neural architecture in a row (TabNet, NODE, now TabTransformer) that only ties or loses to a cheap tree on a single flat table — the habit of running the strong baseline first and reporting the honest verdict is now reflex. Architecturally, TabTransformer isolates the one operation the rest of the curriculum is built on: a column's representation refined by attending to related information. Within a row that is only a mild win. But that same operation — aggregate an entity's related vectors into a contextual representation — is precisely message passing over a relational graph, where the related vectors live in other tables reached by foreign keys, and carry information no single flat row contains. And the pre-training lever generalises too: the value of learning from unlabeled structure only grows when the structure is a database, not a table. Today is the within-row rehearsal of the across-table idea the thesis is betting on.
