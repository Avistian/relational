TabM — parameter-efficient ensembling

One shared backbone, several predictions: trace the savings, the objective, and the evidence.

Lesson 053 asked what a strong training recipe can buy a plain MLP. TabM asks a different question. Can we get the benefit of an ensemble of predictors while sharing the expensive weights, instead of paying for a full copy of each one?

In plain terms. A normal ensemble trains several separate networks and averages their answers, which costs several times the memory. TabM keeps one big shared network and gives each ensemble member a few tiny knobs of its own, so the members still disagree in useful ways without each one storing a full copy of the weights.

Your outcome here is threefold. You will implement the numeric variant called TabM-mini. You will trace its member axis — the extra dimension that carries several predictions at once — from the input all the way to the loss. And you will keep three kinds of evidence apart: what the architecture is, how it is trained, and what a benchmark actually shows.

For our relational mission, TabM supplies a demanding single-table baseline. A relational model must add value beyond good flat features and a well-evaluated ensemble, so we first need to know how strong that ensemble baseline really is.

Read Gorishniy, Kotelnikov & Babenko, TabM: Advancing Tabular Deep Learning with Parameter-Efficient Ensembling (arXiv 2410.24210, ICLR 2025), §3 (the model) and §5 (the analysis), in one sitting; use the notebook for the implementation and evidence in a second. We build TabM-mini — the minimal effective variant — with numeric inputs only.

Recall before reading

1. Ensembling: averaging several predictors

Start with the familiar version. A deep ensemble is a set of networks that are each trained separately, with a different random seed, whose predictions are then averaged. Why would averaging help at all? It helps only when the members make complementary errors — mistakes that partly cancel when you average them. So the ensemble need not beat its single best member, and averaging two copies of the same model changes nothing. The cost is blunt: storing k independent networks takes about k times the parameters of one network, and training them repeats the whole optimization.

In plain terms. Averaging helps for the same reason a panel of judges can beat one judge: only if the judges are wrong in different ways. Cloning one judge adds no wisdom, just cost.

Now the cheaper version. Parameter-efficient ensembling keeps the large matrices shared across members, and gives each member only a small set of its own parameters plus its own output head. TabM builds on an existing technique called BatchEnsemble, and it changes how that technique shares weights and how it initializes them. The saving is a saving in parameters first of all. The activations still carry a member axis, and the dense multiply-adds still scale with k, so compute does not shrink the same way.

Scope check. Runtime overhead can be less than k on hardware that the original MLP underuses; this is a measurement, not a guarantee of nearly free inference. Paper §3.2 and Appendix A.1.

Two levers, kept separate. The paper varies two things that are easy to confuse. Weight sharing is a constraint on the model: it limits which functions the members can represent. Ensemble-aware selection is a choice made during tuning: it picks the hyperparameters and the stopping epoch using the average prediction's validation metric, not each member's own metric. The paper's architecture ladder is designed to probe both levers, one at a time. Our smaller four-arm experiment changes several things at once, so it cannot single out either lever as the unique cause of an improvement.

Why averaging helps only some kinds of error¶

Write member i's regression prediction as the true conditional mean plus an error eᵢ. The ensemble error is the average of those errors. If each member has error variance σ² and every pair has correlation ρ, the variance of the k-member average is σ²[ρ+(1−ρ)/k]. This follows by expanding the variance of a sum into k variance terms and k(k−1) covariance terms. The widget and fixed-correlation k→∞ discussion restrict ρ to [0,1]; negative equal pairwise correlations must satisfy ρ≥−1/(k−1) and cannot stay fixed negative as k grows.

For k=4 and ρ=0, the variance is σ²/4. For ρ=0.75 it is 0.8125σ². Adding members cannot average away the shared component. As k grows, the expression approaches ρσ², not zero. The calculation assumes equal variances and equal pairwise correlation; use it as intuition rather than a fitted law for every TabM ensemble.

Bias matters as well. If every member makes the same systematic mistake, averaging preserves it. “Diversity” is useful when different predictions contain complementary information about the target. Randomly making a strong predictor worse can increase disagreement without improving the ensemble.

TabM aims to obtain useful diversity with shared expensive matrices and relatively cheap member-specific parameters. This creates a tension: sharing reduces parameter storage and can couple learning beneficially, but it also prevents members from being independent fits. The experiment should measure the collective result, individual members and cost rather than assuming independence from the member count.

Three axes that a single ensemble score hides¶

Separate member quality, error dependence and aggregation. A weak member may help if its useful errors differ from the rest; a strong but redundant member may add little. The aggregation rule can also change the result even with identical members. Inspect these axes before interpreting why the ensemble improved or failed.

2. Model architecture

The symbols, once

Fix the notation before the mechanics. The pictured model is numeric TabM-mini, corrected v2, with shared training batches (the paper's §3.4 simplification). B is the number of rows in a batch. p is the number of numeric features. k is the number of members. d is the hidden width. N is the number of blocks. dy is the output width (1 for regression, 2 for our binary tasks). Median imputation and z-score statistics are fitted only on training rows. Regression targets are standardized on training rows, and the errors are converted back to their original units for reporting.

In plain terms. One row of features fans out into k slightly different copies. Each copy travels through the same shared network but with its own small adjustments, and at the very end the k answers are averaged into one.

The forward path, step by step

Broadcast the row. Take x with shape [B,p] and copy it to shape [B,k,p], one copy per member.

Give each member its own adapter. Multiply by the learned input adapter R₁:[k,p], initialized to random ±1. Those entries are continuous trainable scalars after initialization, not permanently binary masks; the ±1 is only the starting value.

Pass through the shared backbone. Then repeat N blocks. Each block is a shared linear transformation with a shared bias, then ReLU max(0,h), then dropout. Dropout independently masks activations during training and is disabled at inference. Mini is deliberately minimal: it has no S adapter anywhere, no later R, and no member-specific backbone bias.

Split into member heads. The remaining outputs [B,k,d] pass through k independent heads [k,d,dy], one head per member.

Aggregate. For classification, softmax each member's dy logits and average the probabilities over k. For regression, average the scalar outputs. The labels reach a mean-of-member-losses objective during training; they are never input features. Member differences can come from the independent heads, the input adapters, and training randomness together — the first adapter is not their only possible source.

What the full TabM adds

Full TabM keeps input/output scaling vectors R,S and member biases in every block, not only at the input. All multiplicative adapters except R₁ start at 1; member bias rows start equal to an ordinary random linear bias. They can then diverge while learning. The paper's † variants apply numerical feature embeddings before the backbone; Appendix A.2 uses a normal first-adapter initialization for those variants. Our plain-numeric scope excludes embeddings, one-hot categories and multiclass training. §3.3, Figure 1, A.2.

Count the parameter saving

Worked example. Fix p=8, d=64, N=3, a scalar output and k=32. The shared backbone has (8×64+64)+2(64×64+64)=8,896 parameters. One MLP adds 65 head parameters, for 8,961. The corrected mini adds 32×8 input scales and 32×65 head parameters, for 11,232 total. An independent MLP×32 stores 286,752 parameters. So mini is about 1.25 times one MLP, and 3.9% of the independent ensemble's parameter count in this example. But its hidden activations still have shape[B,32,64], so this arithmetic establishes storage savings, not equivalent runtime or activation memory.

3. The BatchEnsemble layer

The goal of the layer. The BatchEnsemble layer is what produces several members from one shared matrix. Start from any linear layer l(x) = Wx + b. A deep ensemble would give member i its own full matrix Wᵢ. BatchEnsemble refuses that cost. It keeps one shared W and gives member i only three small adapters: a multiplicative vector rᵢ applied to the input, a multiplicative vector sᵢ applied to the output, and an additive bias bᵢ. The member then computes (§3.2):

lᵢ(x) = sᵢ ⊙ ( W ( rᵢ ⊙ x ) ) + bᵢ   which equals giving member i the matrix   Wᵢ = W ⊙ ( sᵢ rᵢᵀ ).

In plain terms. Instead of storing a whole new matrix for each member, you store one matrix plus a couple of short lists of dials per member. The dials stretch or flip the rows and columns of the shared matrix, so each member effectively uses a slightly different matrix while the expensive part stays shared.

Reading the symbols. Here ⊙ is coordinate-wise multiplication. The term sᵢ rᵢᵀ is the outer product: a rank-one matrix whose (o,i) entry is sᵢ[o]·rᵢ[i]. So each member reuses the shared W but rescales its rows and columns by learned scalar factors, which equal ±1 only at initialization. Adding a member costs only 3d new numbers per layer, which is small beside W's d² when d is large.

How TabM differs from the original. Original BatchEnsemble initializes its multiplicative adapters randomly with ±1. Full TabM instead initializes only the first R randomly; mini retains only that R. Stacked over members, the layer runs all k in parallel: l_BE(X) = ((X ⊙ R) W) ⊙ S + B with X of shape [k, d]. Source: §3.2.

Toggle the ±1 signs in the widget below to see this. At initialisation TabM sets the non-first adapters to 1, not random. So Wᵢ = W exactly, the adapter has no effect yet, and the model behaves like TabM-mini. Training then frees those adapters to add expressivity. Watch that the two computation routes always agree: the adapter route and the explicit Wᵢ·x compute the same layer.

Two matrix conventions, one operation

The same operation appears in two layouts, which is a common source of confusion. The paper's single-object equation uses column vectors and W:[dout,din], so its mask is srᵀ. The notebook stores the transpose W:[din,dout] and multiplies row vectors on the right, so its mask is rsᵀ. When W is rectangular, these shapes expose a mistaken transpose immediately, which makes it a useful check. One more caution: the figure of 3d added parameters per member, for width d, describes a full BatchEnsemble layer, not mini's single input adapter.

A subtle point about rank. The multiplier rsᵀ has rank one. But W⊙(rsᵀ)=diag(r)Wdiag(s) generally has the same rank as W whenever the scaling entries are nonzero. So this is multiplicative row/column scaling, which is unlike adding a low-rank LoRA update. It cannot freely move one matrix entry without coupling an entire row or column.

Follow two members through one shared matrix¶

Use row-vector convention. Let x=(2,3), shared W=[[1,2],[3,4]], zero bias and output adapters S=(1,1). Member A has input adapter Rₐ=(1,1); member B has Rᵦ=(1,−1). A sends (2,3) into W and obtains (11,16). B sends (2,−3) into the same W and obtains (−7,−8). The matrix is shared; the effective function differs.

In this convention, member i's effective matrix entry is Rᵢ,a Wₐ,b Sᵢ,b. The adapter multiplies an entire input direction and an entire output direction. It cannot independently choose every entry of a dense matrix. Calling the adapter a low-rank multiplicative modulation does not mean that the resulting effective matrix must itself have low rank.

For width d on both sides, the shared matrix uses d² parameters. A full BatchEnsemble layer adds roughly k(2d+d) parameters when both multiplicative adapters and member biases are included. Independent dense layers instead use about k(d²+d). At large d, sharing the d² term can save substantial storage. Activations still carry a member axis, so compute and activation memory do not become independent of k.

Corrected v2 mini keeps only the first input adapter R, ordinary shared backbone biases, and independent output heads. It has no S adapter or member-specific backbone biases. The preserved v1 operator included those extra parameters and is historical evidence, not this architecture. The full local TabM variant uses adapters through the backbone. These variants must not be conflated in an architecture caption: their sharing patterns are different.

The first random sign adapter breaks member symmetry. Later adapters initialized to one initially preserve the shared transformation. If every member had identical parameters, identical inputs and identical stochastic behavior, gradient updates would have no reason to separate them. The initialization is therefore what allows the members to diverge.

4. Why weight sharing and joint training

The variant ladder

The paper compares a controlled ladder of variants (§3.3), and the names are easy to mix up. Read each one as a full procedure, not just an architecture.

MLP×k tunes one MLP, fits independent seeds, and selects each member at its own validation optimum. TabM-packed stores the same independent backbone architecture, but trains all members in parallel and tunes and selects the collective predictor; it is therefore not the same experimental baseline as MLP×k. TabM-naive replaces the independent matrices with BatchEnsemble sharing and random multiplicative adapters. TabM-mini removes all adapters but R₁. TabM restores the adapters, but with the improved mostly-ones initialization. Figure 2 reports these variants after each is separately tuned, so a plotted gap is evidence about the full procedures, not about the architecture alone.

Why collective selection and joint training matter

Worked example. Collective checkpointing can change the result even when nothing is shared. Suppose member A's best validation epoch is 12 and member B's is 30, but their averaged predictions are best at epoch 20. Independent checkpointing would assemble A₁₂+B₃₀. Collective checkpointing instead keeps both members at epoch 20. The two assembled ensembles can have different error dependence. Weight sharing adds a second coupling on top of this: gradients from all members update the same W. So calling the branches "independently supervised" does not make their parameter updates independent.

In plain terms. Picking the best moment for the whole team is not the same as gluing together each player's personal best moment, and once the players share muscles, training one nudges the others too.

The training objective

The training objective is L=(1/Bk)Σb,i ℓ(zbi,yb) for shared batches. The per-example loss ℓ is cross-entropy for classification, which is minus the log probability assigned to the true class; for regression it is squared error. At inference the model averages the member probabilities, or the member scalar predictions. The notebook computes all of this as four live functions. One thing you must not do: do not pool the hidden representations and then apply a single head. That would destroy the separate prediction branches emphasized in Appendix A.4.

Shared versus independent batches. In the original independent-batch procedure, each member sees B independently shuffled rows, giving inputs [B,k,p] and targets [B,k]. Shared batches instead broadcast one batch's B rows to all k members. Both still average Bk losses, but they expose the members to different training examples. Our small suite uses shared batches; the post-EXIT trainer exposes the independent permutations, including the correct matching target layout. §3.4.

Parameters versus hyperparameters. The paper heuristically fixes k=32 rather than tuning it in the main benchmark. R,S and the biases are learned parameters, updated by gradient descent. Width, dropout, learning rate and k are hyperparameters, chosen outside gradient descent. Appendix A.3 hypothesizes a connection between TabM's often larger selected learning rate and its effective batch; this is a hypothesis, not a proven causal explanation. Our small comparison intentionally fixes one learning rate across the neural arms.

Average losses during training; average predictions at inference¶

For classification, the local objective computes each member's cross-entropy and then averages across members and rows. This asks every member to predict the target. It differs from first averaging member probabilities and then computing one cross-entropy for the ensemble.

Take a positive example with member probabilities 0.9 and 0.1. The mean member loss is [−ln(0.9)−ln(0.1)]/2≈1.204. The mean probability is 0.5, whose ensemble loss is −ln(0.5)≈0.693. The second objective can tolerate one member's confident failure when another compensates; the first directly penalizes both members' individual errors.

At inference, classification probabilities are averaged. Averaging logits and applying softmax afterward is generally a different operation. In binary form, probabilities 0.9 and 0.6 average to 0.75. Their logits are about 2.197 and 0.405; sigmoid of the average logit is about 0.786. Read the actual aggregation axis and the position of softmax.

For regression with squared error, averaging member predictions is natural, but the training distinction still exists. The mean squared member loss equals the squared loss of the mean prediction plus the variance of member predictions around that mean. This identity follows by expanding each deviation around the ensemble mean and canceling the cross terms.

Shared weights receive gradient contributions from all members. The update is a joint compromise; it is not equivalent to training k independent networks and compressing them afterward. This can act as a useful constraint, but it also means that pruning members after training changes an ensemble that was optimized jointly.

5. Weak individually, stronger collectively?

Define the comparison first. Before looking at any scores, be precise about what is being compared. A standalone MLP is a network optimized with its own weights, on its own. A submodel is one branch of a jointly trained TabM. There are then two different error measurements. The mean individual error scores every branch separately and averages those errors. The collective error first averages the predictions and then scores that single averaged prediction. These two need not agree.

Worked example (regression). For squared error on one row, let μ=(1/k)Σpᵢ. Expanding pᵢ−y=(pᵢ−μ)+(μ−y) and canceling Σ(pᵢ−μ) gives meanᵢ(pᵢ−y)²=(μ−y)²+meanᵢ(pᵢ−μ)². So the ensemble MSE cannot exceed the mean member MSE. The analogous RMSE inequality follows from the triangle inequality for error vectors. For cross-entropy, the convexity of −log gives the same direction when probabilities are averaged. But notice what this means: these are arithmetic facts that hold for any members. Their presence alone is not evidence that TabM learned a better predictor than a separate MLP.

In plain terms. "The average is at least as good as the typical member" is guaranteed by algebra, not by TabM being clever. It would be true of any random collection of predictors, so it cannot be your evidence that sharing helped.

Worked example (classification has no such guarantee). Classification error can go the opposite way. On one positive row, member probabilities (0.51,0.51,0.01) give a mean individual error of 1/3, but the mean probability is 0.343 and the collective error is 1. The two slightly-correct members are outvoted by one confident wrong member. So a CHECK must verify the calculation and record the observed ordering; it must not reject a legitimate result just because a preferred story failed.

Where the real evidence is. Figure 5 is much stronger evidence than the elementary inequality. The authors compare train/test trajectories against a matched width-512, depth-3, k=1 baseline, with dropout and weight decay off, 25 separately tried learning rates, and training beyond the best epoch. Our checkpoint-only small suite does not reproduce those dynamics. Figure 6 evaluates the validation-selected best submodel across the benchmark. Our saved individual_best is an oracle minimum on test, used only diagnostically; it is not a deployable member selection rule. §5.1, D.5.

The widget isolates equal-variance, equal-correlation errors under a zero-mean assumption. It changes the correlation while holding the member error scale fixed. It does not train TabM, and it does not estimate the correlation from our data.

What counts as a dead neuron?

A dead neuron here is a shared ReLU unit that never activates. Section 5.4 measures this over a fixed probe of 2,048 training objects, across all member paths, at the best validation checkpoint. Across 46 datasets the reported fractions of dead neurons are 0.29±0.17 for k=1 and 0.14±0.09 for k=32. Those ± values describe variation across datasets, not the uncertainty of one fixed neuron's state. More member paths offer more chances for a unit to activate, which is consistent with the authors' utilization explanation. Still, the statistic alone does not prove that fewer inactive units caused better generalization; we have not rerun this experiment. §5.4.

6. The k knob and submodel pruning

The k knob controls how many members you train. The paper's Figure 7 averages performance over 17 datasets, with five seeds per score, dropout 0.1, and a learning rate retuned for each k. Larger backbones tended to accommodate more members. Too high a k sometimes hurt, and width 64 or depth 1 was suboptimal in those studied middle-to-large regimes. This does not prove that every small TabM must fail, and it does not license comparing our fixed-learning-rate curves as if they replicated Figure 7. §5.3, D.7.

Pruning is a different experiment. Do not confuse choosing k with pruning members after training. Appendix D.6 greedily adds the next member that most improves the current aggregate on validation, starting from the best validation member. It stops when no new member helps and the current aggregate is already better than the original all-k validation result. Sorting members by standalone accuracy is a different algorithm, not this one. Section 5.2 reports 8.8±6.6 members retained out of 32 across 46 datasets, with slightly worse test performance. To actually save work you must prune the adapter rows and heads; merely averaging fewer already-computed outputs does not establish a speedup. We explain this published experiment but do not reproduce it here. D.6.

Increasing k changes both the estimator and the computation¶

There are two different experiments. Train separate models at k=1,4,16 and compare their final predictors; or train once at k=16 and evaluate subsets of its members. The first changes the training objective's coupled system and computational budget. The second studies the redundancy of a fixed trained ensemble. A pruning curve from the second is not a training-scaling curve from the first.

If you select a subset using validation performance, subset choice is another adaptive decision. Choosing the best subset on test labels would leak evaluation feedback. A fixed first-m-member rule is easy to reproduce but can be sensitive to member ordering; randomized subsets with saved seeds provide a clearer view of average subset behavior.

Measure time on the intended device. A larger batched member dimension can use hardware more efficiently even while doing more arithmetic. Parameter counts alone cannot predict latency, and latency alone cannot describe peak activation memory. Report batch size, member count, precision and whether timing includes preprocessing.

Read weak members without dismissing the ensemble¶

Compare each member's loss with the aggregate loss and inspect paired error dependence. If members are individually weaker than standalone MLPs but their average is competitive, that is compatible with the method's purpose. It does not establish that weakness caused diversity or that any weak model would help.

A useful follow-up fixes the trained outputs and changes only aggregation or subset size. Another retrains under a fixed total compute budget. Keep these questions separate in the exit report, then state which evidence supports a practical choice of k.

7. What exactly are we comparing?

The four arms. The corrected v2 suite compares four predictors: a single MLP, an independently checkpointed MLP×32, numeric TabM-mini with k=32, and a validation-tuned XGBoost. The California, House 16H and Higgs Small arrays come from the released TabR archive. Appendix C explicitly states that TabM inherits 38 TabR datasets, including these three, which is stronger provenance than matching dataset names alone. We keep those dataset boundaries but cap train/validation/test at 1200/600/600, using label-blind selection seeds 53/54/55.

The fixed recipe. Model seeds are 0/1/2. The neural arms use train-only median/z-score transforms, width 64, depth 3, dropout .1, Adam .002, 64 epochs, and batch 256 with the incomplete final batch dropped, and they take the first strictly best validation checkpoint. The deep ensemble selects each member independently. TabM uses shared batches and collective validation. XGBoost searches six depth/rate candidates, with 150-tree ceilings and validation stopping. These arms share equal data and metric boundaries; they do not share equal tuning or compute budgets.

Scope check. The small suite deliberately preserves the earlier budget to evaluate the corrected model without adding more training. It also fixes the checkpoint tie policy from last-best to first-best, which can change classifier scores; the v1/v2 difference is not a controlled estimate of initialization alone. It omits the paper's AdamW/clip1/patience16 procedure, usual modified quantile preprocessing, separately tuned neural recipes, feature embeddings, mostly 15 evaluation seeds, and 43 other datasets. The post-EXIT trainer adds independent member batches, normal quantiles, AdamW, gradient clipping and patience stopping in a separate track. Neither is a benchmark reproduction. We have not independently byte-compared a second TabM archive.

What we record. We save source hashes, exact selected row indices, raw array hashes, versions, predictions, plus single-MLP/TabM validation histories and selected epochs for v2. The independent deep ensemble saves aggregate predictions but does not retain every member checkpoint.

Scope check. The original v1 operators/results remain immutable historical evidence; their extra S₁, member biases and incorrect fan-in make those scores not measurements of the corrected mini architecture. Use each result with its own operator.

10. What the paper establishes, and what comes next

Figure 3 reports strong TabM-family performance across tabular deep learning on 46 tasks: 37 random splits and 9 domain-aware splits. Its relative-performance panels use accuracy or AUROC, or R² relative to MLP; they are not mean raw RMSE. Appendix D.3 ranks models in tiers using means and seed SDs, whereas our local chart uses ordinary ranks. When comparing a particular score, keep the paper's numeric, † embedding and ensemble variants separate. §4.2.

Figure 4 times selected configurations. The asterisk-marked TabM variants additionally use mixed precision and torch.compile, and the authors explicitly caution against a direct unqualified efficiency comparison with unoptimized baselines. Table 2 evaluates full Maps Routing (6.5M rows) and Weather (13M), reusing configurations selected on smaller training sets with the same validation/test boundaries; most models use three seeds, and FT-Transformer uses one. TabR runs out of memory in that setup. That is measured applicability on those datasets and that hardware, not a theorem that retrieval can never scale. §4.3, D.4.

A concrete future target. Appendix E, Table 18 reports California numeric TabM-mini at RMSE 0.4479 ± 0.0022 for a single model, which itself contains k=32 branches. Its separate ensemble column averages five independently trained whole models and reports 0.4461 ± 0.0011. The † mini uses feature embeddings and reports 0.4275 ± 0.0024, so it is a different target. These are cited seed means and SDs under the paper procedure, not a tolerance for declaring our capped fixed recipe reproduced. Table 18.

Connect the mechanism to the nearest alternatives

RealMLP (L053) changes the parameterization, preprocessing and optimization recipe of a single predictor. TabM instead changes how several prediction branches share parameters. The two ideas are potentially complementary, but combining them would be a new experiment. FT-Transformer (L050) lets columns exchange information through attention within each row. TabM's dense W mixes feature coordinates while its member axis stays separate; attention across members would alter its intended objective and branches.

TabR (L052) conditions a row on retrieved training examples and their labels at prediction time. TabM conditions only on a fixed fitted set of weights, with no runtime label memory. For a customer-churn table, all TabM branches still see the same engineered history columns, so more members cannot reveal the customer's unjoined service events. That is why a strong TabM baseline matters to the relational thesis without answering it. An eventual relational comparison must give both models legal information under the same prediction cutoff.

That sets up L055. Keep the ensemble, but change the evaluation question: does its ranking survive when training customers precede test customers in time, with labels available only after a delay? A random-split ensemble win and a temporal-split deployment win need separate evidence. Ask the teacher about any derivation, code path or result you cannot defend.
