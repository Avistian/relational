### A timestamp alone does not teach adaptation

Adding time as an input gives the model a coordinate on which predictions may depend. It does not guarantee that the training tasks contain useful examples of changing mechanisms. If every pretraining task is stationary, the learner may have little reason to interpret time as a predictor of how relationships evolve.

A time-dependent prior changes the distribution of learning problems themselves. Context and query rows can come from different temporal domains while sharing a structured rule for how the mechanism changes. Pretraining then rewards predictions that use historical evidence and domain information under that task distribution.

Covariate shift changes P(X) while preserving P(Y|X). Label shift changes P(Y) while preserving P(X|Y). Concept or conditional shift changes the relationship from features to targets. These are idealized definitions; real datasets can exhibit combinations, and finite observed changes do not identify the underlying cause automatically.

For example, if older and newer customers differ in age distribution but the outcome rule given features is unchanged, a covariate-shift model may be appropriate. If a policy changes the outcome for otherwise similar customers, the conditional rule may have changed. The same aggregate accuracy drop can arise from either situation.

The lesson separates known synthetic mechanism changes from diagnosis on real temporal data. In a generator, we know what changed because we set it. In a real system, we need additional evidence to distinguish explanations.

### Two levels of generation, one learned predictor

The paper's construction uses a base SCM to generate feature/target variables and another sampled mechanism to make selected base-model parameters vary across domains. The second level describes how a data-generating rule changes. It is part of the synthetic task generator, not a neural optimizer and not the true deployment graph supplied at prediction time.

The local mirror uses a simpler edge trajectory w(t)=a+c·tanh(bt+d). The coefficients a,b,c,d are sampled once per task. For a feature x at time t, the target probability is sigmoid(w(t)x). Earlier context and later queries share the same sampled trajectory.

The coefficient a sets a baseline level, c controls the signed amplitude, b changes the transition rate/direction and d shifts the transition along time. Their combined effect can produce a gradual sign change or a nearly stationary edge. These interpretations describe the local smooth function family; they do not cover arbitrary real-world drift.

The PFN observes features and time plus historical labels. It does not receive a,b,c,d or the true future edge value. The learning problem is to infer useful predictive consequences from the available episode data. Supplying the latent coefficients would turn the experiment into an easier, different task.

Pretraining updates PFN weights over many sampled episodes. At evaluation, the pretrained model is frozen and receives a new task's eligible context. A separately gradient-adapted model would be another arm, not an implicit consequence of conditioning on time.

### A sign change gives a concrete prediction to trace

Hold x=1 fixed. If the edge weight is +2, the positive-class probability is sigmoid(2)≈0.881. If the weight becomes −2, the probability is sigmoid(−2)≈0.119. The same observed feature now predicts the opposite tendency because the conditional mechanism changed.

If labels are generated using a uniform noise draw u and the rule y=1[u<p], holding u fixed across these two conditions creates a paired synthetic case. At u=0.5, the label changes from one to zero. Resampling u would mix mechanism change with new sampling noise.

The local ablation trains identical reduced PFNs under stationary and changing-edge priors, then evaluates both on shared stationary and drifting task collections. Matching architecture, optimization budget and evaluation tasks makes the pretraining distribution the intended intervention.

The changing-prior model need not win everywhere. It may spend capacity on variation irrelevant to stationary tasks, or fail to learn useful extrapolation within the finite budget. A favorable drifting-task result supports the local intervention; it does not guarantee robustness to a discontinuous shock absent from the generator.

Keep the random units separate. Model seeds are independently trained predictors under the declared procedure. Evaluation tasks are paired cases shared across those predictors. Counting every query row as a new trained model would grossly overstate the amount of independent training evidence.

### Match the explanation to the actual trajectory

Plot several sampled w(t) curves and mark context/query time ranges. If all sampled curves are nearly constant, the intended drift experiment may be weak even though the generator contains a time variable. If queries extend far beyond the observed time range, explicitly describe the extrapolation demand.

### Eligibility comes before recency

A historical record can have an event time before the cutoff and a label arrival after it. At cutoff 4, event time 3 passes the event test, but label arrival 5 fails the availability test. The row cannot supply that target as labeled context for the cutoff-4 prediction.

Apply the eligibility filter first, then choose a recent window or top-k context from the eligible records. Selecting the most recent k events and dropping delayed labels afterward can leave fewer records than intended and a different context distribution. The policy should say whether it backfills with older eligible rows.

Feature availability needs the same treatment. A historical aggregate computed from current database values may include corrections or outcomes that were unavailable at the original prediction time. Event timestamps alone cannot establish point-in-time correctness.

If label delays correlate with the target, the available labeled context can be systematically biased. For example, difficult outcomes may resolve later. This is a property of the observation process, not merely a smaller sample size. A realistic deployment study should inspect that relationship before assuming eligible labels represent all recent events.

### Separate a new evaluation from a new adaptive method

Switching from a random split to a future window changes the test question. Restricting context to recent labels changes the prediction procedure. Fine-tuning changes parameters. A time-conditioned pretrained prior changes transferred knowledge. These interventions can interact, but each should first be named and controlled.

Choose window lengths and adaptation settings using earlier validation periods. If the future test window repeatedly selects the best policy, it has become validation feedback. Chronological ordering does not by itself prevent adaptive overfitting.

The exit should state the three clocks—event, feature availability and label availability—alongside the prior intervention. Keep the reduced synthetic ablation, the real temporal benchmark and the paper's full method in separate evidence statements. Then name a shift the local generator cannot represent and propose a test that could falsify your preferred explanation.

### Delayed feedback changes the observed training population

Let A indicate that a label has arrived by the cutoff. The available context is sampled from P(X,Y|A=1), not necessarily from the full recent-event distribution P(X,Y). If arrival depends on the outcome or its difficulty, these populations can differ systematically.

For example, uncomplicated cases may resolve quickly while disputed cases take weeks. A recent eligible context can then overrepresent easy outcomes even when event sampling is otherwise unbiased. A model trained on that context may be well calibrated for resolved cases and poorly calibrated for all current cases.

Increasing the recent window can add more resolved history, but it also adds older mechanisms. Waiting longer for labels reduces availability bias while delaying adaptation. These are operational trade-offs that a temporal experiment should make visible.

In a synthetic extension, hold the event/target generator fixed and change only the label-delay mechanism. Evaluate on the same required query population. This isolates the observation process from concept drift. In a real dataset, inspect delay distributions by known covariates and eventual outcomes using an appropriate historical audit, then avoid using those eventual outcomes in the simulated prediction inputs.

## Temporal PFN mechanism card

Local generator: **w(t)=a+c·tanh(bt+d)**, sampled once per task; **P(y=1|x,t)=sigmoid(w(t)x)**. At x=1, changing w from +2 to −2 changes probability from **0.881 to 0.119**.

Eligibility at cutoff c requires both **event≤c** and **label arrival≤c**; feature availability needs its own as-of check. Filter eligibility before selecting a recent context.

Changing the prior, selecting a recent memory, gradient adaptation and switching the evaluation split are distinct interventions. Paired synthetic tasks isolate a known mechanism; they do not identify the cause of drift in a real table.
