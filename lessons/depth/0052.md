### The fitted object contains a memory as well as weights

An ordinary parametric predictor evaluates fθ(x) after training has compressed useful information into θ. A retrieval model evaluates fθ(x;M), where M is an explicit collection of eligible examples. Changing M can change a prediction while every parameter stays fixed. Saving only a weight file is therefore insufficient to reproduce its behavior.

For supervised retrieval, memory entries contain features, labels and identities. Labels are valuable because they provide local evidence; they are also why eligibility matters. A held-out target must not enter the memory that predicts it. A duplicate feature vector from a different legitimate training row is a different issue from retrieving the query's own labeled record.

TabR learns a geometry in which useful neighbors can be selected. It is not simply k-nearest neighbors on standardized raw features, and its neighbor values are not merely scalar targets. The encoder shapes both which records become neighbors and how their information contributes after selection.

Think of the prediction as three questions. **Where should I look?** Compute keys and select nearby memory records. **What should I take from them?** Combine their labels with a learned function of the key difference. **How should I use the result?** Add the aggregated context to the query representation and pass it through the prediction network.

This decomposition suggests useful ablations. Freeze the learned geometry and replace the value function; keep values fixed and change context size; retain the query network while withholding retrieved context. Each changes a distinct route. Comparing the full model only with a standalone MLP cannot by itself identify which retrieval component caused a gain.

### Trace selection and weighting separately

Let a query key be k=(1,1), and candidate keys be a=(1,0), b=(3,1), c=(0,0). Their squared distances are 1, 4 and 2. With context size two, the selected records are a and c. The attention weights normalize only over those selected records: exp(−1)/(exp(−1)+exp(−2))≈0.731 and 0.269.

Notice two operations. Top-k selection produces discrete record identities. Softmax produces continuous weights conditional on those identities. In the local implementation, selection runs without gradient tracking, then selected distances and values are recomputed through differentiable operations. A small key change can adjust the weights smoothly while the neighbor set remains fixed; crossing a selection boundary can change the set abruptly.

Unlike scaled dot-product Transformer attention, this weighting uses negative squared distances without a 1/√d factor. Scaling every key by two multiplies squared distances by four and sharpens the resulting weights. Key scale is therefore part of the learned retrieval behavior, not a harmless unit conversion.

The implementation excludes self-matches using record identity. Suppose two legitimate records have equal feature vectors. Excluding every equal vector would remove both; excluding the query's ID removes only its own labeled entry. These are different policies with different effects on repeated or discretized data.

The teaching widget uses stable row-order tie handling, but the model uses PyTorch topk, which does not promise a stable tie ordering. A fixture without cutoff ties avoids this ambiguity; it does not eliminate the statistical consequences of ties. With identical keys and a context budget smaller than the tie group, the selected subset depends on the declared ordering policy. Preserve memory ordering or use an explicit deterministic tie-break when exact reproducibility matters.

### Why the key difference belongs in the value

For selected record i, the local TabR-S value has the form E(yᵢ)+T(k−kᵢ). E embeds the neighbor target into the hidden space. T is a learned transformation of the directed key difference. The sign matters: T(k−kᵢ) need not equal T(kᵢ−k), because the transformation is not constrained to be an even function.

The target embedding says what happened at the neighbor. The difference term lets the model adjust that evidence according to how the query differs from the neighbor. This makes retrieval richer than averaging nearby labels. It can learn that a neighbor is informative while still requiring a directional correction before its information is useful at the query.

Use a one-coordinate illustration, distinct from the full learned network. Let two target embeddings be 2 and 6, and let their learned difference contributions at this query be +1 and −2. The values are then 3 and 4. With the previous weights 0.731 and 0.269, the aggregated context is approximately 3.269. Averaging target embeddings alone would give approximately 3.076. The same neighbors and weights can therefore produce different representations because the value function changed.

The context vector is added to the encoded query representation, so the downstream predictor can combine direct feature evidence with retrieved evidence. It is not forced to copy the nearest label. This residual route is also why a retrieval model may remain useful when neighbors are imperfect.

During training, dropout on context weights can remove individual contributions. Standard dropout scales retained entries but does not renormalize each realized weight vector to sum to one. At evaluation, dropout is disabled. Do not interpret every training-time context vector as a convex average simply because the pre-dropout softmax weights sum to one.

### When a vector correction has a scalar-label interpretation

In regression, write the label map as Wᵧ(y)=ay+b, where a and b are d-dimensional vectors. As y varies, the embedded labels lie along an affine line whose direction is a. For a correction c=T(k−kᵢ), the component along that direction is a(aᵀc)/(aᵀa), provided a is nonzero. Thus the implied scalar label adjustment is Δy=(aᵀc)/(aᵀa). The remaining perpendicular component carries information outside the label-line direction; the prediction head may use it too.

For example, let a=(2,0) and c=(1,3). Then Δy=2/4=0.5: the parallel component (1,0) corresponds to adding 0.5 to the embedded scalar label, while (0,3) cannot be represented as a scalar-label shift. This is a decomposition of the value vector, not proof that the final prediction is yᵢ+0.5. The head still processes all coordinates and the query residual.

[Appendix A.2, Equation 7 and Table 8](https://arxiv.org/html/2307.14338v2#A1.SS2) remove this parallel correction from an already trained regression model and compare it with removing a random one-dimensional projection. The label-aligned removal is much more damaging on several tasks. The authors did not obtain an analogous interesting classification result. Our label-permutation experiment removes different information; it does not reproduce that projection study.

### A legal training memory can become an illegal serving memory

For a random held-out benchmark, a fixed training-only memory is a clear inductive contract. For deployment over time, “in the database” is not sufficient. A label must have been available before the prediction cutoff, and all retrieved features must reflect what was knowable then. Later outcome corrections can leak information if historical records are reconstructed from their current state.

Suppose an event happened Monday, its outcome arrived Thursday, and you predict on Tuesday. Its features may be eligible under the task definition, but its supervised target is unavailable. A retrieval system that uses Thursday's label while replaying Tuesday's prediction is evaluating a different information regime.

Memory refresh is another procedure choice. A frozen memory, a periodically refreshed memory and an online memory updated after labels arrive have different cost and adaptation behavior. Test the update policy you intend to deploy. Caching a stale key after changing encoder weights can also invalidate nearest-neighbor search; the memory representation must match the encoder used by the query.

For the lab, record context IDs alongside predictions on a small audit subset. Then you can answer whether a surprising prediction came from an unexpected neighbor set, a sharp weighting distribution or a downstream transformation. A score alone cannot distinguish these failure modes.

### What source parity does and does not settle

Copied-weight agreement on fixed inputs is strong evidence that the checked forward computation matches the reference path. It does not establish identical training dynamics, approximate-search behavior, preprocessing, checkpoint selection or large-scale runtime. The local exact-search numeric implementation should retain its declared scope even when its operator checks are excellent.

When comparing with a paper result, audit the memory population and context policy alongside ordinary hyperparameters. Retrieval has made the data available at prediction time part of the model definition. Omitting that field from a reproduction report omits a load-bearing component.

### Read the paper as a sequence of model-design experiments

Before inspecting the paper's table, predict whether adding neighbors' labels to ordinary dot-product attention should always help. A label contains valuable information, but the model must select and transform the right label for the query. This distinction is the central design question in [§3.2, Table 2 and Appendix A.3, Table 9](https://arxiv.org/html/2307.14338v2#S3.SS2), rather than an argument that any cross-row attention is sufficient.

**Step 0** starts with separate query and key projections, scaled dot-product scores, and values projected from neighbor features. **Step 1** adds label embeddings to those values. This supplies more information, but the reported gains are not consistent. **Step 2** shares the search projection between query and candidates and replaces dot product with negative squared distance. The similarity now measures closeness in one learned coordinate system. **Step 3** replaces the feature-only value term with the directed key-difference correction. **Step 4**, the final Equation 5, removes score scaling and excludes the target object from its own context. The lab implements this final step with the simple backbone.

To see the magnitude without confusing datasets or metrics, follow only California RMSE in Table 2: MLP **0.499**, Step 0 **0.484**, Step 1 **0.489**, Step 2 **0.418**, Step 3 **0.408**, Step 4 **0.403**. Lower is better. These are published means after the authors' tuning and evaluation, not outputs from our notebook. Step 1's addition of labels is not a monotonic improvement; Step 2 is the larger transition. The table does not establish that every dataset improves at every step: for example, Covertype changes from 0.975 to 0.973 accuracy at the final step.

Do not assign all of Step 2's change to distance alone: the step changed both the projection-sharing rule and the score. Appendix A.3 separately varies label use, shared projections and distance. The all-three configuration is strongest on several highlighted tasks, while removing labels can still improve California relative to the MLP. The supported claim is about their combined empirical usefulness under this study's protocol, not a theorem that every ingredient is individually necessary on every table. These variants were tuned; the experiment compares model families under a common tuning procedure, not just one frozen parameter vector with a line toggled.

**Check the causal question.** The notebook shuffles stored labels only after training, preserving keys, neighbors, model weights and the query data. A degradation shows reliance on the original alignment of memory rows and labels. It cannot tell you how well a label-free architecture would learn after retraining. In this local code, the retrieval-free backbone still constructs the unused retrieval modules, so the same seed gives the two arms identical initial shared weights. Enabling retrieval then changes the gradient routes and training dropout draws; their fitted representations and weights will diverge. This is a matched initial backbone, not one frozen predictor with retrieval toggled after fitting. To reproduce the paper's design argument, retrain and select each architectural variant under its specified search space. To diagnose one trained predictor, intervene while keeping its other routes fixed. Both experiments are useful, but answer different questions.

### What freezes, what gets recomputed, and what can be updated

For B queries, N candidate rows and d key coordinates, dense exact search evaluates a B-by-N distance matrix. Its matrix multiplication costs roughly O(BNd), and the local implementation stores O(BN) scores, plus candidate keys and their computation graph. Selecting m neighbors reduces the subsequent value computation to B-by-m-by-d; it does not make searching N candidates free. The released source uses **Faiss IndexFlatL2**, an exact index, not an approximate-neighbor index. The local PyTorch replacement therefore changes the implementation and performance of exact search; approximate-search quality has not been tested here.

The released `memory_efficient` path encodes candidates without gradients for selection, then re-encodes only the selected candidates with gradients. That reduces the retained training graph while preserving learning through selected keys. The numeric lab retains candidate graphs and recomputes every candidate encoding for every query batch. It does not cache inference keys or implement the released memory-efficient path. Neither source parity nor an O(BNm) shorthand would establish runtime equivalence. With the linear TabR-S encoder, the candidate encoder itself is relatively cheap; with richer encoders or much larger memories, this tradeoff becomes more consequential.

[§5.1 and Appendix D.2](https://arxiv.org/html/2307.14338v2#S5.SS1) study **context freeze**. After an early epoch, the training object's selected neighbor identities are reused. Keys, weights, value corrections and model parameters continue to evolve; validation and test still retrieve up-to-date neighbors. This is different from caching stale representations. The paper motivates freeze using observed stabilization of context membership and attention mass, then measures training cost and predictive score. Freezing early can miss neighbors that would become useful later. Table 6's California CF-1 has RMSE 0.414 at 72% of baseline training time versus 0.406 without freezing; that is a cost/accuracy tradeoff, not free speedup. Its default-recipe baseline is different from Table 3's tuned 0.403 target. Context freeze is not implemented or measured in this lab.

[§5.2 and Appendix D.3](https://arxiv.org/html/2307.14338v2#S5.SS2) ask a different question: train on a subset of Weather, hold the fitted model fixed, then add labeled rows from the remaining training pool to its candidate memory. This changes M in fθ(x;M), not θ. The paper describes the finding as preliminary; it is not a temporal-drift or delayed-label benchmark. A legitimate new training label can improve retrieval without retraining, but an outcome unavailable at the historical query time cannot be inserted retrospectively. Record both the model version and the memory version.

**Trace a failure before fixing it.** If a new query's score worsens after a memory refresh, first compare selected IDs. Changed IDs suggest a geometry/eligibility change. The same IDs with changed weights suggest different keys or scaling. The same IDs and weights with changed values suggest labels or the correction network changed. If all three agree, inspect the residual predictor and preprocessing. This decomposition motivates the notebook's explicit prediction trace: a scalar metric alone cannot locate the failed route.

### Place TabR beside the previous attention models

For a loan application, FT-Transformer exchanges information among that application's feature tokens: income can change the representation of debt before the classification token is read. Trompt uses learned prompt vectors to weight feature information repeatedly; its prompts are model parameters, not retrieved records with attached outcomes. Both can make row-isolated predictions after training. An external memory is not required by those operations.

SAINT's row attention mixes representations across rows in a supplied context; its predictions can depend on that context's composition. In the SAINT architecture studied earlier, this is feature-representation mixing, not TabR's explicit embedding of retrieved training labels into values. TabR instead selects a small context from a declared training pool and corrects the label-derived contribution for each query. With dropout off and a fixed memory, adding an unrelated query to an inference batch should not change another query's prediction. The notebook checks that property. This is a comparison of these mechanisms, not a statement that all attention between rows is the same algorithm.

Now imagine the relevant signal is an applicant's sequence of prior repayments. TabR can retrieve similar feature vectors from a flat table, but similarity need not pick that applicant's actual history or preserve the event order. A relational model can use explicit entity links and event-time structure; it must still establish availability at prediction time and outperform this stronger retrieval baseline under a common evaluation. The mission's open question is which relationships remain useful after a strong flat-table model already has access to legal historical examples.

### Do not exchange the units of evidence

The paper's default benchmark uses eleven datasets. Its separate Grinsztajn comparison retains original train/validation/test splits, removes duplicate dataset versions and the leaked Eye movements task, and applies its own tuning protocol. If a dataset has several splits, the authors tune and evaluate each split separately and average over splits before the final dataset comparison. Five splits with fifteen model seeds mean 75 fitted models, not 75 independent datasets. [Appendix C.2 and D.6](https://arxiv.org/html/2307.14338v2#A3.SS2) describe the procedure.

Table 5 compares ensembles: fifteen fitted models form three disjoint groups of five; predictions are averaged within each group before scoring. Its tuned TabR versus XGBoost count is 26 wins, 14 ties and 3 losses across 43 datasets. That count concerns full TabR ensembles under the stated procedure, not our numeric TabR-S single-model lab. Figure 1 instead reports single-model comparisons. A win/tie/loss count is not a percentage-point accuracy improvement.

The paper's “best” and pairwise tie convention uses means and the standard deviation of the best-mean algorithm: a competing mean within that SD belongs to its tied group. This is a descriptive convention, not a confidence interval or a Nemenyi test. Our table's t intervals describe variability over three model seeds on fixed sampled rows; our Nemenyi test instead uses the three datasets as blocks. Do not use one of these uncertainty summaries as if it were the other. Neither convention by itself validates a new domain or a temporal deployment claim.

**Retrieval check:** a report says “TabR reproduced the paper because its California RMSE is within 0.01.” Name four missing fields before accepting that sentence: model variant, preprocessing and split membership, selection/training procedure, and number/type of evaluated models. Candidate-memory population and eligibility belong inside the procedure field; the score cannot reconstruct them.

## Paper design and reproduction checklist

Step 0: dot product and feature values → Step 1: add labels → Step 2: shared-key squared distance → Step 3: directed correction → Step 4: no scaling or self-context. Only the last is the lab's Equation 5. Table 2 comparisons include tuning; the notebook's post-training label permutation is a different intervention.

Faiss IndexFlatL2 in the released implementation is exact search. Context freeze reuses training neighbor IDs, not fixed model weights or fixed key vectors. New-memory experiments keep weights fixed and change the labeled candidate pool; they do not establish temporal validity.

Selected-configuration evaluation, renewed hyperparameter tuning, and a fifteen-seed paper mean are distinct milestones. Check data ordering and preprocessing seed/jitter, stopping-rule semantics, full split sizes, initialization, search backend and metric units before assigning a reproduction verdict.
