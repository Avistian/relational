# Influential tabular and relational research: curriculum audit

**Research cutoff and access date: 2026-09-26.** Purpose: revise the Year 5 → 6 bridge around consequential architectures and necessary baselines, rather than recent abstracts alone. [Lecture specifications](./year-5-6-bridge.md) · [Curriculum](../CURRICULUM.md).

## Finding and selection method

The initial bridge over-weighted recent diagnostic papers. The earlier curriculum already covered most classical and graph foundations, but lacked substantive coverage of **TabDPT, Mitra, semantic tabular transfer, and a dedicated Relational Transformer unit**. It also lacked a systematic comparison of the ways pretraining data, representation and adaptation interact. The revised bridge fills those gaps and uses recent papers to update established families.

“Influential” is assessed through several observable signals, not a fabricated citation ranking:

1. **Architectural lineage:** later primary papers explicitly build on, adapt or challenge the mechanism.
2. **Benchmark relevance:** inclusion in maintained comparison infrastructure or evaluation by another research group.
3. **Practical uptake:** maintained implementations, weights, training/evaluation tooling or framework integration. This is evidence of use, not proof of accuracy.
4. **Mission coverage:** the contribution changes what must be compared to test whether relational structure helps.

The matrix below is a qualitative assessment. **Established family**, **current baseline**, **coverage-critical mechanism**, and **exploratory** are different judgments. Core teaching status does not mean every paper is equally famous. Recent versions inherit their family's relevance, not an automatic claim of sustained influence. No citation counts or GitHub popularity scores were used. Author affiliation overlap is explicitly relevant: TabArena/AutoGluon and RelArena are primary benchmark sources, but not organizationally independent arbiters of every model they evaluate.

Searches covered tabular model families, semantic transfer, relational supervised and foundation models, current benchmarks, code availability and critical evidence. The 312-entry staging file supplied candidates; its scores were not used as quality evidence. Method, ablation and evaluation sections were inspected for the main additions and relational comparisons, rather than relying only on abstracts. Secondary search results were discovery pointers; the evidence below links to papers, author repositories, benchmark maintainers and official releases. This was a targeted coverage audit, not a bibliometric census or a reproduction run.

## Findings from deeper reading that affect teaching

**Compare recipes, not names.** TabPack's packed independent models differ from TabM's usual parameter-sharing scheme. TabSTAR uses task-specific fine-tuning; it should not be labeled a forward-only ICL baseline. RDB-PFN generates relational structure but feeds linearized data to its predictor. These distinctions determine the ablations in B02, B07 and B13. Sources: [TabPack](https://arxiv.org/html/2607.05380v1), [TabSTAR](https://arxiv.org/html/2505.18125v2), [RDB-PFN](https://arxiv.org/html/2603.03805v1).

**Context and evaluation versions change conclusions.** RelArena's release reports one seed, separates model/system entries, and distinguishes text-enabled API from text-free local TabPFN-Rel. Its RDBLearn run omits a backend and predates a later toolkit release. Therefore its ranking cannot establish a universally superior architecture. B14 and B23 must audit these conditions. [RelArena §3 and Appendix B](https://arxiv.org/html/2608.16319v2).

**A new report can materially change which baseline is necessary.** Mitra-v2 introduces a hybrid SCM in addition to the outer mixture of generators. Its report distinguishes train-only versus additional-context policies. TabDPT-Turbo changes the retrieval/latency tradeoff, and the author repository records a September v1.3 release. Teach the original contributions and separately pin the deployed version; never transplant newer checkpoint scores into the original paper's experiment. [Mitra-v2](https://arxiv.org/html/2609.04540v1), [TabDPT release history](https://github.com/layer6ai-labs/TabDPT-inference), [Turbo paper](https://arxiv.org/abs/2608.01400v1).

**Open inference is not fully open pretraining.** Mitra-v2's verified release provides weights and inference/fine-tuning artifacts; this does not establish a fully reproducible pretraining pipeline. TabDPT explicitly links separate training code. LimiX-2's repository distinguishes code and model licenses. Availability should be recorded per artifact rather than with one “open” checkbox. [Mitra release](https://huggingface.co/autogluon/mitra-finetune), [TabDPT](https://github.com/layer6ai-labs/TabDPT-inference), [LimiX license section](https://github.com/limix-ldm-ai/LimiX#-license).

**SOTA is not the same as influence.** Core includes historical roots, widely used families and essential methodological comparisons. Electives include credible recent challengers. This avoids two errors: overlooking TabDPT because it is older than the staging window, and asserting that September's RefineICL or JEPA papers are already field-defining.

## Coverage boundaries and deferred work

- Existing Y1–Y3 coverage retains boosting, FT-Transformer, NODE/TabNet/SAINT, retrieval, SSL, GraphSAGE/GAT/GIN, heterogeneous and temporal graph learning. The bridge is a synthesis and gap-filling block, not a replacement for those foundations.
- ModernNCA remains a relevant retrieval comparator, linked from B02; EBM and AutoGluon remain baseline/system checks. Their absence as new standalone lectures does not exclude them from experiments.
- CARTE and semantic transfer are included because enterprise values and column meanings matter. LLM-only table serialization, SQL generation, table QA and general graph foundation models remain adjacent fields, not the core prediction mission. Tabular generative models are relevant when studying priors or augmentation, not automatically mandatory architecture units.
- The benchmark sites and repository integrations were inspected; no live leaderboards were independently recomputed. No new training or statistical meta-analysis was performed. The audit does not claim that every selected model dominates, or that every relevant paper has been found.
- Before teaching, check newer versions, dataset overlap, exact source/checkpoint licenses, named experiment targets and available compute. Formal reproduction remains `NOT_RUN`; learner mastery remains `PENDING_WRITTEN_DEFENSE`.

## Resulting curriculum change

Replace the initial 16-unit recent-paper seminar with **24 planned units: 16 core and 8 electives**. Core repairs architectural coverage and culminates in one declared reproduction and a written defense. Newest diagnostic papers remain available without crowding out influential families. B-unit IDs are revised because no B lessons had been authored or completed; the main 001–240 spine is unchanged. The lecture plan records the old-to-new mapping.
